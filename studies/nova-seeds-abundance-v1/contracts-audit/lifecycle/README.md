# Published SUCCESSOR JobDispatcher bridge

This bridge executes unchanged published Alpha code at revision
`197147ffd22c5ae13113162afffaf3ce9c10aa2e`. It is a local research rehearsal,
not qualification of a held Harness integration or a production authority grant.
The nine necessary published Python files are retained unchanged in `vendor/`
with an immutable source reference, SHA-256 inventory and original license.

## What actually happens

`development_case.mjs` executes the existing Alpha Out-Execute engine through
the study's actual finite instrument adapter, a complete clone and the separately
coded expert. It uses development seed 1, epochs 0 and 1, with fresh mission
identities, synthetic observations and zero-currency fixture scopes. It emits
these observations and source identities as `development-case.json`.

`lifecycle_bridge.py` then uses the published `Journal`, `SuccessorStore`,
`JobDispatcher`, typed protocol objects and signed envelopes. It freezes two
eight-job dependency graphs and dispatches actual installed pure callbacks.
The callbacks construct evidence commitments, independently enumerate the 2,048
candidate assignments in Python, replay the chosen schedule, compare the full
copy, and bind every result to a distinct authorization and acceptance record.
The Node work is explicitly precomputed evidence at this boundary. The graph
does not launch arbitrary code or claim to execute Node inside `execute_tool`.

| Job | Published family | Research TI relation | Executed callback |
|---|---|---|---|
| identify | constitution | Identify | Freeze objective, horizon, scope and zero paid actions |
| learn | evidence | Out-Learn | Bind actual development execution and fresh world digest |
| think | formation | Out-Think | Construct the exact objective, feasibility and assumption record |
| design | formation | Out-Design | Bind the finite calibration-sharing adapter and actual engine artifact |
| strategise | challenge | Out-Strategise | Independently enumerate all 2,048 assignments and compare the complete copy |
| execute | verification | Out-Execute | Independently replay synthetic resource validity and useful outcomes |
| accept | admission | Local acceptance supporting execution | Accept these exact research bytes, explicitly without production grant |
| evolve | renewal | Out-Evolve | Verify full-copy equality and require fresh successor scope and evidence |

These are relations between research actions and the source's lifecycle
families, not claims that the two taxonomies are identical. All seven published
families are required by `compile_jobs`; the eight jobs separate thinking from
constructing its bound artifact. They do not create extra on-chain transactions.

The second graph has a new institution, mission, environment commitment,
release, job terms, authorization IDs, reservations and independently re-evaluated
development observations. Copying the first graph's authority into it fails.
Expired authority, evidence dependencies before acceptance and duplicate tool
invocations also fail. The successor can replay the disclosed method with fresh
authority; it inherits no production permission.

## Observed run

The retained final run has 16 completed callbacks, 24 expected negative cases and 121
verified journal events. Each graph spends exactly its eight callback units and
issues zero production grants. `callback` is a controllable invocation count,
not a CPU-time or dollar unit. Wall and process CPU are reported separately in
the evidence. Both development epochs have zero residual useful-output advantage
against the complete clone. These two cases are interface demonstrations, not
the confirmatory population or an estimate of commercial value.

The final graph execution measured 3,185,404 microseconds wall time and
3,020,314 microseconds process CPU. The separate two-epoch Node development
execution measured 487.965 milliseconds wall time and 676,216 microseconds
process CPU. Node import/startup and final JSON serialization are outside that
timer. A confirmatory worker was also active on the host; these observations
are single-run execution accounting, not isolated performance estimates.
The wrapper's independent enumeration visits 2,048 assignments per epoch.
Typed `WorldProgram` and `PolicyProgram` declarations are bound into each
`CandidateReleaseManifest`; actual `EvidenceSubmission` records supply the
fresh mission-scoped input to every job. Stale observation metadata and reuse
of a predecessor's evidence envelope for its successor are rejected.

The local controller, producer and verifier use distinct ephemeral test keys
under one operator; they are not independent organizations. The upstream
Journal initializer writes its temporary local identity/API token, loads it,
and the bridge immediately unlinks those files. Its entire temporary journal
directory is removed on exit. Principal keys stay in memory, and the exported
record includes only public keys and signatures. No persistent credential is
created or included in the publication.

## Reproduce

Use the retained environment versions in `runtime-environment.json`. From the
source package's root:

```sh
node contracts-audit/lifecycle/development_case.mjs > contracts-audit/lifecycle/my-development-case.json
python contracts-audit/lifecycle/lifecycle_bridge.py \
  --evidence contracts-audit/lifecycle/my-development-case.json \
  --output contracts-audit/lifecycle/my-lifecycle-evidence.json
```

Choose fresh output names for each reproduction; preserve the retained
`development-case.json` and `lifecycle-evidence.json` as the canonical run.

The wrapper refuses evidence if the adapter or independent-evaluator source
hashes changed since the Node run. Re-execute the development case after an
intentional source change. Nonces, local keys, signed journal bytes and timings
change across runs; graph constraints, gate outcomes, useful outputs and source
identities are the reproduced properties.

The public event history is an authenticity and attribution artifact under the
recorded test public keys. As with the contract and off-chain registry, it does
not prove physical instrument truth, commercial demand, beneficial ownership of
local roles, or protection against an operator replacing all trust roots.
