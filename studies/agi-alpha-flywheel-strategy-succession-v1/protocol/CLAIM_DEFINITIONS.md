# Strategy Succession — prospective claim definitions

Status: development protocol, not yet frozen. No new confirmatory run has executed.

## Purpose and selected mission family

The first useful result is a worker-constrained release plan. Inputs state job durations, crew requirements, precedence, releases, capacity calendar and a user deadline. Later missions change inputs and introduce a repair contract: preserve committed work while respecting changed capacity. The implementation also supports an explicit movement limit, but the main generated repair tasks use locks and deadlines for qualification; movement is descriptive there. These are synthetic computational plans, not an executed physical release or evidence of paid demand.

The development shortlist was bounded to three conceptual families: route planning, disclosed evidence-set acquisition and crew-constrained release planning. The recovered historical experiment already supplies route and evidence-selection pilots; no historical numbers are recast as new runs. The new implementation pilot selected scheduling because legality, quality and repair are independently checkable and the first output is useful without a learned capability. The developer explored dispatch and lookahead parameters within this one family; those exploratory measurements remain development evidence.

## Claims and falsifiers

1. **Executed autonomy:** one explicit process start advances successive permitted missions through the unchanged released createWorkbench interface without a human triggering each phase. All manual setup, source edits, debugging, starts, stops and recoveries are counted separately. This does not establish an operating production service.
2. **Useful reuse:** under current scope and fresh inputs, an inherited executable method contributes to an independently accepted result. A stored answer or repeated artifact name does not qualify.
3. **Constructive succession:** a content-identified inherited method is actually executed in construction or qualification of a semantically different later method. A removal test must affect that construction/qualification, and an independently reconstructed equivalent replacement must be allowed. This is a bounded implemented dependency, not invention beyond the authored strategy language.
4. **Amortized productivity growth:** at matched qualified output, cumulative attributable declared work falls relative to an equally strong alternative after acquisition, failed proposals, checking, maintenance and recovery are included. Wall time, primitive-work tariffs, unknown authoring labor and money remain distinct.
5. **Capability expansion:** more fresh offered missions qualify under the same frozen cumulative resource limit, with identical deadline/movement criteria. Expanded mission count is not proof of a new attainable set if an equally enabled conventional learner matches it.
6. **Increasing growth rate:** later matched windows would need to show increasing marginal qualified output per equal increment of full charged resources, beyond transient repayment of an initial acquisition debit, with a causal test of endogenous reinvestment. This implementation allocates bounded research budgets; it does not implement earned-resource reinvestment and therefore cannot establish self-acceleration. Windowed productivity is descriptive. A parent-child lineage, a positive saving, a convex-looking cumulative curve or a one-time speedup is insufficient.
7. **Commercial growth:** real accepted deliveries, demand and economic outcomes. No new study result establishes these; break-even is conditional analysis, never synthetic revenue or profit.

## Non-negotiable experimental boundaries

- Freeze source, independent checker, candidate-generation grammar, mission distribution, seed scheme, budgets, arms, primary endpoint, uncertainty procedure and stopping rules before the first confirmation run.
- Candidate code is a bounded data AST. It cannot alter task generation, checker source, primary criteria, authority controls or protocol files. Local administrative access remains a common-mode limitation.
- Correctness/applicability and net-benefit admission are different decisions. Correct candidates can be rejected economically; rejected assets cannot regain admission through restart or import.
- Include a competent fixed portfolio, saved workflows, an equally enabled conventional learner, strongest practical native MILP reference, and removal/replacement controls. All receive the same public information and applicable stopping opportunities.
- Primary JS counted-work comparisons are not presented as equal physical computation to opaque native solver work. Report native solver wall/CPU limits, gaps and startup/model/checking time separately.
- Confirmation inputs are unavailable to discovery; they are used once after exact freeze. No tuning until a desired outcome appears. Any invalidating defect requires a visible amendment and preserved prior run.
- Retained source-bound artifacts and historical observations carry empty active proof and empty production authority. No financial transactions, new credentials, security changes or held Harness/Fleet action retries are permitted.
