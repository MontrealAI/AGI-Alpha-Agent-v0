# AGI ALPHA Flywheel — browser companion

**Open `index.html` in a current browser and select “Plan this mission.”** The default experience needs no
account, server, package installation, wallet, API key or network connection. The file contains its complete
JavaScript module closure and checks every embedded module against its SHA-256 manifest before starting.

The first mission is a synthetic release with nine tasks, dependencies and a worker calendar. Edit the table,
available workers or target finish, or apply a public/nonpersonal or synthetic JSON mission. The planner computes
a new schedule, checks it separately, and provides JSON and CSV downloads. It plans work; it does not execute a
release, dispatch workers or perform physical construction.

## A useful journey

1. **Plan a mission.** Inspect the actual schedule, capacity and dependency checks, target outcome, counted work
   and methods actually attempted. A missed target is displayed as missed; a malformed mission is refused.
2. **Build the next.** Start a finite stream of six changed missions: ordinary release planning, tighter targets,
   then disruption repair. No human selects or prompts each subsequent phase. The default gate includes
   acquisition and maintenance costs and can retain the incumbent or defer construction.
3. **Inspect construction chain.** This is a separate, explicitly selected diagnostic. Correct methods may be
   retained even when their investment case fails so that a dispatch rule, a look-ahead child and a repair child
   can be inspected. The banner and each asset identify laboratory retention. This mode does not establish
   enterprise productivity growth.
4. **STOP and recover.** STOP requests a durable phase boundary. Reopening this exact file rechecks saved
   history; resumption requires selecting “Resume saved run.” Accepted mission receipts are preserved. An
   interrupted, uncompleted discovery can be refused. Expired scope, exhausted budget or a deadline stop do not
   silently renew permission.
5. **Inspect evidence.** The research record, when embedded, is marked **recorded research**. It is separate
   from the live execution above. The complete archive contains the stronger Python specialist/checker,
   registered protocol, comparators and raw evidence.

`c352bad0a0941fdccd490a7224e3efd1b8de45d5`. It constructs unfunded draft workbench jobs and local receipts.

Retained assets and historical receipts carry provenance. Current institutional proof and production authority

files and storage controls the custody boundary.

## Rebuild the offline file

From the complete source archive, using Python 3.11–3.13:

```sh
python3 browser/build_demo.py
```

The builder uses only the Python standard library. It reads the exact static import closure and emits
`browser/index.html` and `browser/BUNDLE_MANIFEST.json`. No package download or website deployment occurs.
The execution identity includes the application logic, checker, fixed input modules, bootstrap and imported
scientific/workbench modules. CSS, template and recorded data have separate artifact identities. The main
experiment freeze binds the accepted source versions; do not edit scientific code and reuse an old result label.

Browser missions and training/qualification inputs are fixed in `mission-fixtures.mjs`, with construction
provenance in `FIXTURE_PROVENANCE.json`. These are development demonstration inputs, separate from protected
confirmation tasks. Schedules, discoveries and checks are still computed freshly. Normal builds never regenerate
the fixtures. `make-fixtures.mjs --regenerate-development-fixtures` is a development-only generator and must not be
used after a study freeze.

To add recorded results after confirmation, supply `browser/recorded-summary.json` with `headline`, `description`,
optional `metrics: [{label, value}]`, optional
`tables: [{title, note, columns: [{key, label, align}], rows: [{...values}]}]`, and optional
`downloads: [{label, filename, data}]`, then rebuild. `align: "right"` is available for numeric columns. Tables
render escaped text with accessible headers and scroll within their container on mobile. This updates
the data/presentation artifact without changing the executable module bytes. It does not rerun the study.

## Local validation

The checker regression test uses Node and no third-party package:

```sh
node browser/checker.test.mjs
```

Optional DOM/browser tests pin Playwright **1.62.1** in `browser/package.json`. If it is not already available,
install that optional development dependency and provide a compatible Chrome executable through
`AGI_BROWSER_CHROME`. The supplied development environment used Node **24.22.1** and Chrome **156.0.8078.47**.

```sh
cd browser
npm install --ignore-scripts
AGI_BROWSER_CHROME=/absolute/path/to/chrome node qa_browser.mjs
AGI_BROWSER_CHROME=/absolute/path/to/chrome node qa_stream.mjs
```

The tests block all HTTP(S) requests. They verify fresh useful output and downloads, malformed inputs, target
failure, keyboard navigation, desktop/mobile layout, exact configuration stability, STOP/reload/resume, receipt
idempotency, selective refusal, distinct diagnostic retention and empty proof/authority. They write JSON reports
and screenshots. Browser QA records are development verification, not confirmatory research outcomes.

## Preserved development failures

`development-failures/same-html-restore-03/` preserves a failed reload, its local snapshot and separate guard,
the exact HTML, manifest, screenshot and the two configuration objects sent to the hash function. Regenerating
synthetic inputs changed a single `fixture_generation.baseline_work` count from **6096 to 6115**. The guard correctly
refused the unequal configuration. Fixed, hashed fixture data resolves that failure condition; the original
failure remains available. The underlying engine/tiering mechanism was not asserted from this observation.

Work units are an explicit accounting model. They are not CPU instructions, wall-clock hours or money.
Browser and Python specialist counters are reported separately; they must not be pooled as equivalent units.
The same numeric budget does not make those different counters equivalent. A successful
finite loop, retained strategies, and paid commercial growth are separate claims. The browser demonstration
establishes no paid adoption, physical execution, autonomous revenue or sustained self-acceleration.
