# Same-offering economics: archival claim rescue

**Status:** hypothetical finite 90-day service model; no customer transaction, API purchase, source-certified historical delivery, or human time study was performed. **Actual revenue and actual collections are USD 0. Actual authoring and hosted-model costs are unknown.** Simulated collections and profits must always retain the word “modeled” or “conditional.”

This model asks whether a bounded outsourced scientific question package could pay its delivery costs. It does not claim that a new service market, a consumer price, a proprietary scientific method, or an expert-arm causal advantage has been established.

## Offer and acceptance boundary

The proposed offer is one original, pre-agreed linear scientific contrast of archived numerical measurements. It preserves all admitted glyph alternatives, shared calibration choices, and an up-to-k bounded source-error model. A useful accepted delivery requires the **unchanged original query** to be decisive under every admitted world and accepted by the customer. Either a definite true or definite false answer can be useful; switching to a more convenient question does not qualify. An unresolved answer, an unsupported source, or failure to justify the admitted set earns **no success fee**, and the deposit is refunded.

The mathematical answer is conditional on the source model. It does not establish that this model covers every historically possible reading or error. A commercial offer therefore requires human domain-source work to establish and document:

- Source identity, provenance, access rights, readable context, table boundaries, units, and what material could have been omitted.
- Defensible glyph alternatives, including genuinely ambiguous cells and plausible alternatives rejected with reasons.
- Which calibration values are supported by the source, which rows share calibration, and evidence for that grouping.
- The error budget k, error bounds and signs, independence assumptions, and the consequences of violating those assumptions.
- The unchanged query, threshold, exact arithmetic, extremal witnesses, reproducibility, and customer acceptance conditions.

These obligations are represented by scope/ingest, source-admissibility construction, independent domain-source validation, and exact execution/QA costs. They are not replaced by a generic short review allowance. The costs are unknown in practice. The baseline allocates 0.65 construction hours and 0.40 independent validation hours per median-complexity case, plus intake and ingest; these are contestable hypotheses, not measured durations. Actual supported archive families, page/dimension bounds, rights arrangements, and escalation rules remain to be defined before a live offer.

## Demand and value are endogenous within an assumed finite opportunity pool

Each of 60 / 150 / 300 low/baseline/high originating opportunities arrives during the 90-day campaign. These exposure counts are assumptions, not paid demand or market size. **V2 charges USD 5 cash acquisition per originating opportunity**, separately from intake labor and without a labor-overhead multiplier. Warm/inbound USD 0 and USD 15/50 channel sensitivities are explicit alternatives; no channel cost has been measured. Each origin has a source-family fit draw, complexity, independently assumed value of a decisive outcome, and the effort of a competent human/self-service alternative. Unsupported origins are screened out but still incur acquisition and intake costs.

For a source-fit origin, let q_offer include the provider's hard-budget survival, source admissibility, original-query decisiveness, and client acceptance. Let q_H include the shared source/decisiveness/acceptance factors but **exclude provider-specific budget exhaustion**, because the human comparator has no matching hard cap. The buyer compares:

`offer utility = q_offer × (decisive-outcome value − success fee) − buyer effort − deposit liquidity cost`

against:

`best outside utility = max(0, q_H × decisive-outcome value − estimated same-offering human cost − buyer effort)`.

A contract is requested only when the offer utility is at least as large. Deposit finance uses the actually quoted queue wait plus turnaround, rather than silently assuming immediate work. The human alternative includes the same domain-source burden; the model does not assume agents remove that work. Additional human analysis, evidence preparation, and query execution time is separately varied. The customer may value outsourced work even when two agent configurations perform identically.

Customer time is valued at an assumed USD 120 per hour, and the independent baseline decisive-outcome value has median USD 800. Neither is inferred from human R&D development cost. Human alternative costs are cost-led estimates, not consultant quotes. Success probabilities are scenario inputs and are **not calibrated from synthetic solver counts**. Before treating demand as evidence, the effort, value, buyer friction, acceptance, and paying behavior must be measured.

## Attribution null, human alternative, and library parity

The primary economic comparison sets **E = U = identical-content ordinary library** in price, operating cost, demand, capacity, accepted outcomes, and cash flows. This is the explicit attribution null, not a claim of measured equality. A profitable outsourced service under these assumptions would not identify an expert-prompt benefit, an inheritance benefit, or a new mathematical capability.

The separate `competent_human_fast` scenario reduces the human alternative's extra analysis time to a median 10 minutes. The `no_buyer_advantage` stress case gives the buyer an equivalent free result, so voluntary demand disappears. Neither is confused with the E-versus-U null.

## Finite capacity and timing

The 90-day campaign reserves 110 developer hours, 70 scientist hours, and 120 domain hours, including fixed duties and all expected intake. Individual contracts reserve their full possible role-hour requirement even if they later fail early. Six parallel slots and a 21-day maximum start wait limit the queue. A contract reserves the full promised slot without using unobserved source outcomes. Arrivals near day 90 may remain open; their deposits are liabilities and their remaining maximum completion costs are reserved.

No extrapolation to unlimited customers, instantaneous parallelism, or perpetual demand is made. A temporary financing requirement exceeding the configured USD 20,000 credit limit is reported as a liquidity-limit breach, not silently treated as a feasible financed campaign.

## Disjoint cost accounting

The `A_` cost categories cover the following once:

| Category | What is counted |
|---|---|
| Fixed campaign | Maintenance, account management, and standing technical duties |
| Origin intake | Every originating opportunity, including unsupported and non-buying ones |
| Cash channel acquisition | Explicit per-origin cash cost; no labor overhead applied |
| Scope and ingest | Source/question intake and initial preparation |
| Source access | Explicit assumed digital access/export cash cost |
| Source-admissibility construction | Domain labor building the allowed source model |
| Independent domain-source validation | Separate checking that the source model supports the offer |
| Model, tools, compute | Manifest-priced hypothetical token/search/container workload |
| Bounded rework | At most one additional developer/domain round, charged regardless of eventual success |
| Exact execution and witness QA | Computation and reproducible answer validation after admissibility |
| Delivery or refusal | Both successful handoff and unsuccessful explanation |
| Promised support | Accrued at acceptance, including support payable after day 90 |
| Fixed and variable overhead | Explicit 20% of respective labor compensation, each applied once |
| Payment fees | Collection and refund-transfer charges, including nonreturned original fees |

Employer compensation uses BLS national median wages multiplied by a rounded 1.46 compensation factor. Wage/compensation sources and provider price assumptions are recorded in `source_manifest.json`; provider prices originate in the parent's separately researched OpenAI manifest. The planned base per-contract model/tool workload costs USD 0.37, with one additional USD 0.37 workload when the bounded rework event occurs. Source labor, demand, and validation dominate the model; USD 0.37 is not a claim that an archival question can be delivered for pennies.

The attempt is hard capped at the listed labor allowances plus at most one rework round and its capped compute allowance. Rework occurs with an assumed 20% probability and is charged even when the case eventually fails. An independent assumed 5% budget-exhaustion event forces refusal and refund; further unpriced attempts are forbidden. These events model bounded production/rework rather than asserting that all cases fit a small labor allowance. A different cap, observed exhaustion frequency, or heavier workload requires a new model. All incurred attempt/rework costs remain in A, without duplicate B/C charges.

Contribution is earned revenue less bad debt and all direct variable A costs, including acquisition, intake, failed work, fees, and variable overhead. Fixed campaign compensation and its own overhead, followed by financing, then reconcile contribution to operating profit.

Refunds of an accepted fee reduce revenue. Failure refunds return a deposit liability and are not counted again as an operating expense. Defaulted unpaid balances are bad-debt losses, with refund credits preventing double counting. Financing interest is separate. Sunk development C is separate from campaign operations. Development of reusable methods and per-case source construction must not be charged as the same work twice.

## Cash, revenue, obligations, and free funds

The customer pays a 40% deposit. It stays restricted until acceptance or refund. The remaining balance is due three days after acceptance and may default. Expected balance-attempt/collection fees accrue at acceptance, settle with an adjustment to actual fees, and remain in payables while unsettled. Definite next-day refusal-refund transfer fees accrue at refusal. Successful customers have a 14-day refund window; the entire collected fee is conservatively reserved during that window. A separate small conditional fee buffer covers possible additional collection/refund fees above the accrual. All stated fee, default, refund, interest, and deposit terms are assumptions, not published payment-processor terms or observed contracts.

`collected modeled cash` is gross receipts by day 90. `net customer cash collected` subtracts cash refunds. `earned modeled revenue` recognizes accepted fees, deducts completed accepted refunds, and allows for unexpired expected refunds. It is not equal to deposits received. Late unsettled balances are receivables, not cash.

The model pays payroll weekly and reports accrued unpaid costs. It also reserves the remaining maximum completion budget of signed unfinished contracts without counting anticipated future customers. Working cash is cash less restricted deposits, refund reserves, accrued payables, completion reserves, and the conditional fee buffer. Pending payment fees are a reported subset of payables and are not deducted twice. Free funds further deduct outstanding borrowing. Initial owner funding of USD 5,000 and loan advances are financing, not revenue or profit. The first confirmation campaign's complete job and daily cash ledger is retained, and every run checks the cash identity.

## Exploration, correction, freeze, and confirmation

The seven exploratory success fees are USD 150, 250, 350, 450, 600, 800, and 1,000. Each receives 200 baseline hypothetical campaigns with a common fixed seed. The highest mean operating profit selects a quote, with lower price breaking a tie. An exploratory positive mean is only a conditional model gate, not permission or evidence to sell.

The first exploratory implementation contained a scheduling look-ahead defect: an early source refusal freed its slot before that outcome would be observable. The full code, config, policy, and outcomes are preserved in `results_superseded_scheduling_v1/`. The correction reserves the promised full slot. It was made before any confirmation run, without changing demand/cost parameters or tuning the price grid. The corrected exploration and before/after impact are preserved.

The first confirmation simulations completed, but a report formatter omitted structural zero counters and raised a `KeyError` in the zero-demand case. Its separate reporting completion and the unchanged raw results are preserved. An independent audit then found that the original model had not separately priced cash-channel acquisition, buyer queue financing, pending transaction fees, or a bounded rework rule. **The v1 baseline USD 466.82 mean is incomplete and superseded.** Its runner, config, frozen policy, results, reporting failure and completion script remain under `versions/v1_before_acquisition/`.

V2 uses new exploration/confirmation/robustness seeds, preserves the price grid and other primitives, and includes these substantive audit corrections. A further read-only audit caught a comparator issue before v2 confirmation: the provider's budget-failure probability had also reduced the human outside-option probability. That exploratory source/policy/outcome is preserved under `versions/v2_before_outside_option_correction/`. The final revision **v2.1** removes that unjustified penalty from the human alternative and updates buyer break-even conditions; its paired exploration reuses the v2 exploration seed, and its confirmation seed remains untouched until the final freeze.

`policy_frozen.json` binds the final runner, configuration, technical protocol, model manifest, exploratory output, chosen quote, and fresh confirmation seed by SHA-256. Confirmation refuses changed inputs. Six hundred fresh-seed campaigns then evaluate low, baseline, high, fast-human, no-buyer-advantage, and acquisition sensitivities at the same frozen quote. Confirmation cannot change the quote. Losing scenarios and prices are retained. The best exploratory quote is retained for counterfactual analysis even if the model's launch gate rejects the campaign.

Monte Carlo standard errors and intervals quantify simulation noise under the assumed model. They do not express confidence in real demand, scientific mission success, or profitability. The modeled frequency of operating loss is reported alongside mean profit.

## Robust profitable region and break-even thresholds

The robustness grid varies median source construction-plus-validation hours (0.5, 1, 2, 4) and outside additional analyst minutes (30, 90, 180). It retains baseline, reduced decisiveness/admissibility, higher refunds/defaults, lower buyer value, and a combined adverse corner. A cell is marked robust only when every declared corner's simulated mean-profit lower interval is positive and its 95th-percentile temporary financing need stays within the credit limit. This is robustness over a small declared grid, not a guarantee across unknown source families or all uncertainties.

The buyer break-even file reports how much competent-human extra work must be avoidable to justify the selected quote at median complexity and the independently required decisive-outcome value. It explicitly includes the provider-versus-human reliability difference, `(q_H − q_offer) × outcome value`, and reports separate value points. Supplier profitability must also pass. A high buyer threshold does not establish that those minutes exist.

## Optional retention B and development C

The primary measured gain from retained artifacts is unknown. Retention is assessed separately after 10, 50, or 200 explicitly assumed fresh uses. Illustrative avoidable-time values are 0, 5, or 15 minutes per use, with USD 200 initial retention work and USD 0.50 maintenance per fresh use. At zero gain the model rejects retention. Its break-even minutes are reported. Identical-content ordinary-library parity remains zero incremental gain before any extra packaging cost; general reuse value cannot be attributed to a special memory format.

The finite numerical demonstrator has a separate human-led planning range of **30 / 80 / 180 hours**, scoped to parsing, exact arithmetic, witness generation, an independent oracle, failure tests, small finite cases, and documentation. It excludes historical source certification. Existing certain-answer or analytical implementations could reduce these hours. They are analyst estimates, not measured human times.

A larger source-verified deployment is separately scoped at **250 / 700 / 1,600 hours**, including source-family study, admissibility protocols, domain validation, representative archives, ingestion, independent evaluation, and operations. These estimates are also unmeasured and should be replaced by task-specific practitioner estimates. The earlier generic 2,000-hour placeholder is not used as the small-code comparator.

Sunk development sensitivity uses C = USD 0 / 5,000 / 15,000 / 50,000 / 100,000. This can erase a positive campaign result. Human development cost does not establish customer value or a selling price.

## Reproduction and files

The runner uses Python's standard library only. Preserve the literal `study/` directory in the package. From the package root (the directory containing `study/`), the execution order is:

```
python study/economics/runner.py check
python study/economics/runner.py explore
python study/economics/runner.py confirm
python study/economics/runner.py robustness
python study/economics/runner.py supplementary
python study/economics/render_results.py
```

Existing outputs are intentionally not overwritten. Reproducing the full run requires a new clean output directory/copy with the same input files; the checked-in records remain evidence. `results/` contains all exploratory prices, fresh confirmation campaign and per-origin means, disjoint costs, the first confirmation ledger, parity results, robustness corners, buyer break-even thresholds, human-development scope costs, optional retention B, and sunk-development sensitivity. `RESULTS.md` reports the completed numerical findings. No file in the frozen ordinary discovery arm was edited.

An absolute or appropriately relative script path also works from another working directory, for example `python /path/to/package/study/economics/runner.py check`; inputs are resolved from the script's location, not the shell working directory.
