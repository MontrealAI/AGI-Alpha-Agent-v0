## Employer decision and scope

The complete job is to compare two authorized nonpersonal tabular exports, deliver every exact matched pair, identify unmatched rows and conflicting shared fields, group exceptions into an actionable queue while preserving evidence, and provide a readable source-linked handover. The deliverable supports correction decisions; it does not decide which source states the truth. A person ordinarily performs this work with spreadsheets, database queries, scripts, or other ordinary non-AI tools.

Use four domain presentations of the same bounded supported workflow: product catalog reconciliation; inventory export reconciliation; public website asset manifest reconciliation; publication catalog reconciliation. These are four job contexts, not evidence of four independent general cognitive capabilities. A stronger tested portfolio should be added only if an existing authorized adapter supports it before freezing. Avoid presenting invented employer demand or synthetic data as customer acceptance.

The research examines computer-mediated work: work performed through digital interfaces, using a keyboard, mouse or equivalent input, whose deliverable or completed action occurs through software. Untested responsibilities remain with humans: choosing trustworthy sources and business rules; resolving ambiguous identifiers; deciding which conflicting values are authoritative; approving material updates; managing stakeholders; and accepting the result.

## Proposed confirmation design

36 business jobs: four contexts × three predeclared complexity levels × three fresh instances. Low complexity has unique keys, few mismatches and simple values. Medium complexity adds changed key names, reordered fields, unmatched records, more conflicting fields, and unshared fields. High complexity adds duplicate keys (all exact matching pairs required), quoted commas/newlines, Unicode, exact-string ambiguity, and formula-like text. All must remain within supported source bounds. Complexity is semantic and structural as well as row count.

Balance contexts and difficulty across execution order; never place all easy tasks last. Repeated engine calls on identical inputs are timing repeats, not new independent jobs. Record cold start and warm calls separately. Use one predeclared randomized job ordering with a committed seed. Fresh source-generated tasks are controlled instances, not representative sampling from global employer work.

Sequence: Mission 1 delivers a complete useful exception package; retain the executable successor tool. Missions 2–4 use changed inputs and schemas through that tool. A successor mission combines two eligible capabilities—for example retained reconciliation plus exception grouping and a changed source schema—without claiming that selecting known routines invents a new algorithm. A scoped retained plan must refuse when its assumptions fail, with an ordinary supported fallback invoked and recorded if available. Do not label replay as adaptation.

Guard/control cases are a separate denominator: malformed CSV, empty or invalid key, unsupported limits, inappropriate fuzzy matching request, retained-source mismatch, STOP, exhausted budget, interrupted/restarted execution, corrupted saved workspace, and rollback. Passing a refusal is a safety/control success, not an accepted employer job.

## Frozen acceptance criteria

Acceptance is conjunctive; no average score can hide a material correctness failure.

1. Correctness: all and only exact matching pairs appear, including duplicate Cartesian pairs. Every unmatched row is present exactly once with side and original data-row reference. Every unequal shared non-key field is reported with both exact values and source-row references. Numeric-looking strings, whitespace, case and Unicode are preserved according to the published contract.
2. Completeness: 100% coverage of expected exceptions; no silent truncation, deduplication, dropped columns represented as compared, or guessed resolution of truth. Explicitly list unshared fields. Empty results remain valid when the correct answer is no exceptions.
3. Traceability: cryptographic identity and byte length for both inputs; schema/key choices; exact source version; run identity; source-row references; tool/capability lineage; event log; output manifest and hashes.
4. Usability: downloadable UTF-8 CSV and exact JSON; readable summary with counts matching the artifacts; clear ambiguity/limitation labels; spreadsheet-safe exports preserving exact originals separately; no broken output links. This is technical usability, not measured worker usability unless humans assess it.
5. Material error threshold: zero missing/extra/wrong matched pairs, unmatched rows, conflict fields or source values; zero falsely automatic source corrections; zero unsupported operations silently admitted; zero corrupted output accepted as valid.
6. Deadline and budget: predeclared operational limits; timeouts/rejections are recorded as failures for eligible jobs even if rerun later. A rework acceptance includes original attempt cost and latency. A budget exclusion is not an output success.

An independent-role deterministic oracle must parse the input independently, compute expected semantic multisets with different code, and compare every deliverable record. The oracle must not import the producing engine, copy producer logic line-for-line, accept its reported metrics as ground truth, or infer expected results from the output. This reduces implementation coupling; it is not external human acceptance. Assessors evaluate deidentified artifacts when possible, but if the artifact format reveals origin, report that blinding failed or was not attempted.

## Human arm: prospectively executable, NOT RUN

Recruit competent spreadsheet/data-operations workers. Minimum criteria: demonstrated successful completion of a distinct practice reconciliation at the material-error threshold; normal professional ability with tabular data; familiarity with a tool of their choice; informed consent; no dependency on an AI assistant. Do not use arbitrary seniority as a substitute for competence.

Participants may use efficient ordinary non-AI software, templates, formulas, database joins, macros and scripts they ordinarily know how to use. Disable or avoid generative-AI features. Do not force a manual row-by-row process, remove an effective established template, or prohibit ordinary automation. Provide the same brief, information, permitted actions, deadline, output contract and review standard. Identical internal methods are neither necessary nor desirable.

Give both arms practice and setup time, separately recorded. Humans retain their own lawful templates and experience across the sequence. Use matched equivalent task instances and counterbalanced order to limit carryover. A participant never serves simultaneously as their own independent acceptance assessor. Keep all attempts, corrections and abandoned jobs.

Record task start/end, active work intervals, breaks, waiting, supervisor time, reviewer time, correction time, setup, tool costs attributable to the task, and accepted outputs. Do not treat a screen recording as the only possible measurement. A local timer with participant confirmation and event notes can avoid capturing personal screen contents. Store participant identifiers separately; public artifacts use random codes and aggregate characteristics. No names, credentials, employer files or private screen contents enter the public companion. Consent must cover public release of the redacted task evidence, not merely participation.

If a future independent trial is commissioned, it would need authorization to contact specified consenting participants and, if paid, an explicit total payment cap and payment route. A pilot could use 6–12 competent workers with each performing a balanced subset of 6–12 jobs; this is a planning example, not a power calculation or an authorized commitment. Decide sample size from a pilot or prespecified precision requirement before confirmatory recruitment. No such trial is required to complete this market-data comparison, and no approval request is part of the present deliverable.

## Primary analysis

Primary endpoints are job acceptance proportion, complete cost per accepted job, user elapsed delivery time, human attention per accepted job, and accepted throughput within the measured time/budget. Report raw job counts, all attempts, per-family distributions, medians, ranges and 95% intervals with the statistical unit stated. For small purposive samples use descriptive intervals; do not imply population representativeness. Cluster intervals by participant or mission stream when appropriate, and do not count timing repeats as independent jobs.

For any future paired comparison, define cost ratio C_H/C_A and attention ratio H_H/H_A only when both complete comparable observations exist. If either cost is incomplete, ratio is not estimable. Distinguish a failure penalty or capped deadline from actual successful completion time. Provide both intent-to-deliver and accepted-only summaries so failures cannot disappear through conditioning.

Human cost: active work + correction + review + supervision + attributable setup, multiplied by documented employer compensation rates appropriate to worker/year/geography; include attributable software and overhead separately. Compensation assumptions are not observed time. AGI ALPHA cost: model invoices/usage, compute, execution, retries, setup, verification, supervision, maintenance and construction. Fully allocated costs include the declared allocation policy; marginal costs exclude only explicitly stated investment categories. A zero provider-call count is not zero complete delivery cost.

Unknown costs and human effort are missing, not zero. Root-agent/tool transcript elapsed time is not a human stopwatch observation. No token bill or compute invoice means monetary cost remains unmetered; price scenarios may be provided separately. Record model identity even if no live model is used for operational runs and distinguish development-assistant work from product execution.

## Reuse, capacity and interpretation

Demonstrated reuse means the retained executable bytes actually run on fresh inputs and pass acceptance. Broader capability means passing a meaningfully new contract; reusing one reconciliation operation in four domains does not by itself prove it. Improved productivity requires comparable complete input resources and outputs. Increasing improvement rate needs multiple independent measured improvement cycles; a faster second job alone is insufficient.

Scale trials use the actual permitted environment at concurrency 1, 2 and 4 (or justified actual supported levels), balanced input groups and repeated batches. Report accepted throughput, p50/p95 end-to-end latency, peak backlog, resource usage, refusals/failures and intervention count. State foreground process lifetime and browser closure behavior. A local finite runner is not a continuously operating enterprise. Repeated synthetic jobs test this environment's operating behavior, not real customer demand.

Freed worker time is capacity, not cash salary savings unless staffing/overtime/spend actually changes. Lower local CPU time is a resource observation, not revenue or profit. The $40T thesis belongs in transparent scenarios outside experimental findings. Preserve preceding software studies and their negative outcomes; no results here supersede them.
