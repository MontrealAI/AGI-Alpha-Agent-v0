# Scope clarification before confirmation creation

This clarification does not alter the frozen source-screen rules or oracle.

The openly available development task used a mesic setting. Fresh packet A uses a dry documented planting context.
Fresh packet B uses a wet context, adds a monarch larval-host requirement, and changes the required fictional provenance
region. All source properties come from the fixed source-derived catalog. Requirements, proposals, lot records,
quantities, dates, prices, and counterparties are researcher-constructed fixtures.

Every proposed row must satisfy the task's chosen resource evidence class. Thus the stricter nectar stress tasks ask
for explicit nectar evidence for every row; they are not realistic certificates for mixed-role plantings. A complete
planting that intentionally combines nectar species, pollen-only species, and host-only species would need per-row
roles and a new acceptance contract. The wet-host tasks use `flower` mode and a separate additional monarch obligation.

The study never changes an original nectar request into flowering to manufacture success. It reports that the supplied
catalog cannot support the stricter nectar claim. Unknown nectar evidence is not evidence that a species produces no
nectar. Likewise an undocumented habitat context is not evidence of biological unsuitability.

Confirmed correctness means that the report exposes the documented support and remaining obligations precisely. It
does not mean that a field project or commercial purchase has been accepted, funded, authorized, or completed.
