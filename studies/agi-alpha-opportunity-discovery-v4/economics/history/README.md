# Preserved development correction

The first development cash ledger generated each buyer's entire timeline before
the next buyer's expenses. Final profit and the conservative opening-cash test
were unaffected, but intermediate event ordering was not chronological and could
misstate the cash-timing figure. The version and its development receipts are
retained here. Before confirmation, the ledger was changed to queue all events
and replay them in date order. A two-buyer test now requires every delivery
expense to precede final collections. No confirmation outcomes were available
when this correction was made.
