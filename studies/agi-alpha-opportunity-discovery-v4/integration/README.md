# Actual retained-code transfer and fresh research-mission execution

This integration supplements the v4 inspection-evidence experiment. It reuses
existing software; it does not introduce a production capability registry,
change protected access scopes, authenticate live ENS ownership, or authorize
manufacturing or part release.

## What is reused

`binding.py` pins the preserved v3 `integration/inheritance.py` helper by SHA-256.
That helper verifies the original v1 bridge, replay scripts, source manifest and
vendored lifecycle/runtime closure before loading them. The v1
`verify_sources`, `run_lifecycle` and `replay_native` interfaces remain
unchanged. The integration calls the existing transport/conformance runner,
then extends the experiment with an actual received-code invocation.

The existing lifecycle requires assessment evidence before its fixture can
exercise admission and transfer. Its artificial monetary pairs remain
**conformance fixtures**, not an economic assessment of this instrument. Raw
legacy receipts retain their original labels; the v4 summary explicitly records
their artificial basis and no empirical Alpha admission. The negative monetary,
already protected material, version, rights, membership and revocation controls
are retained. The simulated agent names are not live ENS identities.

The existing native capsule schema rejects manufacturing-inspection scope. That
rejection is an expected passing control. A separately configured native
`TrustRegistry` verifies a local Ed25519 research grant, and the existing native
`Journal` records its one-use nonce before computation. A retrieved artifact or
cached receipt carries no mission authorization. Grants permit only running the
research audit code, including its ability to refuse unsupported requests.

## Closure and separately provisioned environment

The ZIP payload contains the complete declared custom application closure:
instrument Python modules, schemas, unit policy and dependency declarations,
plus its manifest. All members must be explicitly named, hash-bound regular
files under `instrument/`; undeclared data, evaluation and answer files are
excluded. Both compressed and expanded payloads must fit the unchanged
2,000,000-byte bridge limit. Credential-pattern and registered-protected-string
controls are bounded checks, not a claim of universal secret detection.

The CAD engine and other installed packages do not fit into that limit. They are
**separate environment prerequisites**, not transferred intelligence. The
wrapper resolves the instrument's mandatory installed transitive package
requirements plus local trust-harness dependencies. It hashes actual installed
files, including native binaries. Bytecode and installer scripts outside package
directories are excluded explicitly. Python version and executable hash are
recorded. Every actual recipient process rechecks this identity. This is not a
whole operating-system or standard-library image attestation.

Public CAD/QIF/OWL mission sources are separate filesystem inputs, bound by
role, hash, byte count and resolved path. They are not embedded in the code ZIP.
The original request path and relative source layout are preserved. Hashes are
checked before and after execution; the application opens them for reading.
This local experiment does not claim an OS-enforced read-only mount or a
production sandbox.

The independent checker and protected oracle are outside the transferred
application. Their frozen identities participate in the qualification context.
The integration invokes the checker without importing its implementation as an
instrument proof routine or reading its protected answers into the package.

## Generic reuse and fresh acceptance are separate

The existing `QualificationCache` holds six finite runtime/packaging checks:
source identity, exact received closure, installed dependency identity,
registered protected-string refusal, credential-pattern refusal and unsafe
member refusal. An exact reuse can execute zero of these six generic checks.
This is **not** a claim of scientific qualification, reduced total work or lower
customer cost. Each current mission still pays the source, environment,
authority, actual execution and independent semantic verification costs.

Cache identity includes source, artifact, schema, dependencies, evaluator,
scope, policy and generic bank. Changes to any component require a new
qualification call; no passing receipt is invented for an altered component.
The grant separately binds this complete identity and the complete current
request/source binding. Changing a purpose, statement, source or missing
metadata invalidates the earlier grant.

## Execution and comparison

After both instrument and independent evaluator are frozen, the integration:

1. verifies the inherited source manifest and packages the exact application;
2. moves its actual bytes through the existing protected lifecycle fixture;
3. reconstructs the received application and an ordinary-library copy with the
   same bytes and permissions;
4. checks generic conformance and exact-identity cache behavior;
5. installs only a public local trust anchor in the recipient context;
6. launches a new recipient process, which checks its current environment,
   sources and grant, consumes the nonce in the native Journal, and starts the
   actual received CLI in another process;
7. evaluates the resulting report with the independent source-based checker;
8. repeats the unchanged request using the ordinary-library copy and a separate
   fresh grant, then compares results;
9. attempts replay with the consumed original grant and records the refusal.

The ordinary-library run is a parity control, not a second independent
scientific observation. Semantic comparison excludes only named execution
telemetry fields; the raw reports remain available. Timing is measured, and
dependency hashes/bytes, artifact bytes and source bytes are recorded. Actual
complete research expense, model tokens and costs without telemetry remain
`null`; actual customer collections remain zero. Timing observations from a
shared local machine are not an estimate of commercial latency at scale.

The retained ordinary-library copy also illustrates a limitation of revocation:
revocation can block new mediated access, but cannot erase bytes already
retrieved. The local research fixture has no remote production enforcement
claim.

## Running the experiment

The instrument owner supplies a frozen closure declaration of this form:

```json
{
  "schema": "inspection-evidence-closure/v1",
  "files": {"instrument/cli.py": "exact-sha256-for-each-runtime-file"},
  "dependencies": {"lxml": "exact-version"},
  "schema_identity": "exact-schema-identity",
  "policy_identity": "exact-policy-identity",
  "entrypoint": "instrument/cli.py",
  "provenance": "assistant-constructed instrument; stated source and rights provenance"
}
```

The actual declaration includes every required file and dependency. The
independent evaluator supplies a frozen identity JSON containing
`checker_sha256` and its other policy/oracle identities. Its output must expose
an explicit boolean `accepted`. A missing report, missing verdict, nonzero
checker exit or rejected audit does not become a passing outcome.

```sh
python -B studies/agi-alpha-opportunity-discovery-v4/integration/run_integration.py \
  --closure studies/agi-alpha-opportunity-discovery-v4/instrument/freeze.json \
  --request /absolute/path/to/frozen/request.json \
  --checker /absolute/path/to/frozen/checker.py \
  --oracle /absolute/path/to/protected/oracle.json \
  --evaluator-identity /absolute/path/to/frozen/evaluator-identity.json \
  --expected-closure-sha256 EXACT_INSTRUMENT_FREEZE_SHA256 \
  --expected-evaluator-sha256 EXACT_EVALUATOR_IDENTITY_SHA256 \
  --out /absolute/path/to/new/result-directory
```

The output directory must be new. Failed checks remain in its receipts; do not
overwrite it with a corrected run. A corrected instrument/evaluator policy
requires an explicitly new version and fresh prospective testing.

Targeted tests use only small, labeled integrity fixtures and native interfaces:

```sh
python -B studies/agi-alpha-opportunity-discovery-v4/integration/test_binding.py -v
```

These tests do not open protected scientific jobs. They verify code/source
mutation rejection, secret-pattern exclusion, dependency mismatch, current
mission binding, actual signature/time/revocation checks, one-use authority,
generic reuse boundaries, unchanged native scope and signed A/B/C accounting.
