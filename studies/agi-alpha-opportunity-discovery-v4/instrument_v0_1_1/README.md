# Source-bound inspection evidence audit

This finite research instrument constructs useful evidence dossiers from actual QIF 2.1 and STEP geometry.
It supports source facts, formal SI interpretation, conditional numerical requalification, geometric
witnesses, family-permutation arguments and explicit evidence requests. It does not release physical parts.

See `CONTRACT.md`, `request.schema.json`, and `report.schema.json` for the API. The public development
example is `../data/development/request.json`. Sources are mounted separately from the code-only transfer.
The declared installed runtime is in `dependencies.json`; native CAD binaries are a prerequisite,
not a component claimed transferred within the two-million-byte capability limit.

The supported proof predicate is a closed Diameter interval. Other kinds remain visible as raw facts
and cannot inherit that proof. Negative tolerances remain negative. Exact QIF 2.1 defaults mean absent
linear unit declarations resolve to meters. A supplied mm repair scenario is explicitly counterfactual;
it never changes the formal facts or proves the exporter intended millimeters.

Five distinct purposes are accepted as typed, caller-supplied mission formulations:

- `evidence_audit`: a concrete supported witness is required; blanket unknown is insufficient.
- `recorded_values_all`: quantifies explicitly selected records against an explicit criterion.
- `family_all`: additionally requires compatible receiving-family cardinality and conditional set coverage.
- `feature_localization`: a universal family statement is insufficient; current cross-provider identity is blocked.
- `physical_release`: unsupported, regardless of supplied guard labels.

The code preserves the requested statement and purpose. It does not claim automatic natural-language
mission interpretation. The existing enterprise's authority and acceptance processes remain external.
A caller writing `externally_evidenced` in a request does not authenticate evidence or grant permission.

Strong E includes the supplied NIST integrated ontologies, existing STEP/QIF tools, the 2024 CCAM/NIST
alignment method and normal expert scripting. The instrument does not claim invention of those methods,
graph-specific advantage, a new GD&T algorithm, measured customer savings or general physical qualification.

`tests/` contains Plate-only development checks. Protected fresh confirmation is implemented separately
by another agent, without using this code as its correctness oracle. Frozen versions and failed candidates
are preserved. Research and evaluation costs are not counted as paid-job learning or assumed zero.
