## Demonstration format / Format de démonstration

Open `demo.html` directly in a browser. All display data, code and the geometry figure are embedded; no server,
external script, API request or model call is required. Select **EN** or **FR** in the header. Allow approximately
six to eight minutes for either language, including pauses for the audience.

Ouvrez directement `demo.html` dans un navigateur. Données affichées, code et figure géométrique sont intégrés;
aucun serveur, script externe, appel API ou modèle n’est nécessaire. Choisissez **EN** ou **FR** dans l’en-tête.
Prévoyez environ six à huit minutes, pauses comprises, dans la langue choisie.

**Presenter boundary:** controls replay immutable receipts and explain their logical scope. They do not rerun
the scientific instrument. The record-only view exposes an existing numerical field; it is not an additional
independent test. The economic controls display saved simulations, never observed customer activity.

**Limite à rappeler :** les commandes restituent des reçus figés et expliquent leur portée logique. Elles ne
relancent pas l’instrument scientifique. La vue des seules valeurs expose un champ numérique existant; elle
n’ajoute pas un test indépendant. Les commandes économiques affichent des simulations conservées, jamais une
activité client observée.

## 1. Establish the purpose / Établir la finalité

**Action:** Start at the top, then move to the evidence explorer. Keep **Cover → Formal QIF 2.1 → All selected
recorded values**, the default state.

**English narration**

“This edition asks what useful work leaves the next worker better equipped to do. Our concrete case is an
inspection recipient trying to reuse evidence from another provider. A familiar label or a passing number
does not tell us whether the new obligation has been met.

“These are actual public NIST/MTC source records. Here, the source lacks applicable unit metadata. QIF 2.1
therefore defaults these linear quantities to metres; the receiving requirement explicitly uses millimetres.
The scale looks implausible for the part, but plausibility is not permission to rewrite a source. The formal
numerical implication fails.”

**Narration française**

« Cette édition demande ce que le travail accompli laisse au prochain intervenant pour mieux agir. Le cas
concret est celui d’un destinataire qui veut réutiliser les preuves d’inspection d’un autre fournisseur.
Un libellé familier ou une valeur conforme ne suffit pas à établir une nouvelle obligation.

« Nous utilisons de véritables données publiques NIST/MTC. Ici, la source ne fournit pas les métadonnées
d’unité applicables. QIF 2.1 interprète donc ces quantités linéaires en mètres, alors que l’exigence à réception
emploie explicitement des millimètres. L’échelle semble peu plausible pour la pièce, mais cela n’autorise pas
à réécrire la source. L’implication numérique formelle échoue. »

## 2. Construct the useful statement / Construire la proposition utile

**Action:** Select **Hypothetical millimetres** while retaining the selected-record purpose. Select
**Reverse display order**, then inspect a record and its hash.

**English narration**

“Now we introduce a clearly marked researcher hypothesis: suppose the producer intended millimetres.
Cover has 400 selected recorded values between 4.523 and 4.537 millimetres. All lie inside the receiving
interval, 4.2 to 4.8 millimetres, under that hypothesis.

“The order of these same values cannot change that universal numerical statement. We can answer it without
inventing a one-to-one label correspondence. This uses known mathematics; it is not a new solver. The
constructed instrument makes the statement executable, source-bound and reviewable, while preserving the
unverified unit assumption.”

**Narration française**

« Introduisons maintenant une hypothèse de recherche explicitement signalée : le producteur aurait voulu
dire millimètres. Les 400 valeurs sélectionnées de Cover vont de 4,523 à 4,537 millimètres. Sous cette
hypothèse, elles se trouvent toutes dans l’intervalle exigé, de 4,2 à 4,8 millimètres.

« Réordonner ces mêmes valeurs ne peut changer cette proposition numérique universelle. Nous pouvons donc
y répondre sans inventer une correspondance individuelle entre libellés. Il s’agit de mathématiques connues,
pas d’un nouveau solveur. L’instrument construit rend la proposition exécutable, traçable et vérifiable, tout
en conservant l’hypothèse d’unité non confirmée. »

## 3. Change the mission, recheck the conclusion / Changer la mission, réexaminer la conclusion

**Action:** With Cover and the millimetre hypothesis, select **Complete receiving feature family**, then
**One identified physical feature**, then **Physical part release**. Finally select **Box → selected records**
with the millimetre hypothesis, and choose **Show maximum value**.

**English narration**

“The purpose matters. Cover’s 20 source characteristics do not establish coverage of four receiving features.
A numerical pass does not identify the physical specimens, certify the measurement method or locate one
particular feature for rework. Physical release is outside this instrument’s authority.

“Box supplies an even stronger falsifier. Its 76 selected values run from 3.246 to 3.536 millimetres under
the same hypothesis, against a receiving interval of 3.1 to 3.5 millimetres. The maximum is outside the
requirement. Changing the formulation cannot make a false statement true. The exact actual ID, source line
and hash show where that conclusion comes from.”

**Narration française**

« La finalité compte. Les 20 caractéristiques sources de Cover ne prouvent pas la couverture des quatre
formes à contrôler. Une réussite numérique n’identifie pas les pièces physiques, ne qualifie pas la méthode
de mesure et ne localise pas une forme précise à retoucher. La libération physique dépasse l’autorité de
cet instrument.

« Box apporte une réfutation encore plus directe. Sous la même hypothèse, ses 76 valeurs sélectionnées vont
de 3,246 à 3,536 millimètres, alors que l’intervalle exigé va de 3,1 à 3,5 millimètres. Le maximum dépasse
la limite. Changer la formulation ne rend pas vraie une proposition fausse. L’identifiant de mesure, la ligne
source et l’empreinte montrent précisément d’où vient cette conclusion. »

## 4. Preserve failure and improve the next action / Conserver l’échec et préciser l’action suivante

**Action:** Open **All eight original outcomes**. Then choose the prospective **Cover · labeled distance**
request and expand its source-bound obligation details.

**English narration**

“The independent checker accepted five of the original eight complete audits. Three failed because two
repair requests did not identify the affected source objects precisely enough. A program’s own success
label was not accepted as proof.

“The separate revision adds source-bound repair scopes. Four new requests were frozen before that revision
ran, and all four passed. They use previously seen documents, so this is a bounded prospective repair,
not a replacement for the original five-out-of-eight result.

“For this request, the recipient must reconcile source record 77 with receiving obligation 155. The plan
identifies exact objects, units, requirement semantics, specimen scope, measurement evidence and current
authority. It asks the responsible party for evidence the program cannot manufacture.”

**Narration française**

« Le vérificateur indépendant a accepté cinq des huit audits complets initiaux. Trois ont échoué parce que
deux demandes de preuves ne désignaient pas assez précisément les objets concernés. L’étiquette de réussite
du programme n’a pas été prise pour une preuve.

« Une révision distincte ajoute des périmètres de correction liés aux sources. Quatre nouvelles demandes
ont été figées avant son exécution; les quatre ont réussi. Elles emploient des documents déjà vus. C’est
donc une correction prospective délimitée, pas un remplacement du résultat initial de cinq sur huit.

« Ici, le destinataire doit rapprocher l’enregistrement source 77 et l’obligation à réception 155. Le plan
précise objets, unités, sens des exigences, identité des pièces, preuves de mesure et autorité actuelle.
Il demande au responsable les preuves que le programme ne peut pas fabriquer. »

## 5. Show inheritance without automatic advantage / Montrer la transmission sans avantage présumé

**Action:** Review the separate hosted-method panel, then scroll to the actual geometry and transfer section.
Open the transfer controls if useful.

**English narration**

“Operational Alpha has to be measured. In the small same-model trial, ordinary use and expert operation each
accepted four of four jobs. The enhanced method accepted three under the strict identifier rule: it named
the correct serial in a trace, then used component ID 528 as a serial in the requested action. A lenient
reading would yield parity, not an advantage. Complete costs are unknown.

“Inheritance did execute. The recipient received 43,242 bytes of packaged custom code and ran a fresh Cover
evidence-acquisition mission in a separate process. The independent audit passed. The same-content ordinary
library also passed, so this is not evidence of graph-specific superiority.

“Thirty-five targeted controls checked integrity and authority. A changed source, revoked grant or expired
permission did not inherit acceptance. Native manufacturing scope remained rejected. The local identities
are research fixtures, not live ENS authentication.”

**Narration française**

« L’Alpha opérationnel doit être mesuré. Dans le petit essai avec le même modèle, l’usage ordinaire et la
méthode experte ont chacun obtenu quatre résultats acceptés sur quatre. La méthode enrichie en a obtenu trois
avec la règle stricte d’identification : elle donne le bon numéro de série dans une trace, puis utilise
l’identifiant de composant 528 comme numéro de série dans l’action demandée. Une lecture indulgente donnerait
l’égalité, pas un avantage. Les coûts complets sont inconnus.

« La transmission, elle, a bien été exécutée. Le destinataire a reçu 43 242 octets de code empaqueté et a
traité une nouvelle mission de preuves sur Cover dans un processus distinct. L’audit indépendant a réussi.
La bibliothèque ordinaire contenant les mêmes éléments a aussi réussi : aucun avantage propre au graphe
n’est établi.

« Trente-cinq contrôles ciblés ont vérifié intégrité et autorité. Une source modifiée, une révocation ou une
autorisation expirée ne pouvait hériter de l’acceptation. Le périmètre natif de fabrication est resté refusé.
Les identités locales sont des dispositifs de recherche, pas une authentification ENS réelle. »

## 6. Make the commercial stopping decision / Prendre la décision économique d’arrêter

**Action:** Show the central saved financial scenario, then **Efficient incumbent** or **Low demand**.
Keep the optional-development rejection visible. Optionally open the ledger and move from initial capital
through deposits to the final event. Show the separate post-confirmation milestone-refund stress panel.
End at provenance and the download button.

**English narration**

“These finances are explicitly simulated. The proposed offering combines a useful audit, private adaptation
and optional common adapter construction. Buyers retain their outside options. Coordinated development
may change funding and responsibilities, but no compatible buyers or real demand were observed here.

“The central comparison does not favor retention: the retained-and-arranged configuration loses money in
48 of 80 modeled horizons. The optional six-horizon increment is about 2,221 dollars against 2,950 dollars
of additional construction, retention and transfer cost. The policy says stop that optional investment.
It can still deliver a separately profitable paid job.

“The saved ledger illustrates why cash and profit differ. A deposit is cash with an obligation; seed capital
is not revenue. This favorable individual example does not override the broader result. Actual customer
revenue is zero.

“A separate adverse audit asks what happens if all committed work is incurred, the development milestone
is then rejected, all advances must be refunded, and no final payment finances the work. Of 1,889 original
selected commitments, 114 would need more opening cash. These are conditional exposures, not realized
insolvencies; eleven were later cancelled in the original realizations. No rejection probability is assigned,
and the original expected profits are unchanged.

“What remains is concrete: executable readers and witnesses, precise missing-evidence requests, preserved
failures, and a successor that can undertake a fresh audit while earning fresh trust. The next commercial
step needs real buyer scope, acceptance, complete cost and permission. The loop is allowed to stop.”

**Narration française**

« Ces finances sont explicitement simulées. L’offre envisagée associe un audit utile, une adaptation privée
et la construction facultative d’un adaptateur commun. Les acheteurs conservent leurs solutions alternatives.
La coordination peut modifier financement et responsabilités, mais nous n’avons observé ici ni acheteurs
compatibles ni demande réelle.

« La comparaison centrale ne favorise pas la conservation : la configuration avec conservation et contrat
perd de l’argent sur 48 des 80 horizons modélisés. L’incrément facultatif sur six horizons vaut environ
2 221 dollars, face à 2 950 dollars de construction, conservation et transmission supplémentaires. La règle
rejette cet investissement facultatif. Une prestation payée rentable peut néanmoins être livrée séparément.

« Le registre conservé montre pourquoi trésorerie et bénéfice diffèrent. Un acompte est de l’argent assorti
d’une obligation; le capital initial n’est pas du revenu. Cet exemple individuel favorable ne renverse pas
le résultat général. Le revenu client réel est nul.

« Un audit défavorable distinct examine le cas où tous les travaux engagés sont effectués, puis le jalon
de développement est rejeté, tous les acomptes doivent être remboursés et aucun paiement final ne finance
les travaux. Sur 1 889 engagements initialement retenus, 114 exigeraient davantage de trésorerie au départ.
Ce sont des expositions conditionnelles, pas des insolvabilités réalisées; onze ont ensuite été annulés
dans les réalisations initiales. Aucune probabilité de rejet n’est attribuée et les bénéfices espérés
initiaux restent inchangés.

« Il reste quelque chose de concret : des lecteurs et témoins exécutables, des demandes précises de preuves,
des échecs conservés, et un successeur capable d’un nouvel audit en renouvelant la confiance. L’étape
commerciale suivante exige un périmètre client réel, une acceptation, un coût complet et une autorisation.
La boucle a le droit de s’arrêter. »

## Evidence and production notes / Notes de preuve et de réalisation

- Primary result: `evaluation/results/confirmation-v1/summary.json` — 5/8, immutable v0.1.0.
- Prospective result: `evaluation/prospective-v1/results/confirmation-v1/summary.json` — 4/4 new requests on
  already-used sources, separate v0.1.1.
- Transfer: `integration/results/confirmation-v1/summary.json` — actual ZIP transfer, fresh recipient,
  same-content library parity, 35 targeted controls, no production manufacturing scope.
- Hosted trial: `evaluation/hosted-grading-v1/summary.json` — U 4/4, E 4/4, E+ 3/4; no complete-cost inference.
- Finance: `economics/confirmation/summary.json`, `economics/admission.json` and
  `economics/confirmation/cash_examples.json` — all commercial outcomes simulated.
- Post-confirmation adverse audit: `economics/postconfirmation_solvency_v1/RESULTS.json`, `FREEZE.json`
  and `README.md` — 114 of 1,889 original commitments conditionally exposed after full committed work and
  milestone rejection/full refund; not realized insolvencies, no assigned probability or revised profit.
- `build_demo.py` builds `demo.html` and `demo-evidence.json` from these frozen receipts and verifies the
  decoded report hashes it extracts. It does not run or change any instrument or financial model.
- `demo-evidence.json` contains compact display evidence and the exact input-file manifest. The HTML embeds
  the same data and original geometry PNG. The downloadable excerpts are display artifacts, not new reports.
- The publication is AI-assisted. The instrument was constructed by the research team with frontier-model
  assistance; numerical and geometric receipts come from executed software. Complete model billing and
  research cost are unknown. This page uses no tokens and claims no separate model capability.
- External links open only when the viewer chooses them. The page itself makes no external network requests.
  Publication to a stable public location remains a separate repository-owner release action.

**Terminology / Terminologie:** “accepted audit / audit accepté” concerns the usefulness and source fidelity of
the scoped report. It never means “physical part accepted / pièce physique acceptée.” “Hypothetical millimetres /
hypothèse de millimètres” is an unverified researcher assumption, not corrected producer evidence. “Selected
records / valeurs sélectionnées” must not become “complete physical coverage / couverture physique complète.”
