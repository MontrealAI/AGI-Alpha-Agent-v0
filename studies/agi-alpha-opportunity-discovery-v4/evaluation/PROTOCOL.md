# Protected manufacturing confirmation protocol 0.1

Prepared after selection and before any candidate execution on Box/Cover. The curator is independent of the
instrument builder. Public, historical files from the same assembly are contextually withheld, not asserted to be
absent from model training. The curator may inspect sources to make checkable service requests; these are
researcher-authored jobs, not customer orders or independently sampled industries.

## Frozen job family and acceptance

Nine jobs are selected before candidate output is seen:

| Job | Useful purpose | Required disposition |
|---|---|---|
| Box report comparability | Audit the complete paired inspection packet | Source-supported useful audit, including formal semantics and missing identity |
| Cover report comparability | Audit another paired packet and its supplied graph | Same; never treat a graph as automatic cross-provider equivalence |
| Box formal family claim | Test a declared diameter family under the actual formal units | Correct independently computed numerical verdict and explicit physical prerequisites |
| Box conditional family claim | Evaluate an expressly researcher-supplied unit-repair hypothesis | Separate formal result from counterfactual, exact quantities, preserved guards |
| Cover conditional family claim | Test a larger same-kind family from the actual source | Correct common-interval invariance without pretending a complete physical mapping |
| Box feature localization | Identify a particular physical feature from insufficient identity | Deny localization while preserving useful weaker findings and exact evidence requests |
| Cover physical release | Attempt to promote an audit to part release | Explicit unsupported purpose, regardless of assumption labels |
| Cover packet without CAD | Audit evidence when geometry/reference data were not supplied | Useful bounded audit with explicit absent geometry; no invented trace |
| Fresh Cover evidence acquisition | Separate recipient plans the evidence needed for a different decision | Exact unresolved evidence requirements, useful source-bound findings, no acquired-data fiction |

The last job is reserved for the separate recipient-transfer owner. The ordinary-library parity replay uses the
same request, source bytes and permissions and is a control, not a tenth independent customer job.

Every accepted report must preserve the mission and source identities, raw numeric literals, formal unit rules,
characteristic and result-set status ancestry, actual source references and the distinction between a numerical
family result and physical reuse. Assertions of wrong equivalence, invented geometry, silently changed units or
tolerance signs, changed purpose, or inherited release permission are fatal. Unsupported or indeterminate results
can pass an audit contract only when they supply specific checkable findings and actionable missing-evidence
requests. Blanket refusal fails the audit. A correct audit does not mean that its requested physical claim passed.

Exact expectations, source object identities, family values and geometry checks are kept in `protected/` and must
not be read by the instrument builder before the executable/policy/dependency freeze. Family identifiers in an
explicit request are curator-supplied mission scope; discovery credit is reserved for actual automated construction
from other requests. No request asserts that those selected QIF records constitute a verified physical feature set.

## Independent checking

`source_oracle.py` uses standard-library XML/Expat, Decimal, independent interval and permutation checks, direct
STEP entity inspection and direct OCP reimport. It does not import instrument modules. Shared OpenCascade is
acknowledged; this is independent checking logic with shared infrastructure, not independent metrology truth.
Formal QIF 2.1 linear-unit defaults are pinned to the standards owner's schema. Original files are never repaired.
Small families are exhaustively permuted; larger common-interval conjunctions use the exact symmetry argument,
not sampled permutations presented as exhaustive proofs.

The report checker will be bound to the builder's documented JSON contract before first confirmation. Interface
adaptation against Plate examples is allowed; adapting expected answers to protected candidate output is not.
Checker robustness tests use synthetic/altered reports and are separately labeled. No such perturbation counts as
an independently originated market need.

## Freeze and execution

1. Freeze input, request, oracle, evaluator and protocol hashes before the first protected candidate call.
2. Require the builder's separate code/schema/policy/dependency freeze and preserve that identity.
3. Execute each first-pass request once, each with a 60-second subprocess deadline; report elapsed time, exit
   status and stdout/stderr. Deadline exceeded is an execution failure; no silent replacement.
4. Run the independent checker and preserve original reports and receipts. Repairs are new post-confirmation
   versions, never relabeled development or recovered first-pass success.
5. The fresh recipient executes its reserved request after actual byte transfer and separate local authority
   checks. Protected oracles/evaluator are not included in the capability package.

Actual executable wall time and subprocess counts are observed. Complete curation/AI token and billing telemetry
are unavailable and remain unknown. No human-service time saving, model U/E improvement, customer revenue,
physical acceptance, or live authentication follows from these computational receipts. Costed market scenarios
remain separate from these observations. Stop any broader claim that cannot pass this bounded contract.
