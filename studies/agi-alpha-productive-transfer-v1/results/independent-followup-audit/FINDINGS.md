## Substantiation of the C2 defect

The immutable NetworkX consumer is [`networkx/algorithms/centrality/eigenvector.py` at `9c1ee6392311d056760714d4126cd6382f75a96f`](https://github.com/networkx/networkx/blob/9c1ee6392311d056760714d4126cd6382f75a96f/networkx/algorithms/centrality/eigenvector.py). The selected component is `eigenvector_centrality_numpy`. Its registered dependency is SciPy. It calls `sp.sparse.linalg.eigs` at line 336 and `sp.linalg.norm` at line 340. It also applies `eigenvector.flatten()` at line 339 and `largest.sum()` at line 340 to returned numerical data.

The captured `eigs` return documentation specifies ndarray eigenvectors on both sides: [SciPy 1.10.1, lines 1208–1214](https://github.com/scipy/scipy/blob/c1ed5ece8ffbf05356a22a8106affcd11bd3aee0/scipy/sparse/linalg/_eigen/arpack/arpack.py#L1208-L1214) and [SciPy 1.14.1, lines 1211–1217](https://github.com/scipy/scipy/blob/92d2a8592782ee19a1161d0bf3fc2241ba78bb63/scipy/sparse/linalg/_eigen/arpack/arpack.py#L1211-L1217). Under that nominal source contract and ordinary imports, flatten and sum are NumPy data operations rather than calls into SciPy-defined receivers. The pre-outcome oracle explicitly excludes these two calls with this rationale. The criterion was not invented after inspecting C2.

C2 propagates dependency association through tuple assignment and return values without distinguishing the returned array's library. It therefore adds both calls as unresolved, citing “unpacked dependency value” and “return type of dependency call is unknown.” Its customer report asks the maintainer to identify/test these extra targets as part of the SciPy call assessment. The frozen evaluator records two extraction errors and two handoff errors: **two unique spurious calls, not four independent defects or jobs**.

This is a source-scope precision failure. It is not an unsafe approval, fabricated location, incorrect binding result or demonstrated application failure. The audit does not claim runtime NumPy object identity was experimentally proved: no upstream package was executed. The nominal source/ordinary-import assumptions are the same assumptions under which A/B/C2 may propose conditional captured targets. A broader behavioral regression review could appropriately observe downstream array operations, but that is different from the registered inventory of calls into the selected dependency.

C2 is a materially fairer comparison than the failed original C: it now follows the captured public export paths and gives the same six conditional binding results. Its remaining error supplies one bounded fresh observation of over-inclusion, not evidence that conventional tooling cannot solve the task or that a model has a general commercial advantage. There is no further correction or confirmation set in this study.

For F02, C2's `style` refusals are justified by the actual `**styles` arguments. The different representation does not conceal a missed decidable binding or create an additional failure.
