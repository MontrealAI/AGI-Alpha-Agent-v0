This edition investigates a shared observation that equips several operators to make their own contingent decisions. It delivers a small executable compiler, independently checked finite-model results, complete conditional economic accounting, actual transfer of the retained artifact, and a fresh recipient that correctly stops the commercial offer.

The central result is conditional: **+$22.83 expected operating contribution for the illustrative origin, 0 of 48 fresh offers launched under the frozen commercial policy, and −$323.17 modeled contribution for the combined campaign before optional additional retention or R&D.** Actual customer collections are **$0**. Actual complete research cost and profit are unknown. The fresh cohort is a deliberately constructed synthetic test set, not a market sample. See the [origin economics](results/economics/summary.json), [fresh commercial evaluation](results/economics/confirmation_summary.json), and [campaign accounting](results/economics/campaign_summary.json).

The primary four-configuration comparison uses **H** for an explicitly estimated human-service labor reference, **U** for ordinary frontier-model use, **E** for a competent established expert workflow, and **E+** for that workflow with the retained artifact. No live frontier-model outcome trials were run. The primary economic case gives U, E and E+ the same assumed success probability; a separate analytic sensitivity grid states the gains that would be required. The source does not manufacture a prompting gain or count established expertise again as retained learning. See [economic sources and assumptions](economics/SOURCES.md).

The shared observation is motivated by orbital conjunction services, but the model is a finite decision instrument. Its scope contract is not a learned or calibrated sensor probability model. The compiler was constructed by the researcher using development feedback; no model weights were trained. ## Reproduce without replacing evidence

From this study directory, run:

```bash
python scripts/reproduce.py --output reproduction/my-run
```

From the repository root, the equivalent invocation is:

```bash
python studies/agi-alpha-shared-observation-v1/scripts/reproduce.py --output reproduction/my-run
```

Relative output paths are resolved from the study directory. The directory must be new. Inside this study, the runner accepts outputs only below `reproduction/`; an existing destination is refused. Omit `--output` to obtain a new timestamped directory. The runner neither installs dependencies nor provisions services.

The runner first verifies the technical and independent-reference freezes, all 48 input digests, and both integration custody manifests. It copies only the required source and input closure into `reproduction/my-run/workspace/`. All subsequent commands run there, and the original source hashes are checked again at completion. The original `results/`, `evaluation/`, and `evidence/` outputs remain in place.

The bounded replay executes 13 existing entry points or operations:

1. Compile the origin with the frozen source and scope contract.
2. Recompute its independent exact reference and check the candidate.
3. Replay all 48 released confirmation inputs with the frozen compiler.
4. Recompute origin economics, all fresh commercial decisions and the postconfirmation inverse-price diagnostic.
5. Re-run the existing input-contract probes, information-value inclusion diagnostic, accounting assertions and bundle controls.
6. Transfer the exact retained bundle through the existing fixture lifecycle, execute the recipient in a separate process, compare the identical-content ordinary library, and independently check the recipient output.
7. Replay the illustrative service-only amounts through the pinned native Journal, trust and cost interfaces; reconcile custody separately.
8. Reconstruct campaign accounting transparently as origin contribution plus the sum of all 48 fresh-offer contributions, with B/C held and actual revenue zero.

Its scientific comparisons cover all **144 candidate/reference/check records** in the confirmation cohort, origin results, all economic outputs, the retained bundle, recipient output and declared native ledger values. Timestamps, elapsed times, process IDs, temporary paths and ephemeral signing keys are expected to differ. The historical `results/origin.json` omits the CLI’s `compiler_sha256` metadata field: the runner compares its scientific content, separately compares the exact frozen CLI output with `evaluation/origin-check/candidate.json`, and verifies each economic `technical_sha256` against the input actually used. It never ignores a numeric difference to obtain a pass.

The preserved [successful reproduction receipt](evidence/reproducibility-v2/receipt.json) records **13 successful commands and 31/31 verification checks**. The [first reproduction receipt](evidence/reproducibility-v1/receipt.json) remains available: all commands completed, but its first comparison policy exposed the origin metadata difference and the consequent input-hash difference. That diagnostic was corrected prospectively; the failed receipt was not overwritten. Both published receipt directories include command logs, a source manifest and an output manifest. Full isolated replay workspaces remain local and are omitted from the publication as reconstructible duplicates; the original study sources and scientific evidence are included elsewhere in this edition.
