# Exact-source native evidence demonstration

Run `python scripts/native_evidence_demo.py` from the study directory after generating the final delivery artifacts and execution reports. The wrapper verifies all 26 upstream files against their recorded Git blob and SHA-256 identities before importing the native Python component. All source files and original licenses remain unchanged. The source baseline is `3947e4ec8fd74ad40e13e8ff825a149fa98a10e9` of `MontrealAI/AGI-Alpha-Agent-v0`.

The demonstration uses the existing `Charge` model, Nova-Seed `sealSeed`/`openSeed`, FusionPlan `compilePlan`/`verifyPlan`, and Insight `validate`/`analyze`. It introduces no server, identity service, accounting signer, wallet, runtime adapter or publication infrastructure. Python 3.12.14, Pydantic 2.11.7 and Node 24.22.1 were already installed in the study environment. Repository production Node qualification remains a separate gate; no new packages are installed by these scripts.

Each case binds its frozen input, recovered notebook, complete currently present delivery-file hashes, original and repaired execution-report hashes, passing-check counts and independently authored report references. The final protocol and economic assumption/output hashes are included. A Python/JavaScript canonical digest equality check verifies the same binding object crosses the language boundary. The payload excludes full notebook contents and contains no private inputs.

Nova-Seed encrypts and reopens a local public-research payload, then rejects altered ciphertext. The passphrase is an explicit public reproducibility fixture, not a secret or production credential. AES-GCM randomized sealing means repeated runs produce a different ciphertext and commitment even when the bound plaintext is unchanged. The plaintext payload hash is the stable comparison. Neither encryption nor a matching digest establishes scientific correctness or commercial value.

FusionPlan compiles one job per current delivery, checks the root/proofs using the unchanged upstream verifier, and rejects an altered acceptance specification. Its nominal 100 base units of AGIALPHA per job and 172,800-second duration demonstrate the native schema. They are not a funded price, USDC amount, service-level measurement, token issuance, transaction or live assignment.

Actual resource billing remains unknown. Nine native `Charge` categories per case have `accrued_micro_usd: null` and `basis: unknown`; a zero-accrual/unknown-basis mutation is rejected by the native schema. `paid_micro_usd: 0` records no new external cash payment in this study, not a claim that allocated platform use costs nothing. No signed CostLedger, completeness seal or complete-profit admission is invoked. The separate economic simulation is never promoted into actual accounting.

Insight preserves the unmet evidence requirements for real customer acceptance and complete billing. Its `evidence-needed` response concerns native evidence admission and does not erase an explicitly conditional commercial calculation. MARK, live ENS identity, protected services, settlement and production qualification remain `NOT_EXECUTED`.

The default explicit refresh writes `evidence/native_inputs.json`, `native_nova_seed.json`, `native_fusion_plan.json`, `native_insight.json`, and `native_execution.json`. To replay without replacing supplied evidence, use `python scripts/native_evidence_demo.py --output reproduction/native`; all five new files are written under that directory. The complete reproduction command uses this separate output directory. Rerun an explicit refresh after any evidence or delivery modification so the final publication does not carry stale artifact bindings.
