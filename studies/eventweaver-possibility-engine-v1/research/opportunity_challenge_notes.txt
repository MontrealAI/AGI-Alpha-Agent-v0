INDEPENDENT OPPORTUNITY CHALLENGE — 2026-10-28

The six-candidate initial shortlist is in opportunity_challenge.json. It intentionally avoids treating a familiar workflow as a newly discovered industry. No demand curve or customer willingness to pay has been observed. Public service fees are cost anchors, not endorsement of our offer.

After the parent's temporal-instrument candidate arrived, the recommended direction changed. Compared with the private-consortium idea, an executable time-tag instrument compiler permits a more decisive end-to-end local technical test. The deliverable should be named and contracted as a verified firmware design pack for an OEM's integration process. It is not a physically calibrated measuring instrument, deployment-ready bitstream, hardware latency guarantee or biological result.

The best narrow function is a bounded temporal event grammar with candidate sequence, delayed veto, overlap and explicit finite-resource behavior. It must be more useful than a generic histogram fixture. A possible scientific use is heralded event selection where a photon sequence is valuable only if no veto arrives before the decision deadline. This is a plausible application hypothesis, not evidence from a microscopy customer. Exact behavior must be frozen before construction. Avoid an attractive but ambiguous natural-language description whose semantics can change to pass tests.

Suggested contract questions:
1. Can more than one trigger be active? What is the maximum number?
2. Are bounds inclusive? How are simultaneous events ordered?
3. Is there a new trigger on every clock with the trigger bit high, or on rising edges only?
4. What is the decision time? A later veto must be able to cancel an earlier provisional match.
5. Are outputs one pulse per accepted trigger, or a count when decisions coincide?
6. What happens on reset while candidates are pending?
7. Are input gaps real elapsed time or merely no events?
8. How is overflow reported? Silent loss is an acceptance failure.
9. Is downstream backpressure permitted? If not, say so.
10. What quantities are in clock ticks rather than physical picoseconds?

The best conventional implementation is a straightforward hand-coded temporal state machine or bounded shift-register pipeline, developed by a skilled engineer with current AI assistance, plus an independently written event-history oracle. Give it identical semantics, information and verification tools. A Python-only comparator is weaker than RTL if the product is RTL. A functional tie preserves an integration-service opportunity but defeats a unique technical superiority claim.

Prior art materially constrains novelty:
- NIST's open-source fast multichannel acquisition board already performs time stamping and multiple coincidence detection, expressly permits altering the collection algorithm, and supplies debugged data-transfer code. https://www.nist.gov/services-resources/software/simple-and-inexpensive-fpga-based-fast-multichannel-acquisition-board (web ref turn17search3; page dates require direct verification; do not assume 2015 from memory).
- BrightEyes-TTM (Rossetta et al., Nature Communications 13, 7406, 2022) is an open-source FPGA time-tagger and was used in actual microscopy. The paper distinguishes the physical time-to-digital acquisition stage from downstream preprocessing. https://pmc.ncbi.nlm.nih.gov/articles/PMC9715684/ (turn17search0); https://github.com/VicidominiLab/BrightEyes-TTM (turn17search2); https://brighteyes-ttm.readthedocs.io/en/latest/ (turn17search1).
- Swabian's existing software virtual channels detect coincidences and can compose processed time-tag streams. https://www.swabianinstruments.com/static/documentation/TimeTagger/api/VirtualChannels.html (turn17search4).
- Swabian's existing hardware conditional filter drops irrelevant time tags before transfer; its documentation carefully distinguishes physical input timestamps, hardware delay and internal TDC timestamps. https://www.swabianinstruments.com/static/documentation/TimeTagger/InDepthGuides/ConditionalFilter.html (turn17search5).
- quTAG already provides hardware mute/coincidence/sync filters on specified channels. https://www.qutools.com/files/quTAG/documentation_HR/tdcbase_8h.html (turn17search6); manual https://www.qutools.com/files/quTAG/quTAG-Manual_V1.4.0.pdf (turn17search7).

Commercial challenge:
A customer who already uses a standard coincidence/gating function has little reason to pay for a new compiler. Qualify only requests beyond installed functions, with an existing FPGA integration path, bounded semantics, acceptance authority and internal engineering cost. Defensibility is trusted integration, acceptance evidence, component quality and a reusable contract library; not exclusive access to frontier AI. Price must compete with internal engineers using the same AI and free cores. A pooled-core arrangement can help only when enough buyers want a reusable common grammar, agree to nonexclusive rights and do not impose correlated unlimited warranties. Count core development once and charge coordination/integration per buyer.

Billion-scale discipline:
A niche of 1000 OEMs times five packs/year times USD20000 gives USD100m annual revenue, not USD1bn. Larger significance would require additional reachable categories or verified productive value per deployed instrument. A scenario of 10000 deployed instruments times USD100000 incremental annual productive value reaches USD1bn value created, but both quantities are assumptions. Do not label it a forecast or valuation.

Further prior-art search before experiment freeze found temporal-specification-to-FPGA compilation itself is well established. The primary research paper 'FPGA Stream-Monitoring of Real-time Properties' (2020), https://arxiv.org/abs/2003.12477 (turn26academia45), compiles RTLola to synthesizable VHDL. 'From signal temporal logic to FPGA monitors', https://repositum.tuwien.at/handle/20.500.12708/56259 (turn26search9), is earlier primary work. R2U2's own documentation, https://r2u2.github.io/r2u2/index.html (turn26search3), describes resource-constrained MLTL stream monitors. The Amaranth project, https://github.com/amaranth-lang/amaranth (turn26search11), supplies a free Python HDL, simulator, standard library and FPGA workflow. EventWeaver therefore cannot claim to invent temporal hardware synthesis. Its tested contribution can be a narrow contract, implementation, verified acceptance pack and commercial arrangement.
