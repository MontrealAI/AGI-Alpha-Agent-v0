commit, Git blob identities, byte counts and SHA-256 digests. Every path was compared with `git show`
at the frozen source. The adapter verifies the saved digests before importing native modules.
Its public export includes no private key or credential.

The adapter does not make missing expenses zero and does not fill absent resource categories.

Opportunity costs belong in paired enterprise comparisons and are not duplicated as native cash charges.

## Authorized publication route

The unchanged rules are implemented in `scripts/paper_changes.py`, `scripts/research_papers.py`,
`scripts/publish_paper_site.py`, `.github/workflows/paper-scope.yml`,
`.github/workflows/paper-publication.yml` and `docs/agent/FAST_RELEASE_POLICY.md`.

1. Keep the executable research source/evidence in a separate additive review branch and PR.
   Required hosted lint, behavioral and configured review checks remain applicable.
2. A genuinely separate passive-paper PR may add versioned PDF/TEX originals under `docs/papers/`,
   catalog metadata in `docs/research-papers.json`, and only the deterministically generated paper
   blocks and service workers. Use the existing `research_papers add`, `render` and `check` commands.
   Preserve all old catalog IDs, file identities and resource URLs.
3. The pre-change classifier checks every introduced commit, not only the net diff. Any new study code,
   custom HTML or other unknown path requires the full lane. A static narrative HTML file is not an
   allowed passive-paper asset. Reading/experience links in a passive overlay must already exist as
   exact qualified software-baseline bytes.
4. Review and merge through the ordinary authorized repository process. The existing Paper site
   publication workflow restores the qualified PUBLIC software site, proves the paper-only descendant
   overlay, validates the homepage and paper links, rechecks main and live ancestry after acquiring the
   shared Pages lock, and verifies the served bytes. A lease or unsuccessful check remains a genuine
   limitation; no independent deployment is substituted.
5. Publish a new browser edition only through the full qualified source process. A source/archive link,
   local HTML inspection or successful PDF build is not a live Pages verification.

The full software release policy keeps security, integrity, source, artifact, browser and regression
requirements. Its named cosmetic feedback is advisory; other failed required checks are not waived.
The held native-source restrictions are preserved, and this study does not invoke or modify those files.
