Illustration using 20,000 uncached input and 5,000 output tokens at the listed standard rates: Terra $0.045, Sol $0.09, Astra $0.45. This arithmetic is not an observed cost per accepted task. An inexpensive model with expensive errors can cost more overall. Route by total expected cost:
C = inference + execution + human review + probability of correction × correction cost + failure exposure.
Use deterministic code for exact numerical calculations and repeatable checks. Cache pinned source extraction. Escalate unknown representations, failed invariants and genuine scientific judgments. Do not have every model reread every artifact.

Commit date: 2026-10-26T21:18:03Z.
Read actual LaTeX `preprints/The-Exponential-Time-Hypothesis-is-False-October-25-2026/build/main_full_version.tex` (Git blob f7af85e623b58e0ca9f4b9416916d442defa963a, 214,857 bytes), especially abstract, main theorem, related implications and technique overview. Also inspected `lean/docs/378.md`.

The manuscript's main theorem claims fixed-k exact counting in polynomial space and time
(n+m)^{O_k(1)} 2^{O_k(n loglog n / sqrt(log n))},
with a sharper sparse-input exponent. The public scope note describes a Lean-verified bound with an extra loglog factor. These must not be conflated.

The illustrative construction deforms Boolean clause inputs into polynomial linear forms, separates groups after fixing shared measurements, computes Taylor information and reconstructs the desired count by interpolation. Its asymptotic parameters balance three exponential costs. The overview explicitly handles the finitely many smaller inputs by exhaustive search.

Consequently: the paper does not itself deliver a practical solver, a demonstrated crossover, or general polynomial-time NP algorithms. The useful inference is that representational invention can reopen previously discouraged searches. A future dependency would be a public implementation with independently verified correctness and a measured finite-size advantage on the beneficiary's instances.

No Lean build or independent theorem validation was performed. The retained source is a reading cache and should not be bundled without preserving repository licensing and attribution.

## Invention directions suggested by these sources

These are original proposals, not empirical findings.

1. **Make an unobservable mechanism observable.** A beneficiary wants to distinguish rival explanations that produce the same existing measurements. Construct an intervention and measurement protocol that separates the rivals within existing resource limits. The first paid outcome would be a validated experiment design; the larger possibility is an enterprise that invents new forms of observability. Test identifiability before and after against strong experimental-design baselines, then transfer the instrument to a different mechanism family.
2. **Produce an outcome no participant can produce alone.** Co-design a production chain, shared instruments and incentive-compatible commitments, so a set of modest facilities can undertake an outcome outside each facility's standalone capacity. The missing means is joint technical and institutional composition, not a marketplace interface. A first instance must satisfy real resource, acceptance and participation conditions under a conventional-delivery comparison.
3. **Turn mathematical structure into a portable research instrument.** Build a representation that exposes computable invariants shared by apparently unrelated fields, use it to obtain an important new result in one field, then give a successor a meaningfully different task. BootLoops is relevant prior art and a competent free substitute; novelty cannot rest on using toolkits or keeping notes.
4. **Make discarded information experimentally usable.** Reinterpret old measurements under an executable inverse model, construct the next acquisition needed to break ambiguity, and deliver a capability that neither the archive nor a static model provides separately. A simulation-only first step must be marked accordingly and must include model misspecification.

Selection should depend on the importance of the newly feasible activity and the decisive construction, before dataset convenience or easy sales.
