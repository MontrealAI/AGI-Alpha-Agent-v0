# Mechanical evaluation protocol

## Scope and independence

This evaluation concerns synthetic Ontario commercial mutual-NDA support packets. It does not adjudicate legal correctness, enforceability, appropriateness of advice, or professional acceptance. The evaluator is a separate same-session agent, without an established professional legal qualification. Comparator D is independently authored from the common task specification, without viewing B/C implementation. It uses ordinary Python text and comparison tools; it is not a measured run of a paid commercial legal product.

If the same agent also authors the primary corpus, that fact must be reported and cannot be described as blinded external evaluation. A separate corpus author receiving only the common specification is preferred. Answer keys remain outside production inputs and retrieval until predictions are sealed.

## Order and preservation

1. Establish common input/output schemas, playbook rules, supported scope and stopping rules.
2. Construct and test B/C/D using development documents only. Log failed attempts, source changes and activity intervals.
3. Freeze all prediction code, rules, helper assets and source identities before creating primary documents.
4. Independently generate and freeze 24 new synthetic cases and separate factual answer keys. Use four cases from each of six declared strata: direct changes, unfamiliar wording, cross-references, amendments, conflicting or absent provisions, and out-of-scope or unanswerable requests.
5. Give only input documents and the common playbook to the production runner. Run each method once on every case, retaining timing, failures, corrections explicitly allowed by the frozen protocol, and the complete packet.
6. Seal predictions before reading private keys. Verify input/source hashes and source-span fidelity, then score against factual keys.
7. Preserve all failures. No retrospective source repairs, substitutions, exclusion of difficult cases, or claims of professional acceptance.

## Mechanical acceptance

Scoring separates reference fidelity, extraction completeness, explicit playbook comparisons, escalation, and unsupported revisions. Severity weights follow the common scope: 5 for R1–R5 and R7; 3 for R6 and R8. Any incorrect rule status, missed required material source, unsupported substantive revision, or invalid supporting source prevents mechanical acceptance of the complete packet. Zero false passes on severity-5 issues is a separate mandatory criterion. Averages remain descriptive and cannot override that gate.

Recognized uncertainty is reported separately from completed support work. A correct escalation is useful but does not establish that the underlying legal work is complete or eliminate professional effort. Rejected packets and escalations remain in workload and cost denominators. Out-of-scope requests must not receive substantive legal answers.

Fields requiring professional judgment remain unassessed. Mechanical correctness cannot be used as a proxy for legal-service acceptance. A fresh matched professional review study remains necessary to measure residual lawyer effort, false confidence, quality equivalence and commercial usefulness.

## Resource accounting

Execution elapsed time and process CPU are actual measurements where logged. Construction activity intervals are elapsed agent work, not human labor minutes. Token/inference billing, human attention and qualified review costs are unknown unless separately supplied; no absent value is treated as zero. Any monetary allocation is a labeled scenario rather than an observed cost.
