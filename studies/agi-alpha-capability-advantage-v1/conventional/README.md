## Executable alternative

Import `solver.py` and call `solve(task)`. It accepts the same finite conductance-job schema and returns a complete numerical result or a reasoned refusal. It uses public conventional algorithms and retains its own implementation across jobs:

- Sparse network assembly and SuperLU factorization; one factorization serves every right-hand side at the same conductance vector.
- Bounded inverse calibration with SciPy trust-region least squares, analytic implicit sensitivities, and cached states/factorizations. Local identifiability is checked at the supplied initial point. Prediction loads use the fitted conductance vector.
- Convex finite-scenario minimax design represented with an epigraph variable, scaled constraints, analytic compliance gradients and SLSQP. A supporting-plane linear program checks the final numerical optimality gap. A second optimization attempt is permitted only when the bound remains insufficient, within the fixed solver budget. This is competent conventional optimization, not a deliberately naive finite-difference baseline.

The public workload contract fixes a 60-second complete-job budget; this solver stops new iterative evaluations after 45 seconds to leave room for independent acceptance and native packaging. The lead's outer timeout remains authoritative. Source-validation, startup, independent acceptance, serialization and packaging are excluded from the displayed solver-only development timings and must be added by the primary campaign.

Development input fixtures are synthetic engineering software tasks, not paid customer orders or physical validations. The initial 49-node development jobs all passed independent acceptance on the first numerical source version. Later schema guard and budget edits are preserved separately; they are not hidden failed scientific confirmations. The registered 400-node discovery chain tests scaling before the primary freeze. No held-out primary outcome informed this source.

## Primary method references

Inspected 26 October 2026. The execution environment uses NumPy 2.3.5 and SciPy 1.17.0; current online documentation identifies SciPy 1.18.0. The employed interfaces are also present in the installed version.

- [SciPy sparse LU](https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.linalg.splu.html): factorization and repeated solves.
- [SciPy bounded nonlinear least squares](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html): analytic Jacobians and trust-region reflective methods.
- [SciPy SLSQP](https://docs.scipy.org/doc/scipy/reference/optimize.minimize-slsqp.html): constrained optimization with supplied derivatives.
