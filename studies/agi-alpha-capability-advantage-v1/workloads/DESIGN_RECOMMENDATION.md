# Demanding-work design recommendation

Status: independent pre-experiment design; no development, discovery or held-out numerical outcome has been evaluated by this role. Source inspection is read-only. This is an additive research family; it does not qualify an installed operator, scientific worker, contract or live identity.

## Inspected baseline

The actual Alpha Workbench numerical handler is exact rational polynomial integration with two quadrature rules. `studio.py` explicitly limits its frozen numerical comparison to that adapter. The source identities are recorded in `inspected-source-identities.json`.

The existing scientific engineering worker already constructs a time-indexed scheduling MILP and invokes `scipy.optimize.milp`/HiGHS with sparse constraints, deadline, release, capacity, dependency and baseline-movement requirements. It independently checks schedules. A new scheduling wrapper alone is therefore not evidence that existing agents lack a capability.

The thermal-fluid studies already contain finite calibration and useful successor experiments; their foundation audit explicitly records stronger conventional calibration, unmeasured demand, failed accuracy implications and held installed-runtime boundaries. Avoid duplicating or bypassing those lanes. A new scientific software task may use a thermal interpretation only with explicit synthetic scope and a distinct additive execution path.

Recommended bounded study: the first two connected families. A third stiff/hybrid family is useful only if enough independent construction and verification time exists; adding it solely to inflate family count weakens the study.

The numerical methods themselves are established, publicly available methods. Scarcity can only mean measured lack, costly reconstruction or difficult reliable integration in the tested recipient population. Neither a new name nor a missing file proves lack of capability.

## Proposed prospective protocol

1. Fix the complete job schema, units, reference physical discretization and admissible parameter/topology scope before development. Research-generated inputs must be labeled as simulated engineering cases with no paid demand or physical validation.
2. Use three capability generations: G1 forward/sensitivity capability produced by an inverse job; G2 constrained design composition produced when fresh inverse work creates a downstream allocation need; G3 multi-scenario/changed-topology composition produced by an independently specified new design job. Valid components do not imply valid compositions.
3. Use two development jobs per generation and four held-out jobs per generation (12 held-out underlying jobs), with dimensions/topologies, observation patterns and active constraints varying meaningfully. Execute the same jobs across A/B/C/D (48 primary method evaluations), not 48 customers. This is a small bounded engineering sample: enough to demonstrate connected reuse, not population-wide economic asymptotics.
4. Reserve all held-out case definitions, numerical oracles and evaluation outputs to an acceptance owner until source/selection freeze. Public interfaces and scope are shared before freeze. Do not encode hidden parameter answers in skill records, descriptions, example outputs, filenames or retrieval indices.
5. Before acquisition, give receiving model agents the full problem specification, ordinary tool access, source search and a realistic equal construction allowance. Record model family, actual allowed tools, retained portfolio, begin/end time and all code/attempts. Suggested minimum 15 minutes of active construction per family per recipient; if the whole study cannot afford that, report an incomplete absence test rather than claiming inability. Equivalent independent reconstruction may be retained for subsequent A jobs.
6. Use at least three genuinely different artifact portfolios: numerical forward/sensitivity experience; constrained optimization experience; general integration/testing experience. Describe these as current-session model instances with different retained artifacts and task exposure. Do not call them independent pretrained foundation models or externally operating ENS agents. Actual model identities must be recorded rather than inferred.
7. A retains each recipient's own accumulated code and every legitimate improvement. B and C share exactly the same validated sources, evidence and dependency metadata. B gets competent keyword/tag/full-text search, dependency closure and planning; C may additionally traverse typed adjacency. D gets an independently authored best conventional composition. No forced rediscovery, absent cache, naive dense-only solver or deliberately incorrect method is an acceptable strong comparator.
8. Compare a complete accepted outcome. Gate success on finite schema, feasibility, numerical error/residual, independent objective bounds and full report artifacts; validate timing only for equally accepted jobs. Failures and abstentions remain in cost and job counts.
9. Measure whole acquisition/selection/adaptation/verification wall time and CPU, all attempted source versions, code/runtime identity, and actual human attention if observable. Model authoring/inference bills are unknown unless receipts exist. Price complete cost categories parametrically without treating assumptions as invoices.
10. Freeze the complete primary campaign and timing order before any held-out result. No outcome-driven repaired rerun counts toward the same primary. Development corrections remain preserved; a separate fresh follow-up requires a new freeze and held-out cases.

## Acceptance design for the recommended two-family chain

Use a sparse symmetric positive-definite network balance model `K(theta) u = q + B a`, with explicit grounded boundary conditions and positive conductances. It can represent linear diffusion/steady transport without claiming a validated physical installation. Input files include all public network connectivity, observation matrix, loads, parameter bounds, decision bounds and declared noise/tolerances. The agent receives enough information to solve the task by any conventional means.

- Forward checks: independently assemble every incidence/ground term; bound relative residual and compare selected small instances with dense solves; test conservation and invariance to node permutation.
- Inverse checks: independently compute the supplied objective at returned parameters, test box feasibility, assess predicted observations on withheld evaluation loads, and compare declared optimality to an independently run high-accuracy reference. Parameter truth is not a correctness criterion when the inverse problem is nonidentifiable. Separate identifiability/refusal requirements from numerical convergence.
- Design checks: independently replay every constraint for every required scenario, recompute objective and compare against an independently formulated LP/QP/MILP lower bound or complete small-instance census. Claimed safety must be scoped to the provided finite scenarios.
- Composition checks: independently check interface shapes/units/version identities and full end-to-end outputs. Test at least one incompatible dependency, stale skill, wrong scope and revoked status refusal. These are software controls, not additional valuable jobs.

Do not choose tolerances or timeouts after observing which method wins. Publish realistic and identical operation budgets. Only claim inability when the real receiving agent's best allowed attempt fails; distinguish inability under this budget from mathematical or global impossibility.

## Economic connection

The buyer hypothesis is an engineer commissioning a reproducible calibration or design report to choose parameters/allocations under explicit constraints. Public source or numerical literature supports the class of work; it does not establish demand for this particular service. Actual receipts remain zero absent real collections.

Transfer value is the recipient's best-practical-alternative cost minus acquisition, adaptation, execution, verification and allocated shared costs, conditional on equivalent accepted quality. Construction is charged once; cross-agent fees are enterprise-internal transfers. Graph value is C minus B after graph construction/upkeep, not C minus a weak A. A second investment must draw only from collected modeled operating-generated surplus after obligations/reserve, and independently repay its full incremental cost on fresh jobs. Level 6 needs difficulty-adjusted construction/validation efficiency evidence; merely having three skill versions is insufficient.

## Primary-source method references

- SciPy sparse factorization: https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.linalg.splu.html (supports factorization followed by reusable solves; no reason to deny this to A/D).
- SciPy bounded nonlinear least squares: https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html (supports callable or numerical Jacobians, sparse structures and robust loss).
- SciPy ODE integration: https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.solve_ivp.html (Radau/BDF/LSODA and event support; ordinary stiff methods are competent alternatives).
- SciPy MILP: https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.milp.html (HiGHS wrapper with integer constraints and gap/bound outputs; already represented in the actual Alpha scientific worker).
