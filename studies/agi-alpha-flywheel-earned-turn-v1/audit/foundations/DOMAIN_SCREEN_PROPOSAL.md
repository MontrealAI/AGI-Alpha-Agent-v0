# Bounded mission-family screen: proposal for root to freeze before measurements

This is a development-design proposal, not a retrospective protocol and not a result. Root must freeze its actual screen before executing it. Compare exactly three families, with two fixed sizes and a small number of declared development instances each. No old confirmation instance becomes a development instance, and no final confirmation is generated before domain selection and source freeze. Log all variants, including failures. Stop the domain screen at its declared budget, even if every family fails.

## Leading hypothesis: sparse response instruments

The change is from repeatedly reconstructing a solver for each demand to retaining an executable response instrument for an unchanged network. Changed demands are fresh right-hand sides, not cached answers. A later permitted conductance change creates a genuinely different response map. A cheap low-rank update builder may use the retained parent’s solves to construct that map; a strong native refactorization builder remains eligible and should win whenever cheaper.

For grounded positive conductances, let `A x = b` describe the current network. A permitted positive update is `A_new = A + U C U^T`. The parent computes `W = A^{-1}U`; the successor uses the small matrix `C^{-1}+U^T W` with the parent to answer fresh updated-network demands. This is the established Woodbury/Schur mechanism, not an invented algorithm. It creates testable usage events both during successor construction and during new output execution.

Mission A should produce a useful response and retain a correctly serialized factorization if admission justifies it. Mission B should solve changed loads and record actual parent use. Mission C’s change must come from a fixed rule applied to B’s actual accepted state (for example, a bounded reinforcement of its highest-load allowed edges). Each arm follows the same accepted mission requirements; any differing plan-induced input must be disclosed as a policy outcome, not silently pooled as the same task.

## Decision rule and break-even before confirmation

For each development family, estimate `K`, the construction plus qualification/integration cost, and `delta`, the positive per-use cost difference against the strongest competent alternative. Let `M(R)` be retrieval and maintenance cost over recurrence `R`. A provisional reuse horizon is the smallest `R` with `R * delta > K + M(R)`. If `delta <= 0`, no finite recovery horizon is asserted. Report CPU/time and declared work units separately; never convert one to money without measured billing.

Select the family with credible independent verification, an executable successor relation and positive plausible headroom at a useful declared recurrence. If every family lacks headroom against a strong conventional method, deliver that bounded negative screen rather than extend search until it wins. Equal-enabled conventional reuse may be identical in outcome and cost; that is evidence the useful mechanism is conventional and transferable, not an agent-specific advantage.

## Implementation pitfalls to resolve before freeze

- A SciPy `SuperLU` object is not directly a durable serialized capability. Either serialize L/U/permutations with a verified reloader, or charge factor reconstruction after every process restart. Do not imply restart persistence from a JSON ancestry label.
- Check residual and conservation using an implementation that does not call candidate solve code. Residual tolerance alone does not establish a strong forward-error bound for arbitrarily ill-conditioned systems. Define conditioning/scope and reference-check manageable cases.
- Test one changed matrix hash, nonpositive/unsupported update, stale dependency and expired receipt. A valid old factorization cannot certify the changed system.
- Native sparse refactorization can beat low-rank construction at small sizes or sufficiently large update rank. Include that crossover and never disable the winning native solver.
- Keep the service account protected from research spending. A new construction request requires an improvement account reservation independent of service obligations.
- A real-time saving is not automatically a reusable resource. Record the reserved worker interval, actual service consumption, transferable remainder, new-task reservation and actual new-task consumption. Research-funded baseline execution is separately charged, not called earned service capacity.
- Compare parent retained, parent removed with reconstruction allowed, strong parent-free direct solve, independently constructed equivalent factorization where feasible, and equally enabled conventional reuse. Record actual parent solve calls. Hash lineage alone is insufficient.
- Separate first construction, execution, maintenance, serialization/reload and integrated checking. One-time research analysis and human implementation effort belong in the full-investment ledger, even when monetary measurement is unavailable.

## Why this can advance the prior study without rewriting it

A fixed competent algebraic builder can remove search-allocation uncertainty and make the cost of a complete nominee knowable before reservation. Positive service headroom can be tested without sacrificing the incumbent. The successor can be tied to the actual prior accepted network and response. This repairs experimental prerequisites; it does not guarantee that the final instrument beats a direct specialist or recovers research investment.
