# AGI ALPHA — Earned Turn browser companion

Open `index.html` in a current desktop browser. No account, wallet, installation, API key or network connection is needed for the default mode. The file bundles its exact module closure. Local IndexedDB and Web Crypto are required; if unavailable, the application refuses execution rather than pretending persistence is present.

## Four fresh computations

Press **Start four missions** once. The actual AGI ALPHA workbench executes a bounded local adapter:

1. **A — Deliver:** solve an 8 × 8 synthetic grounded conductance network and retain its numerical factorization after a separate edge-balance check.
2. **B — Reuse:** solve changed loads with the retained factor. No previously computed answer is substituted.
3. **C — Construct:** select the two largest absolute edge flows from B's actual accepted response. Add two permitted positive conductance changes. Use two parent solves to construct a rank-two Woodbury update instrument, then use and check the instrument.
4. **D — Transfer:** solve fresh loads on the changed network using the retained update and parent, and check the result independently.

The graph is a computational example, not a physical installation. The browser's 64-node dense JavaScript implementation is a separate mode from the native SciPy confirmatory experiment. The recorded research panel never executes the native experiment.

The competent direct reference retains factors when the network is unchanged and refactors when it changes. It is allowed to beat the inherited method. Conventional factor caching and Woodbury updates use the same established mathematics; this browser does not establish a unique agentic advantage.

Device/JIT/scheduling effects make small timing differences unstable. Operations are not CPU cycles, cash or collected proceeds. Unknown full monetary and human costs are not represented as zero.

## Persistence, STOP and rollback

The browser imports the exact upstream `createWorkbench` and transactional `openMissionStore` implementations from `runtime/vendor`. The store uses compare-and-swap revisions. It persists accepted history and an intent reservation before computation.

- **Pause after result** stops at the next accepted boundary.
- **STOP** aborts the active workbench at a checkpoint; no partial output is accepted.
- Closing or reloading the tab stops computation. It does not leave a service running.
- On restart, every stored accepted output, asset identity and pack is rechecked. A pending unacknowledged attempt is charged its reserved ceiling; the cursor does not advance. Resume is explicit and can be refused when the remaining budget cannot cover another reservation.
- Duplicate acceptance is prevented by the phase cursor and atomic accepted state, not by an external exactly-once guarantee.
- **Rollback to the parent** deactivates successor use while preserving the successor's historical evidence and all prior outputs.
- Stale-evidence and unsupported-update controls exercise actual refusal functions on copies.

Up to twelve runs may remain in this browser's upstream store. A new run preserves old entries; reaching the store limit fails closed. Export evidence before intentionally clearing browser storage. This local integrity model is not protection against a malicious user rewriting all local code and hashes.

The event ledger records run start, resume, stop, pause, acceptance, reservation, refusal, rollback and diagnostic controls. `intervention_count` counts run-control interventions; human duration is unknown. Setup, debugging and authoring remain separate research work.

## Build and verify

From the complete package root:

```bash
python3 browser/build_demo.py
node browser/checker.test.mjs
```

The first command uses Python's standard library and builds a single HTML file from the source closure. Runtime Python is not needed to open the built HTML. Numerical tests use Node 24.22.1 in the executed environment. The package declares Node 22.17.1–24 compatibility; those other versions were not separately executed here. Upstream runtime requirements are source-inspected, not proof of a maintained installed service.

Optional browser QA uses Playwright 1.62.1 and a Chromium executable:

```bash
cd browser
npm install
npx playwright install chromium
npm run test:ui
npm run test:recovery
npm run test:recorded
```

The QA loader also honors `AGI_PLAYWRIGHT_MODULES` and `AGI_BROWSER_CHROME`; the repository's previous study is not a dependency. QA blocks outbound HTTP requests, checks desktop/mobile overflow, downloads, parent usage, baseline reuse, negative transfer, STOP/resume, pending-intent interruption, conservative budget charge, stale results and rollback.

`qa/*.png` files are visual-inspection intermediates, not publication evidence or required user deliverables. Numeric QA records and failed development records are retained separately.
