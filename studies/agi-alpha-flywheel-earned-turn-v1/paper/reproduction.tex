\section{A usable companion and an auditable publication}
\label{sec:reproduce}

\subsection{One obvious start, three explicit execution states}

The self-contained browser companion opens with a single \textbf{Start four missions} action. It requires no
account, installation, wallet or API key. A small synthetic network is solved locally in JavaScript; the
reader sees the verified response, retained factor, changed-network successor, fresh reuse, declared costs
and a conventional comparison. The load can be changed. Evidence can be downloaded. STOP, interruption,
restoration, stale-scope refusal and rollback are visible parts of the journey.

This fresh computation uses a 64-node browser workload and a declared operation tariff. It is a working
explanatory implementation, not the native CPU experiment. The tariff excludes hashing, serialization,
rendering and browser storage overhead. The separately labeled \textbf{Recorded confirmation} panel embeds
the unmodified native analysis, exact source identities and the first registered A--B08--C--D01 lineage.
It shows the failed product gate as prominently as the successful construction. Reading that panel does
not execute the native campaign. An authenticated approved executor is explicitly disconnected. Closing
the tab stops local execution; browser persistence does not imply a running service.

The browser's executable closure is frozen separately from presentation. Final recorded-result integration
preserves that identity. Automated component, interface and actual reload checks are retained, together
with a final 32-check presentation/download report. Desktop and mobile layouts were visually inspected.
The interface neither claims a live hosted agent nor issues transactions.

\subsection{Reproduce the evidence without changing its status}

The complete companion contains source, protocols, original raw data, rejected development attempts,
intervention records, the bibliography, editable SVG/PDF figures and this authoritative author PDF.
Large raw records are compressed losslessly in an inner evidence archive; the supplied extraction command
verifies its SHA-256 manifest before admitting files. The paper-only source package is sufficient to rebuild
the publication and its figures without unpacking the numerical trial arrays.

The recorded environment is Python 3.12.14, NumPy 2.4.6, SciPy 1.17.0 and Node 24.22.1, with numerical
thread counts fixed to one. Publication figures use Matplotlib 3.10.8; the executed paper build uses
XeLaTeX/BibTeX from TeX Live 2023 and Latin Modern fonts. Exact versions, platform observations and
reproduction commands are in \artifact{protocol/ENVIRONMENT.json}, \artifact{requirements.txt} and
\artifact{REPRODUCE.md}. Once dependencies are installed, the numerical campaign requires no network service.

First require the delivered \artifact{protocol/FREEZE.json} to exist, then verify its 32 file identities.
The freeze script can also create a new freeze when none exists; that behavior must not be used to legitimize
a modified or incomplete historical package. For read-only reconstruction of the result, run the producer
aggregator and independently implemented raw auditor into a new output directory. Repeating the numerical
missions uses \artifact{companion/confirm.py} with the original \artifact{SEEDS.json} supplied explicitly
through \artifact{--seeds-file}. The runner labels this reproduction, not additional confirmation. CPU
timings are new measurements and need not match historical observations byte for byte.

The source archive rebuild runs \artifact{paper/build.sh}, regenerates vector figures from packaged data,
and executes XeLaTeX, BibTeX and reference-resolution passes. The delivery verification binds the canonical
PDF to a clean packaged-source rebuild and a visual review of every final rendered page. PDF serving
metadata can alter a displayed copy's bytes; the author PDF preserved inside the source archive is the
authoritative identity for exact comparison.
