## What the acceptance verifier actually checks

The fresh driver writes two canonical `tae.artifact.v1` packages, each with exact input, mission and capability identities, an integer output and empty current proof/authority. The independent `tae.proof.v1` receipt binds exact artifact bytes, exact input bytes, criterion bytes and checker bytes. The EVM wrapper captures the files and reruns the frozen standalone checker in a separate Node process. It compares the entire emitted receipt, not just an `accepted` flag. The frozen candidate source manifest is separately hash-anchored, and the captured candidate file digest joins the local seed commitment. A digest binds bytes; it is not evidence of semantic correctness or user permission by itself.

The source bridge checks repository revisions and source identities, routes both mission outputs through Alpha → Manager → Jobs → Fleet, and verifies exact output groups. The final `study/verify-journey.mjs` cross-checks the scientific input, mission, capability, artifact and proof identities against every repository binding and the EVM. It also requires each exact 16-stage history, distinct transaction hashes, ordered blocks, positive gas, matching aggregate gas, seed/job identities, lineage resets and token conservation. Both joins pass, and eight targeted regressions reject mutations while preserving acceptance of the original valid artifacts. The scientific result is computed before the local job is posted; the chain is an exact-evidence settlement replay, not a live award-to-worker dispatcher.
