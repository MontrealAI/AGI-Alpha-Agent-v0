Use a fresh copy of this companion on a machine with **Git, npm and Node 24.19.0**. This is the recorded runtime; setup accepts later Node 24.x versions from 24.19 onward, but a changed runtime requires its own revalidation. The demonstrated environment is Linux. Other operating systems have not been qualified.

```sh
node study/quickstart.mjs
```

First setup fetches pinned public source, installs locked local dependencies with package lifecycle scripts disabled, and compiles the local contracts if needed. Subsequent starts reuse those dependencies. Setup refuses different checkout revisions or tracked source edits; it does not reset an existing repository. Network access is needed for the initial public downloads. Download and installation time are separate from the measured mission time.

The interface starts with clearly labelled recorded evidence. **Run the local journey** creates a fresh result; the comparative score table remains the recorded experiment and is labelled accordingly. **Take the 3-minute tour** explains each step. English and French, keyboard navigation, reduced motion, technical evidence drawers, export and restore are included. The local server allows one fixed journey at a time, rejects arbitrary inputs and commands, and stops a run after 60 seconds. **Stop local run** stops its local process group on the tested Linux environment. Completed evidence remains available for inspection. `Ctrl+C` stops the server and an active run.

For a readiness check or a terminal-only run:

| Construct | Reusing the wrong meaning can produce a confidently wrong answer. | A typed executable capability separates dependency structure from its algebra. | Verify | A saved success cannot certify a different mission. | Independently implemented path enumeration or reachability checks the current output. Generic module qualification can be reused only under the exact source, criteria, runtime and context identity. |

| Settle locally | Funding, roles, execution evidence and payouts have different responsibilities. | Existing Access, NovaSeed, RiskOracle, JobMarket and MARK contracts perform their actual roles on an unforked disposable EVM. Exact artifact and receipt bytes are committed; test validators vote; mock-token accounting is checked. |
| Evolve | A successor should enlarge useful behavior without inheriting certification. | A distinct remediation-impact mission retains four modules and adds the Boolean kernel. Multiple paths now count a reachable target once. The child starts with empty current proof and authority and obtains its own fresh check and local risk review. |

The selected parent has total **125** over four targets. The selected successor has mixed outputs **1, 0, 1, 0**, total **2**. It is a different task semantics, not a renamed demand instance. The illustrative successor was selected after scoring to expose this distinction; it does not alter the evaluation population or its score. The exact packages are under [journey-inputs](study/results/journey-inputs/).

**Execution order matters:** the driver computes and checks artifacts, executes the four-repository source route, and then posts their exact evidence to the local EVM. The contracts do not trigger an installed Fleet dispatcher. The new public graph capsule is a byte commitment; it is not an encrypted payload. The broader installed runtime, held Harness integration and independent production operators remain outside this demonstrated scope.

## The original mechanism and measured result

The unnecessarily restrictive assumption is that every successor must replay all generic qualification tests for every unchanged module. The new adapter makes each qualification record specific to an exact module dependency closure, evaluation context and runtime. It reuses that generic evidence when the identity remains valid, but always recomputes the new answer with a separate checker. Changed semantics require a new capability and the relevant new module qualification. Historical evidence never grants current proof or authority.

The frozen population contains **48 missions: 16 weighted-demand, 16 remediation-impact, eight flat reductions and eight invalid requests**. Three repetitions compare six predeclared variants; a seventh old-representation variant is explicitly supplementary. Each campaign therefore contains **1,008 mission attempts**. Both the first scored campaign and the disclosed confirmation are retained: **2,016 attempts total**, not 2,016 independent tasks.

The table reports the final known-bank confirmation. Valid and invalid denominators are separate; module checks and wall time are per 48-mission trial. Three timing repetitions are descriptive, with substantial system variability.

| Variant | Valid accepted, over 3 trials | Invalid refused | Generic qualification cases / trial | Median trial time |
|---|---:|---:|---:|---:|
| Integrated loop with scoped reuse | 120/120 | 24/24 | 64 | 59.867 ms |
| Integrated loop with full replay | 120/120 | 24/24 | 1,600 | 163.225 ms |
| Rebuild without inheritance | 120/120 | 24/24 | 1,600 | 164.472 ms |
| No capability construction | 24/120 | 24/24 | 8 | 27.660 ms |
| Retain the wrong algebra | 84/120 | 24/24 | 64 | 57.526 ms |
| Supplied direct specialist | 120/120 | 24/24 | 64 | **54.921 ms** |
| Old representation, supplementary | 33/120 | 24/24 | 64 | 65.468 ms |

The prospectively frozen technical threshold was at least 50% fewer repeated module qualification cases with identical decisions and fresh per-mission checking. The observed reduction is **96%: 1,600 → 64**. This is not a 96% reduction in all validation, CPU, dollars or human effort. Fresh reference work remains **3,624 steps per full-quality trial**; generic qualification reference work changes from **44,416 to 1,733 steps**. Including those unchanged fresh steps, the counted reference-step reduction is **88.85%**. Source hashing, construction, delivery, settlement and authoring still cost resources. All exact counters are retained in [scored-v2](study/results/scored-v2/summary.json) and [COST_LEDGER.json](evidence/COST_LEDGER.json).

The direct specialist has the same accepted answers, fewer candidate operation events and the better final median timing. It is a supplied deterministic algorithm, **not a recruited human expert**. These comparisons support a finite engineering result, not a claim of optimality or superiority over people. The no-construction alternative accepts 8 of the 40 valid task instances per trial, while the constructed capability accepts all 40 under the declared bounds; external usefulness and economic value still require separate evidence.

## Ownership, cost and next experiment

WORLD records the finite input and uncertainty. POLICY names exact answers, limits and allowed actions. PROOF consists of scoped independent-algorithm receipts and retained evidence. AUTHORITY is separately enforced and empty in descendants. Export/restore retains executable assets and history while resetting current proof and authority. A symbolic Kahn/DFS planner swap is tested; a learned-model provider swap is not established. The local operator's fixture permissions do not become production authorization.

No external payment, sale, firm offer or customer demand is evidenced. The executable experiment makes zero external model-provider calls; that does **not** make its development free. Assistant authoring, engineering, host cost, data preparation, failed attempts, maintenance and human oversight are not fully priced. The [ledger](evidence/COST_LEDGER.json) therefore keeps fully attributable cost and realized profit as unknown, preserves measured resource counters, and labels hypothetical human-time sensitivity separately. The measured technical threshold is not substituted for the requested compelling external practical value.
