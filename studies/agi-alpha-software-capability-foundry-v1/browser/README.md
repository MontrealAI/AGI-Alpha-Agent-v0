# The Software Capability Foundry: browser companion

Open `Foundry_Lab.html` in a modern browser. The complete local example runs without an account, installation, API key or network connection. The same application can be served from this directory as `index.html`; its original ES modules remain available for review. `build.py` reproduces the self-contained file from those sources.

## Three explicitly separated modes

1. **Live local computation:** the browser hashes the supplied public text files and produces new manifests and drift reports. The included files are complete, byte-pinned source files from AGI ALPHA main `f836f06e8351e64db1da770e16e304b5feb01f28`. Browser computation is a public engineering example, not the protected Python benchmark.
2. **Recorded research:** `research.json` is a presentation of the separate experiment's measured results. It is never presented as an experiment running in the browser.
3. **Approved executor:** not connected in this companion. The page does not provision a native service, acquire credentials, commission paid jobs, invoke Fleet, settle a transaction or clear an original Harness restriction.

The existing `createWorkbench` interface and its seven-stage plan are used unchanged. Its source dependency closure is vendored byte-exact with original license notices; see `vendor-manifest.json`. Public local evidence remains HOLD, unauthenticated historical import, without inherited proof or authority.

## The visible journey

- **A:** verify eight public companion-source files (31,837 bytes) and retain the authored local snapshot instrument's version, code hash, interface and scope.
- **B:** use that exact instrument on eight different public gallery files (31,999 bytes). The selected result records one actual parent invocation.
- **C:** use the instrument twice to produce a different output, an exact drift diagnostic. The public fixture deliberately changes one body, changes one file mode, omits one file and adds one file. Its expected result is visible and is not a protected task. The fixed constructor was authored before execution; the browser does not claim to discover new code autonomously.
- **D:** refuse a parent-traversal path before processing content. No external file is read.

The stronger substantive claim about improvement-making belongs to the separately frozen Python experiment and its controls. These local manifests are not evidence that a saved answer constitutes a new engineering capability.

## Completed recorded result

The research panel presents one frozen campaign and stops at its observed result: **HOLD_FLYWHEEL_SUPERIORITY**. All 1,344 read or diagnostic outputs passed across 24 generated repository instances and seven arms. The primary flywheel/direct-specialist total CPU ratio was 1.0574356495, with a 95% bootstrap interval of [1.0245655557, 1.0899163789]. The direct specialist remains the performance incumbent. These 24 instances share one public source ecosystem and one host; they are not 24 natural repositories.

The practical development repair remains useful: median CPU fell from 72.202 to 11.562 ms for Mission A and from 1.510538 to 0.172914 seconds for fresh Mission B, with exact outputs in all 30 development runs. The selected parent was actually called 96 times in protected diagnostic executions. One authored child template was bound to 24 scoped cases. Full research payback, profit, autonomous language-model-agent superiority and acceleration remain unproved; model, human, integration and maintenance costs are incomplete.

`downloads/` contains byte-exact copies of the final analysis, prospective freeze, frozen protocol and development summary. These are also embedded inside `Foundry_Lab.html`, so the research download links work without a server or adjacent files. `research.json` records the exact source hashes and unrounded primary values. A downloaded freeze records the historical pre-confirmation boundary; its `confirmation_generated: false` field describes that boundary, not the present completion state. The complete paper and reproduction package contains the remaining raw observations and source.

## Bring your own permitted files

Choose baseline and candidate UTF-8 text files and affirm that they are public or licensed nonpersonal material. Matching filenames identify the same file. The page compares hashes and reports changed, missing and unexpected files. Duplicate names, invalid UTF-8, unsupported modes/paths and inputs over the declared bounds are refused. Text is read, never executed. Limits are 128 files and 1 MB of text per set, subject to the existing workbench's complete serialized-input bound.

## Stop, recover and roll back

Pause prevents the next checkpoint from progressing. STOP aborts the active local workbench call and preserves completed missions. An incomplete mission can be restarted explicitly; completed missions are not repeated by reopening. Browser storage is optional and can be unavailable; use **Export workspace** for portable custody. Restore checks source and pack integrity, stays inactive and does not run a mission. Imports have no trusted signature or production authority. Rollback retires the selected local instrument and preserves the journal and completed outputs.

## Reproduce the browser checks

```bash
python3 browser/build.py
node browser/tests.mjs
python3 -m http.server 8767 --bind 127.0.0.1
```

In another terminal, from the companion root:

```bash
python3 browser/qa.py --url http://127.0.0.1:8767/browser/
```

`qa.py` uses Python Playwright. Install Playwright and a supported Chromium build if needed; `--browser /absolute/path/to/chrome-headless-shell` selects an existing binary. No browser installation is needed to use `Foundry_Lab.html` itself. The helper's server is for automated QA of the module entry point only.

Initial local acceptance used Node 24.22.1 and Chromium 156.0.8078.47 on Linux x64. It is not full upstream platform qualification. Fifteen direct Node checks passed; actual Chromium passed 29 checks across the module and standalone entries, including STOP, pause/resume, inactive reopening, export/restore, rollback, tampered/wrong-source refusal, selected files, invalid UTF-8, a 390-pixel viewport and keyboard navigation. Those initial receipts remain in `evidence/`. The final recorded-result presentation and offline downloads have a separate final Chromium receipt, `evidence/final-browser-qa.json`, bound to the final standalone HTML. Run it with `python3 browser/final_qa.py --browser /absolute/path/to/chrome-headless-shell`. Internal visual-QA screenshots are not research deliverables.

The standalone bundler emits readable lexical module wrappers. Its executable bytes differ from the original ES modules as an explicit packaging transform; original modules are embedded byte-exact for source inspection, and `standalone-build.json` records both the source closure and final HTML hash.
