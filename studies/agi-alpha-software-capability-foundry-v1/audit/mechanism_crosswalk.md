## Recommended scientific framing

The defensible contribution is an **executed test of whether an accepted engineering tool reduces the complete work required to produce and qualify a distinct later improvement**. The public implementation and measured causal comparisons should carry this claim. The terminology is a crosswalk to source mechanisms, not a substitute for the experiment.

Keep three endpoints separate: (1) useful patch, (2) useful retained asset on changed work, (3) more effective improvement process on fresh campaigns. Mission C can establish a distinct constructed capability without establishing a generally better constructor. Repeated service reuse and cumulative output are not acceleration.

A conventional builder receiving an independently equivalent asset is an essential comparison: if it ties the proposal, the result supports useful transferable content, not a causal benefit of ancestry labels. Removing the parent must still allow legitimate reconstruction, history and other tooling; charge those reconstructions fully.

## Software-specific cautions drawn from the mechanisms

1. If the chosen bottleneck is hashing or artifact verification, a digest cache keyed only by pathname, mtime or file size can pass stale or adversarial artifacts. The full-check oracle and mutation/race assumptions must remain explicit. A faster implementation does not get to weaken the accepted release-integrity contract.
2. Deduplicating multiple references to the exact same immutable input within one call is materially narrower than reusing results after filesystem changes. Benchmark and claim them separately.
3. If a retained profiler creates a new repair/verification instrument, trace the served instrument's actual imports/calls or data use of the parent, rather than counting parent activity somewhere in search.
4. CPU time, wall time, bytes read and repeated calls are separate measurements. A saved CPU interval is only an opportunity for a follow-up task until that follow-up is actually executed and charged.
5. A `STOP`, checkpoint or rollback button is not recovery evidence until interruption and stale-state cases have been executed.
