# S3 prospective computational confirmation

The four-mission portfolio was constructed **after** the opportunity dossier and selection, and **before** any participant saw it. The useful service is a source-bound model-reuse qualification packet. It does not discover a new H4 mechanism or demonstrate a physical experiment.

The scientific source facts are actual public artifacts. The requested new purposes, alternative clock conversions and calibration interval are researcher-constructed. In particular, the calibrated interval is an **assumption**, not new experimental evidence. The four missions are one campaign over two source families; request variants and numerical assertions do not create extra independent opportunities.

## Common participant materials

`public_case/` contains the complete brief, four requests, exact public source files, source/license notices and a public interface smoke test. The H4 source was already used to develop the candidate instrument. The Boehm source is a separate public model family with finite-time data. The instrument builder was told only the general finite-time applicability requirement and public interface, not the new source files or numeric request values before freezing. Public availability means this is not a contamination-proof benchmark. Participants receive the materials in fresh agent contexts and have no prior local artifact or hidden-score access under the protocol.

All U/E/E+ arms get identical scientific inputs, requirements, available packages and outer resources. U receives a complete, reasonable task brief and tool access. E additionally receives the already established expert workflow. E+ receives the new frozen generic instrument. No algorithm is required to be novel; direct conventional algebra is allowed. Protected tests add changed requests without reducing requirements.

The existing `protocol/trial_runner.py` is reused unchanged. It records successful reads/writes/runs, output bytes, wall time and subprocess timing. It does not provide OS isolation, complete model/tool telemetry, token billing or a verified API model snapshot. Time and operation limits are outer budgets, not equal hidden-compute measurements. Actual monetary costs remain unknown.

## Independent conventional construction

`../conventional/direct_method.py` is an independently written, competent conventional solution using explicit source inspection, linear solves, matrix exponentials and eigenvalues. It does not import the candidate instrument. It is a **researcher-authored construction**, not a free pre-existing service or a sampled human expert. Its construction cost is unknown. This control can tie the instrument; it prevents attributing established algebra to a new algorithm.

The private acceptance oracle independently reconstructs H4 reaction rates from pinned source identifiers, solves the stationary nullspace by SVD, and computes transient probabilities by Poisson uniformization. It does not import the retained instrument or the conventional implementation. The model's fixed normalization is respected. A necessary dimension bound does not decide the selected model's full identifiability. Changed requests must receive new fingerprints and no inherited authority. Every receipt retains its five-core-file model fingerprint and additionally binds all supplied files in the selected source directory through a complete evidence mapping and fingerprint. This includes the model-space declaration and reference-simulation table. The pre-exposure identity correction and preceding freeze are preserved in `history/evidence_identity_correction/`.

The private oracle and conventional implementation are separate internal implementations, not external scientific replication. The mathematical premises and scope are explicit. A reviewer must inspect explanatory prose as well as automated numerical and provenance checks.

## Run commands

From the study root:

```bash
python opportunity/protocol/build_public_case.py
python opportunity/private/validate_protocol.py
python opportunity/private/evaluate.py opportunity/conventional/direct_method.py --out opportunity/conventional/acceptance.json
python opportunity/conventional/direct_method.py --sources opportunity/protocol/public_case/sources --requests opportunity/protocol/public_case/requests.json --out opportunity/conventional/packet.json
```

After each participant freezes:

```bash
python opportunity/private/evaluate.py /absolute/path/to/frozen_submission/qualification/submission.py --out /absolute/path/to/arm_acceptance.json
```

Do not expose acceptance feedback until all three arms are frozen. Preserve every failed run, correction and final output. A script that rejects all missions cannot pass; neither can blanket approval or importing an H4 equilibrium witness into the finite-time Boehm mission.

## Success and non-success

An accepted packet is a computational delivery result under the specified source assumptions. U-to-E and E-to-E+ acceptance differences must be reported separately. Tool efficiency or wall-time observations are descriptive unless independently replicated. Unknown actual cost prevents an observed positive-margin commercial crossing. Any price, human-hours reference, coalition or financing result belongs to separately labeled modeling.

No grade in this protocol proves general identifiability analysis, calibrated biology, superior autonomous discovery, live ENS authorization, market demand or commercial compounding. The constructive result is a bounded reusable instrument and a test of whether its recipient benefits on the stated mission family.
