# Source-bound scientific model reuse qualification

**Capability:** `scientific-model-reuse`, version **1.0.0**. Research instrument; no production admission or execution authority is conveyed.

## Useful purpose and transformation

A reused model may support a stationary calculation while lacking evidence for a requested physical-time prediction. This instrument separates those requests, constructs a checkable common-clock counterexample where its premises hold, and updates a conditional prediction when a source-bound calibration assumption is supplied. It preserves the original fitted model and its valid conditional uses. It does not diagnose the original publication as wrong.

The restriction is missing evidence for the new interpretation, rather than insufficient numerical optimization. The constructed asset is an executable qualification procedure: parse actual sources, check applicability, calculate a useful prediction or witness, bind it to the new mission, and report what remains unsupported. Generic conservation, linear algebra, common-rate scaling and matrix exponentiation are established mathematics. This asset is researcher-authored operating expertise, not a new theorem, autonomous scientific discovery, changed model weights or validated biology.

## Executable scope and prerequisites

Python 3.12.14, NumPy 2.3.2 and SciPy 1.17.0 were used in development. Standard-library `Fraction` checks exact column conservation of decimal-valued rates before floating calculations. No executable strings or symbolic `eval` are used. The bundled module requires local readable PEtab-style files: `model.xml`, `parameters.tsv`, `measurements.tsv`, `observables.tsv`, `conditions.tsv`. An optional `model_space.tsv` alongside the PEtab files or `../model_space.tsv` immediately above them contributes candidate-space evidence and the source fingerprint. A directory named `petab` immediately beneath the supplied directory is also accepted. Standard PEtab YAML path resolution is not implemented.

Inventory is available more broadly than executable dynamics. Dynamics are deliberately limited to a closed, irreducible, first-order, one-to-one conversion network, one constant unit-volume compartment, normalized initial total one, constant parameters, irreversible reactions, and one condition without overrides. Supported MathML uses identifiers, numbers and multiplication. Events, rules, assignments, functions, nonunit stoichiometry, boundary species, nonlinear kinetics and other unsupported constructs are refused. Equilibrium clock witnesses and dimension checks additionally require all measurement times to be infinite and direct species-abundance observation formulas. A source outside this scope requires another qualified solver; it is not thereby a scientifically invalid model.

No general SBML/PEtab compliance, posterior inference, full structural identifiability, experimental validation or model-fitting service is supplied. The instrument does not infer physical-clock calibration merely from a time-unit declaration. Very small or poorly separated eigenvalues can exceed its numerical scope; the spectral routine uses a fixed `1e-9` zero threshold and must be requalified before materially different rate scales are served. Numerical interval outputs are not outward-rounded certified interval arithmetic.

## APIs and information bindings

`inventory(path)` returns source hashes, counts, times, estimated/fixed parameters and declared units. `build_generator(path, param_overrides=None)` exposes `species`, `matrix`, `initial`, and kinetic parameter names, using `dx/dt = Qx`. `stationary(...)` calculates a normalized conditional stationary vector. `clock_witness(path, scales=(1,2), time=1, param_overrides=None)` independently recomputes the two scaled stationary solutions and finite trajectories. `dimension_bound(path, kinetic_parameters=None)` returns a necessary mean-coordinate bound. `qualify(request, path)` combines these methods with a fresh source/request receipt and an empty authority list. See README for request schemas.

Every qualification reloads current source bytes, validates the current request and returns no inherited authorization. A source hash is provenance, not an authenticity signature. A prior success cannot authorize another mission. Calibration must name this source fingerprint, the current scope, an evidence identifier, physical unit and positive conversion interval. Parameter overrides require an additional hash binding. `assumed` and caller-labeled `observed` evidence remain distinct; neither label is independently verified by this instrument.

The internal fingerprint is SHA-256 of canonical JSON mapping every ingested source filename to its byte hash. If model-space evidence is supplied, this has **six** entries. An external contract may require a **five-file** fingerprint; compute that contract binding separately rather than confusing the two. This version uses UTF-8 JSON with sorted keys and compact separators, `ensure_ascii=False`, `allow_nan=False`. ASCII filename/hash maps match ordinary `json.dumps(..., sort_keys=True, separators=(",", ":"))`.

If no model-space file is supplied, `candidate_estimated_kinetic_parameters` is null and `candidate_space_evidence` is `not_supplied`. This does not prevent applying a declared prospective parameter count. The caller must justify that count from its actual model-space definition. Counting source parameter symbols alone does not establish which parameters are free in a particular study.

## Development provenance and evidence

Development used the published H4 PEtab model in `PEtab-dev/petab_select`, commit `7b1a1528cee614e72f17eb82338472e7ba91d8de`, test case `0009`. Source authors supplied the model, parameter values and measurements. Its fixed `da_b=1` is a legitimate normalization. No claim of independent physical-rate inference is made. The source's BSD-3-Clause notice is retained with that separate source checkout; no source dataset or evaluation answers are embedded in this capsule. The new code is Apache-2.0 under the repository's licensing context.

Eighteen development tests compare the parsed generator with a separately written motif-rule construction, compare stationary and transient values with independent ODE integration, preserve the selected fit, and exercise finite-time refusal, calibration identity, changed parameters, observation-map scope and fresh-mission authority. Those tests were written by this instrument's developer and are development evidence, not blinded independent confirmation. The initial candidate count omitted the basal estimated rate; that error and subsequent scope corrections are preserved in the development history. Source snapshots, test logs and development outputs remain outside the transferable capsule.

All construction, debugging and development testing were **unpaid research**. Actual model tokens and provider charges are unavailable and recorded as unknown. Runtime observations cover local executable calculations, not model inference, human review or complete delivery costs. No sales, collections, profitable admission or network-wide benefit are established by building this instrument. Fresh recipient confirmation and complete incremental accounting must decide whether retention is worthwhile.
