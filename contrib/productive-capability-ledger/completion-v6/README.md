# Bounded source recovery and offering costs

This is a focused continuation of the existing integration, based on owner
commit `78da6b69e168b23d3c16f406f63270cbf0e53386`. It extends
[the existing source adapter](../transport-v1/README.md) and shared
StrategyExecutor. It replaces no runtime, scheduler, source specialist, cost
calculator, publication owner or accepted evidence. Earlier completion-v1–v5
records remain immutable. Operational adoption remains **NOT APPROVED** and
approved-operator execution remains **NOT RUN**.

## Useful result and acceptance

For one explicitly registered public nonpersonal Git inventory, receive complete
CSV inventories, exact differences, an action list, a portable workspace,
readable report and independent acceptance. The fixed specialist reads ordinary
local Git objects; it never fetches repositories, runs inspected code, repairs
source files or collects customer credentials. All Git, path, row, source,
time, attempt and output bounds of the existing adapter remain enforced.
Unsupported, changed, missing, corrupted, expired, stopped, cancelled or exhausted
work produces a retained refusal/unknown record, never an accepted job.

[The delivered example](source-deliverable/report.md),
[differences](source-deliverable/differences.csv),
[actions](source-deliverable/action-plan.csv) and
[portable workspace](source-deliverable/workspace.json) are actual worker outputs.
The [independent acceptance](source-deliverable/independent-acceptance.json)
reconstructs all CSV values, references and action mappings against committed
Git bytes. It accepted five public paths and three differences with 348 checks.
This is **one internal qualification mission**, interrupted then recovered,
using a previously published five-path input. It is not fresh held-out diversity,
a paying customer, thousands of jobs, semantic code approval or demand evidence.

## What changed

- The existing inert registry optionally declares `maxAttempts: 2` (1–4 allowed).
  Omission keeps the old one-attempt behavior and disables recovery.
- The existing journal reserves the finite lifetime cap and durably charges one
  conservative service unit **before** every recoverable attempt starts. Startup
  makes one finite recovery pass; explicit Pause→Ready can make another. It
  preserves the exact plan, original approval, lease ID, start, expiry and source
  binding. No authorization or budget is renewed.
- The original specialist restores verified checkpoints and rechecks completed
  artifacts. An interprocess journal lock prevents competing executors. Completed
  response replay returns the same outcome without work or another charge.
- Per-mission CANCEL is durable and distinct from global permanent STOP. Uncertain
  work retains its full reservation; interrupted work is never refunded as free.
  Planning recovery remains disabled in the default installed profile.
- Actual source delivery now carries the existing `alpha-automated-costs/v1`
  contract, stage observations, attempt count and explicit unknown full costs.
  No new financial calculator or token operation was added.
- Wheel builds reject stale/unlisted payloads. A reproduced reused-directory
  failure had carried two retired prototype files into an otherwise valid wheel;
  clean builds and the new regression enforce the exact package manifest.

The [recovery receipt](unattended-recovery.json) records actual SIGKILL of the
owned Node process after durable preparation, followed by ASGI-startup recovery
without another approval/run call. The same checkpoint bytes and original lease
survive; two attempts are charged. The 53-case source campaign covers six adverse
recovery guards, cancellation, duplicate/lost acknowledgements, actual competing
processes and lock-link refusal. The stale-payload regression is included in that final campaign. The existing 85 worker/transport cases also pass. These are
component/isolated-runtime tests. Final hosted browser/source/Security/release
qualification must be bound to the final published commit.

## Opération en français

Le résultat utile est un dossier de contrôle de sources publiques : inventaires,
écarts, actions, rapport et espace de travail exportable. L’acceptation indépendante
reconstruit les données ; une erreur, un refus ou un résultat partiel ne compte
jamais comme mission réussie. Les cinq fichiers de l’exemple sont déjà publics.

La reprise reste désactivée par défaut. Le responsable peut proposer un registre
candidat avec `maxAttempts: 2`, puis demander son adoption selon la procédure
existante. Le système conserve l’autorisation initiale et impute chaque tentative
avant exécution. Il ne renouvelle ni durée, ni budget, ni permission. **Annuler**
concerne une mission ; **ARRÊT permanent** concerne l’enveloppe entière. Le journal
et les fichiers conservés permettent d’inspecter une interruption ou un refus.

Les montants du tableau sont des hypothèses simulées. Le coût monétaire réel
complet, le prix client, le temps du client, les recettes et le surplus disponible
restent inconnus. Les trois méthodes construites restent en HOLD ; aucune
accélération autonome ou promotion rentable n’est établie. L’exécution isolée
n’accorde aucune autorisation opérationnelle. Voir la
[procédure d’acceptation du responsable](OPERATOR_ACCEPTANCE.md).
