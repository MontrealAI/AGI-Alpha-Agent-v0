# AGI ALPHA — review a dependency update with evidence

This offering gives the maintainer of the native AGI ALPHA agent a bounded,
actionable dependency-refresh packet. It identifies the exact profiles examined,
checks the writer's original consumer requirements and evidence, and delivers an
English/French report, a reviewable component-lock patch and the remaining action.
The source record, original evidence, canonical costs and checksums travel with it.

The main example is the actual `RequestBoundary` / strict mission-input work from
[writer PR #4932](https://github.com/MontrealAI/AGI-Alpha-Agent-v0/pull/4932), source
`05658097540e5b771aeae71244ab74734e10355d`. All 61 declared requirements passed in
both recorded native component profiles. The original FastAPI import bridge and
actual 15-second timeout are retained. The useful decision is **keep the current
native application lock and advance this component evidence to full application
qualification**. This does not authorize applying a dependency update or releasing
the complete application. Customer acceptance and paid demand remain unobserved.

## Use the complete packet now

From this repository, with Python 3.12 and the existing Node/Git tooling:

```sh
python -m contrib.upgrade_decision.export_packet \
  --output /tmp/agi-alpha-native-upgrade-review-001.zip
```

Use a new destination for each export. Extract the ZIP and open `report.html`;
switch between English and French. Read `report.en.md` / `report.fr.md`, examine
`research/proposed-component-lock.patch`, and carry the listed remaining work
into the application's existing qualification process. Nothing applies the patch.

`research/` preserves all 28 files of the writer's corrected first delivery,
including its manifest, reporting-correction receipt, exact sources, locks,
observations, execution receipts and original verifier. `source-pack.json` binds
the complete input. `decision-record.json` records this new verification and
source-linked decision. `checksums.json` covers every payload member.

This one-shot export only checks inert recorded evidence and writes a file. It
creates no journal, credential, service, scheduler or operator authority. It is
separate from the connected runtime route below. Re-exporting the same evidence
is a repeat evaluation, not a new useful customer job.

The optional `--case starlette-httpx-historical` is an exposed historical call
contract and recorded integration failure. Its old pins are not current production
recommendations. It remains development evidence, not fresh confirmation or a new
repair discovery. Declared call-target mappings remain explicitly conditional.

## Connected workflow through the existing runtime

`UpgradeDecisionWorker` implements the existing fixed-worker interface. It reuses
#4915's process supervisor, StrategyExecutor, signed Journal, prepare/approve/run,
idempotency, exact source/policy binding, cancellation, permanent STOP and bounded
recovery. It adds no endpoint: the same three static routes and existing API serve
the offering view. The browser sends only a registered case ID and exact pack
digest, never a host path, command, arbitrary source URL or permission grant.

An eligible existing operator supplies the already reviewed journal, interpreters,
catalog and separately adopted `ExecutorPolicy` to `worker.create_app`. The factory
requires all component/input/source hashes, pure service work, no native or
construction allowance, and the unchanged original policy binding. It refuses a
mismatched interface catalog or policy. It does not construct or install a policy,
create a home/token, migrate an existing journal or renew a budget.

The user chooses a public change, connects the existing executor, reviews and
approves its exact finite plan, runs it, and downloads the hash-checked ZIP and
signed history. Browser closure does not create another approval or attempt.
Read-only status refresh is limited to 120 polls while running; manual refresh
remains available. A disconnected session cannot render a stale response from a
previous connection.

**Operational adoption: NOT APPROVED. Approved operator: NOT RUN.** The exact
approved installation/session is unavailable in this continuation. Disposable
engineering fixtures qualify only their recorded local scope. Source review,
required hosted CI/Security, final integration, installed-profile qualification,
release and served-site acceptance remain the existing owners' separate gates.
The existing planning wheel/profile and all held Harness/Fleet sources are intact.

## Evidence and bounded review

The writer owns the consumer contract, research comparison and economic
interpretation. This component imports the corrected original packet without
editing it. It checks every manifest/evidence relationship and reruns the fixed
inert-observation verifier. The installed verifier differs only in formatting and
top-level standard-library import order; a normalized AST comparison checks it
against the unchanged original bytes in the packet. This is another invocation of
the same verifier, not an independent research replication or hostile-recorder
attestation. No inspected consumer code is executed by the product worker.

The importer requires all 28 original packet paths and reconciles every original
assembly/correction relationship, lock version and wheel hash, installed profile,
recorded execution input/output identity, and the exact proposed lock patch.
Self-consistent subsets and a rewritten envelope cannot replace those checks.

The call-contract path constructs claims, source witnesses and uncertainties
together. A bounded critic checks missing claims and unproved dispatch. A separate
Python `inspect.Signature.bind` computation checks alleged binder defects; only
substantiated defects can cause recomputation. A critic may return no issue.
The implementation does not claim organizational or model independence.
Constructor calls and descriptor receiver dispatch without a supported proof
remain unresolved. Two binders sharing a guessed receiver are insufficient.

Missing/corrupt cases, changed sources/locks/profiles, unsupported declarations,
unlisted requests and expanded permissions refuse or retain explicit unresolved
scope. A verified proposed-profile mismatch with a preserved baseline becomes a useful
hold decision; it cannot become preservation. Missing required evidence remains
incomplete. Synthetic controls qualify that handling without creating a real
regression, customer job or confirmation outcome. See
[CAPABILITY.json](CAPABILITY.json) for inputs, dependencies, rights, invalidation,
fallback, upkeep and retirement. The stronger conventional method remains a valid
fallback. Economic promotion is not automatic.
