# Progressive experience diagnostic

This source-only experiment tests the unchanged numerical mechanisms from PR
#5024. It adds 0/4/8/12 verified training prefixes, a same-history reset, a
first-four frozen baseline, ordinary result caching, matrix caching, native HiGHS
warm starts and all six original SciPy/HiGHS configurations. Existing production
defaults, original negative evidence and sealed trials stay unchanged.

The operator problem is safe fixed-order energy/time replanning. The 64 generated
evaluation cases are an engineering cohort, not an admitted loss-making business
cohort. Half use charging-stop routes withheld from every training prefix. They
share one original public instance and the same coefficient structure; this is
not independent-source or cross-city generalization. The existing matrix-shift
regime also changes charge coefficients.

All policies, verifiers, twelve training cases, four retained memories and setup
costs freeze before the evaluation seed exists. No evaluation output updates a
candidate. Each arm receives the same applicable historical solutions. Reset
rebuilds and discards compiled experience for each target; it is a causal control,
not a claim about the best conventional service. Every original competent control
also remains. One timing is taken per arm, with randomized order. No panel is
enlarged to rescue an outcome. Cases exposed during development remain development.

The separate verifier never imports the candidate. Its existing Linux kernel
filter denies writes, new sockets and exec; write/socket probes must actually
refuse. It independently reconstructs certificates and optimality bounds, checks
training lineage and inverse matrices, and reconciles all 768 planned outputs
and resource costs. Shared author, host and libraries mean procedural separation,
not external certification or hostile-code isolation.

Advancement requires zero quality loss and at least 10% lower observed lifecycle
CPU than every declared control at stages 8 and 12, in both families and overall.
Failure retires promotion of this mechanism for this cohort. Passing would permit
only further engineering work: complete monetary costs, operator cohort economics,
demand, frontier comparisons and earned-funded successors remain unresolved.
No scientific confirmation allowance is allocated or reset.

## Run from source

Use the repository's supported Python 3.11-3.13 development environment, the
`compounding-discovery` extra with NumPy/SciPy 1.17, and Linux `libseccomp.so.2`.
No model, Docker daemon, server, account grant, wallet or paid call is required.
Source qualification is separate from wheel and release qualification.

```sh
python -m pytest -o addopts='' contrib/retained_experience/test_progressive.py -q
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m contrib.retained_experience.progressive /tmp/NEW-progressive-trial
```

Expected output is a decision, 64 unique cases, 768 checked outputs and a seal
SHA256. A negative decision is a successful execution, not a benefit claim.
Existing output paths refuse. Keep failed originals. Check without changing them:

```sh
python -B -m contrib.retained_experience.progressive_check /tmp/NEW-progressive-trial --freeze-sha256 FREEZE_JSON_SHA256
```

Preserve the printed seal independently. Verify every filename/hash in `seal.json`
against that trusted seal before interpreting saved results. Rechecking original
cases is a replay of exposed work, not new confirmation. Each trial also stores
the frozen source snapshot. Private journal credentials live in the separate
`NEW-progressive-trial-private-journal` directory; never publish that directory.
For cleanup, archive the trial and its private journal first; no service or
production setting needs rollback.

## Accounting and limits

Reported lifecycle CPU includes cumulative history acquisition, asset construction,
preparation, current-stage target compilation/solving, output serialization and
separate verification. Whole-stage setup is charged fully to each family, never
diluted across extra tasks. The full unallocated verification remainder is charged
to each history-using comparison, conservatively favoring existing fixed methods.
Its measured amount does not establish whether it scales as fixed or recurring.
Mutually exclusive arm costs are not one business's deployment bill.

CPU nanoseconds and retained representation bytes are multiplied by the inherited
illustrative SIM rates USD0.10/CPU-hour and USD0.03/decimal-GB-month. These are
proxies, not calibrated provider invoices or complete memory/hosting measurements.
Engineering labor, maintenance, operator attention and full monetary costs stay
unknown. No human labor savings are invented.

The existing signed Journal records the opportunity, construction and result.
The existing CostLedger reports an incomplete financial ledger. Nine typed cost
inputs remain unsigned/unadmitted because no accounting authority is provisioned.
No grants, payments or ledger authority are created, and an empty ledger never
means zero complete cost. A free authorized frontier execution interface, operator
cost/cohort evidence and independent demand evidence are still required for the
corresponding claims. This engineering run is not a calibrated commercial simulation.
