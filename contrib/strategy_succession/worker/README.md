This is a separate engineering adapter over a byte-identical subset of Strategy Succession scientific source `7e5a1dd2dcf7eb00ec055f1858d5dd722cc950f15f33314bb94c456c753845a7`. It does not alter that frozen study, inspect confirmation data, publish software or grant authority. The original Strategy owner retains that work.

`fixed_worker.py` supplies `FixedWorker.execute(method, payload, limits, checkpoint)`. An operator configures the absolute Node/Python executables and this source directory. Browser input cannot choose an executable, script, provider, environment or filesystem path. The containing transport verifies its independently approved combined source hash and signed Journal before calling the worker. The worker separately checks every `SOURCE_FILES.json` body before execution; the manifest hash is not a signature or an external trust root.

Fixed methods:

- `run-mission`: `{task, strategy?}`. `task` is bounded `release-plan/v1`; the optional strategy is a checked fixed-grammar AST.
- `construct`: `{stage,parent?,training,validation,remaining_missions?}`. Stages are dispatch/lookahead/repair. Construction, failed candidates, current checks, integration and retained reports debit only the improvement account.
- `run-journey`: `{initial,changes,repair,construction:{enabled}}`. One action produces an initial plan, a plan under changed requirements and a repair of that actual preceding verified plan. Jobs and dependencies are retained. Changed durations/crew/calendar/releases/deadline are explicit. Repair baseline is reconstructed from the chosen preceding receipt, with starts before `observed_at` locked. Completed/in-progress labels are inferred from that planning time and the previous schedule; physical job execution is not observed. A browser-provided baseline or lock map is refused.

Tasks explicitly declare `public_or_synthetic: "public"` or `"synthetic"`, plus `planning_only:true`. Jobs are 1..18, calendar 1..128 slots, crew 1..4 and duration 1..12. Inputs produce planning artifacts, not physical execution, financial actions or general desktop work.

Trusted limits are `service_work`, `improvement_work` (each at most 5,000,000), `native_calls` (at most six), `native_solve_seconds` (at most 60), `wall_seconds`, `allow_native` and the transport's exact `source_hash`. Native is off unless the operator approves it. The approved development journey used six calls, a 20-second total solve cap and 60-second process wall cap. Each native solve allocates two seconds and has a bounded outer response timeout. The cumulative allocation prevents retry/timeout uncertainty from silently obtaining extra solver allowance. The `native_solve_seconds` budget counter charges the full two-second solve allowance before every attempt, including failed/unknown attempts. Actual observed solver time, import/startup, checker time, process wall and CPU telemetry remain separate; no native work is converted into JavaScript units.
