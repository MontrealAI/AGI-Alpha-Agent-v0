# Find your Alpha: local discovery planning

Additive future-version entry at `/successor/discover/`, over the continuing
mission workspace. This is a deterministic evidence-organizing and comparison
aid, **not autonomous research or a validated scientific discovery engine**.

## What it actually does

- Captures mission, incumbent, best credible alternative, candidate, why now,
  rights, research/expertise/experiment/lesson references and hard constraints.
- Links supplied evidence to each option and the claimed change; forms three
  inspectable hypotheses. No reference is fetched or verified.
- Uses explicit common integer-scaled units and minimum gains to compare the
  candidate with **both** alternatives. Benefit, total cost, proof effort,
  residual risk and human burden are mandatory; there is no invented conversion
  between them. Units, conditions and uncertainty still need human review.
- Prioritizes unresolved hard constraints, then missing/illustrative measurements,
  change evidence and option evidence. A reported failure or burden regression
  preserves the incumbent. Even a fully passing supplied case only nominates
  independent review, never established advantage or deployment.
- Exports exact-input/source-bound opportunity and unfunded Gym/job proposals.
  The Gym develops capability before trust; it trains and does not certify.
  Failures/lessons remain in experimental history. No simulation ran and future
  simulation would guide experiments, not replace physical validation.
- Imports only validated inputs, discarding every imported result and authority.
  Input edits invalidate the displayed analysis and export. Browser page state
  is volatile; explicitly save the proposal before leaving.

The battery scenario is clearly illustrative. No chemistry recommendation,
physical procedure, external research, qualification result or safety claim is
produced. A qualified reviewer must define any safe physical test separately.

## Compatibility and limits

The existing canonical serializer, bounded parser and domain-separated digest
engine are reused. Existing executable workbench engines are linked, not
misapplied to battery research. Their five bounded families and mission
persistence remain separate. There is no executable adapter for general research.

All four repository entries in the portable proposal are **planning-only**.
This schema is not a native Jobs WorkSpec, Manager WorkSpec or Fleet grant.
USDC and AGIALPHA settlement remain distinct. No provider, network, private
upload, wallet, budget commitment, production activation or inherited review.
`connect-src 'none'` and hashed scripts/styles remain in force.

No current release version or original flowchart is modified. This branch is a
future contribution, requiring independent review and exact-head CI before merge.


The browser test supports `CHROMIUM_EXECUTABLE` for an existing installation,
`AXE_SCRIPT` for the repository's pinned axe-core and optional
`DISCOVERY_SCREENSHOT`. CI uses its installed pinned browser tooling and axe.
It covers EN/FR edits, literal markup, strict numbers, illustrative evidence,
retain-incumbent, fresh-context imports, discarded authority and mobile overflow.

### Progressive local draft

The combined candidate starts with mission, why now, and optional supplied evidence, then offers editable alternatives, constraints and comparison questions. A retained summary and direct step buttons keep earlier answers accessible. Unknown observations remain blank; no missing number is converted to zero. All five burden categories and the unchanged native validator still gate proposal creation. An incomplete draft is never a comparison result.

`alpha-discovery-draft/v1` stores raw strings, step and EN/FR language with explicit `partial-unvalidated` state and `authority: none`. It allows incomplete numeric editing without allowing analysis. Export is explicit; there is no autosave. Strict key/enum/size/scalar parsing and fatal UTF-8 apply on restore. Imported drafts never carry analysis or permissions. Input edits, language changes, step changes and newer imports protect against stale asynchronous restoration. Language, step and all-questions view changes preserve a completed analysis when its inputs remain unchanged. Semantic edits clear the result and require recomputation before proposal export. Only a fully recomputed `alpha-opportunity-brief/v1` can be submitted to the existing project continuity import; draft files are not project or execution artifacts.

The beginner UI keeps the reviewed native discovery, mission, project and evaluation contracts intact. The saved opportunity can be opened explicitly in a new local public-data project; CSV selection, project choice and all native source/review checks remain required. The unchanged evaluation route retains its separate uncommissioned contract boundary.
