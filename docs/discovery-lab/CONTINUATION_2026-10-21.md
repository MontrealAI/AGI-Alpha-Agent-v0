# Frozen capability and auditable continuation

This additive continuation belongs to flagship issue #4850 and existing implementation
PR #4851. It preserves the existing proposal workshop, synthetic lab, Out-Evolve
workspace, paper paths and mission store. It has no deployment, spending or
settlement authority.

The browser records an accepted capability freeze before a separately committed
future-task bank, saves a bounded execution reservation, invokes the actual frozen
program and retains every treatment and control. Changed-regime refusals, failed
successors, ties, cheaper alternatives and exhausted budgets remain evidence.
The competent static alternative is much cheaper overall in the supplied small
model; a finite causal-use experiment does not establish general capability or
commercial advantage.

The thirteen-section [Evidence Docket](EVIDENCE_DOCKET.md) derives from the same
mission hash chain. It retains original artifacts, raw inspection receipts,
source declarations, costs, uncertainties and pending review. Semantic receipt
identities prevent whitespace reframing from double charging an inspection.
Distinct proposals keep distinct checker costs. Imported records grant no
promotion, remote execution, payment or validation authority.

The source-bound [deployment inventory](DEPLOYMENT_COMPATIBILITY.json) preserves
all 39 recorded contracts and historical instances. Its read-only consumer
compares recorded code and direct roles at one observed block when a trusted
transport is supplied. Current live observation is NOT_RUN here; missing ABI,
ENS, operational and intermediary governance qualification remains explicit.
The old Fleet Manager instance is retained as historical, not silently repointed.

The separate [public-software adapter](REAL_TASK_ADAPTER.md) defines a bounded
numerical-module task family with construction, artifact freeze, later task
commitment and independent arithmetic checks. A qualified model/tool runtime,
isolated executor, invocation trace and independent operational acceptance are
still required. Its state remains NOT_RUN; submitted source is never evaluated
by the evidence inspector.

Publication still requires normal integration with the paper/release predecessor,
fresh compatible receiver pins, actual installed/native acceptance, configured
checks, independent findings closure, final-main qualification, versioned release
profiles, downloaded artifact verification and the actual public website checks.
This source continuation does not transfer older evidence to newer commits or
turn local browser tests into a release or operational claim.
