# Public-software operational adapter contract

The Discovery Lab has a separate path for a reusable public numerical-software artifact. The implemented family is `public-integer-affine-module/v1`: construct one UTF-8 ES module exporting `transform`, then reuse the same frozen module for multiple batches of canonical decimal integers. Required behavior is exact `output[i] = input[i] * multiplier + offset`, preserving order, length and duplicate rows. Inputs and coefficients have at most 32 decimal digits; valid outputs can have up to 64. Batches contain at most 256 rows and a future bank contains at most sixteen tasks.

**Operational pilot: NOT_RUN.** No qualified model/tool runtime or independent operator is installed by this change. This contract does not import or evaluate the supplied module, invoke a model, use Computer Use, fetch a URL, commission work, transact or certify source execution. The existing free synthetic experience remains usable. Arithmetic checking of supplied observations is a deterministic contract check, never evidence that the frozen module ran.

## Reuse the mission and interfaces

`examples/successor-capability/discovery-lab-real-task.mjs` validates the existing `successor-discovery-work-request/v1` envelope and retains its complete inert data, digest, mission/revision/source bindings and typed stage artifact commitments. Its distinct `successor-discovery-real-task/v1` proposal binds an existing campaign digest and workspace-head digest. Its stable `proposalDigest` binds mission, immutable original `originHead`, campaign, original typed-request/source identity, specification, limits and adapter/checker sources. Artifact freezes and check digests include that identity, so identical numerical checks from separate campaigns cannot collapse into one cost record. Fresh same-campaign proposals at distinct original history heads retain separate cost identities. The original head remains fixed through artifact/task/check transformations; reanchoring is refused until a separate history rule is implemented and reviewed. It is an evidence attachment to that mission, not another persistence store or an additional paid commission. Existing Manager USDC6 and Jobs AGIALPHA18 receivers still admit only their documented synthetic-local zero-cap requests; this proposal grants neither receiver a new execution mode.

The history owner must compare the retained work request's payload and ancestry with the actual campaign and append the attachment through the existing mission event chain. Docket admission supplies the expected mission, workspace head and campaign independently. `validateRealTaskRecord(record, {workspaceHead, missionId, campaignDigest, adapterSources})` returns inert validated data or rejects a mismatch. The application supplies actual installed adapter/checker source digests; an imported record cannot choose trusted code. The source registry and generated browser catalog must include these files before final-source qualification.

## Protocol and API

1. `createRealTaskRecord({workRequest, workspaceHead, campaignDigest, publicSource, specification, resourceLimits, adapterSources})` creates a source-bound `NOT_RUN` proposal. `publicSource` is a canonical HTTPS reference, supplied under an explicit public/nonpersonal data declaration. The contract does not fetch it or independently establish that the referenced content is public. Operational admission must verify its exact bytes, public status and provenance.
2. `realTaskProducerPacket(record)` exposes the construction requirement, public source reference, frozen source bindings and limits. It excludes the future task bank, checker observations and expected answers. Future expected values exist only in the independently written BigInt checker. Public arithmetic requirements are intentionally known to the producer; this is not a secret external benchmark.
3. A separately qualified producer would return the exact module bytes, frozen environment digest and observable tool trace. `freezeRealTaskArtifact(record, {moduleUtf8, environmentDigest, trace})` captures at most 128,000 UTF-8 bytes and binds specification, checker source and environment. It never imports or evaluates those bytes. A hash or producer-supplied trace does not establish safe code, competence or genuine execution.
4. `commitRealTaskBank(record, [{id, inputs}])` supplies and commits all future input specifications after artifact freeze and before any result check. The same bank cannot be replaced and task identifiers are unique. Independent temporal custody is still required to establish this ordering in an operational pilot; the record's schema alone is not an attestation.
5. A qualified installed executor would invoke that exact artifact in its isolated, source-bound environment for each bank task. It must retain invocation and output bytes, all tool interactions and interventions, interruptions and actual resource observations. `checkRealTaskOutput(record, {taskId, artifactFreezeDigest, outputs, trace, resourceUsed})` currently checks only supplied observations against independent exact arithmetic. It binds the same frozen artifact and complete bank, rejects duplicate results and retains rejected results before later successes.
6. The owning mission history appends each resulting record; its evidence docket exports the complete original proposal, artifact bytes, task bank and checks. Reload and import validate all commitments and recompute every arithmetic disposition. Import cannot promote the operational state.

Each trace item has exactly `{sequence, action, inputDigest, outputDigest, summary}`. Actions are `read-public-source`, `write-artifact`, `tool-call` or `intervention`; summaries describe observable actions and policy decisions. At most 64 items are admitted per captured trace. Do not include credentials, private data or purported hidden reasoning. Empty traces in the regression fixtures demonstrate contract validation only.

## Costs, outcomes and authority

`resourceLimits` bounds the **whole future task bank's reported observation units plus declared local checker units**, conservatively summing every vector component. Exact decimal totals use BigInt, so earlier failed observations and safe-integer overflow cannot erase costs. Each local checker charges one declared check per row and the encoded observation footprint; these are bounded accounting units, not VM instructions or heap measurements. An exceeded cumulative cap yields `inconclusive`. A correct in-cap output gets `reference-output-matched`; a mismatch gets `rejected`.

Runtime costs in imported observations remain explicitly untrusted. Model construction, source inspection, runtime installation, coordination, independent review and real execution costs are unmeasured here, so this record cannot support a pilot cost or amortization claim. The synthetic future-task campaign has separate measured/declared accounting. All records retain `operationalState: NOT_RUN`, `settlement: not-performed` and `authority: none`, including successful arithmetic checks.

Before an operational pilot, independently qualify the actual model/tool access and budget, producer/executor sandbox and cancellation controls, immutable public source bytes, separate checker environment, expected-answer custody, complete trace collection, exact source invocation and outputs, total costs, task-bank custody and mission-history/docket round trip. Runtime availability, source inspection or a contract-test callback cannot substitute for those observations. No pilot was performed by this change.

## Reproduce contract tests

```bash
node --test examples/successor-capability/discovery-lab-real-task.test.mjs
```

These tests cover mission/source/request binding, artifact freeze before future tasks, producer answer separation, multiple tasks using one frozen artifact, retained failure followed by success, cumulative checking costs and budget exhaustion, exact wide integers, duplicate/altered input, corrupted imports, getter traps and snapshot custody. Fixtures supply outputs directly; they do not execute an operational producer or artifact.
