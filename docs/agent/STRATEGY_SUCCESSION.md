# Strategy Succession — plan, adapt and repair

Prepare a release plan, change its requirements, then repair that same project while preserving its committed
planning prefix. The connected interface runs reviewed fixed methods on your explicitly configured local executor.
It retains checked results, reusable candidate methods, costs and recovery evidence in the existing Alpha Journal.

This is a bounded planning product. It does not execute physical jobs, run arbitrary repository code, operate a
desktop, fund a job or activate the held Harness/Fleet integrations. The free [flagship browser experience](../try/index.html)
remains local and requires no account, wallet, installation or API key. A static tab is not an unattended executor.

## One explicit start

1. **Start** prepares the exact input, executor, source, expiry and separate budgets. It does not begin execution.
2. Review the immutable input and approve that exact finite scope. Editing the future-input field does not change it.
3. **Approve and start work** runs planning, changed planning, construction comparisons and repair without further phase prompts.
4. **Review** the three checked results and their committed receipts. Native specialists remain available at every phase.
5. **Keep** downloads inspectable candidate methods, with executable AST, dependencies, provenance, limits and cost history.
   These records contain no inherited proof or production authority. **Improve** is available only for an admitted separate proposal.
6. **Export** downloads the signed local evidence package. Its signature establishes local attribution, not truth or authority.

**Download report** also saves readable English or French text showing the actual schedules, selected methods, receipt
hashes, caps, charged costs and unknowns. Keep the signed export for complete machine-readable evidence.

The default request caps are 500,000 declared service units, 3,000,000 improvement units, six native invocation attempts
and twenty solve-allowance seconds. Every native attempt charges its two-second allowance before starting, including
startup or import failures; actual physical wall/CPU measurements stay separate. The request expires within 120 seconds,
approval within 600 seconds, with one active request and finite installation-wide totals. There is no default recurrence daemon.

## What the comparisons mean

The default local six-job example first yields makespans 15 and 17. Reducing capacity during slots 12–14 makes the actual preceding
plan invalid at slots 12/13. Repair preserves the starts already committed at the supplied planning time and produces a
valid makespan-19 schedule. These are planning classifications; physical job execution is not observed.
The public preparer begins with a different editable seven-job synthetic project. Its results must be checked on that
actual input; the six-job outcome is not a promised result for another project.

Parent construction and repair usefulness are separate tests. Inherited, rebuilt and equivalent parents have matched
total and child allowances. Retrieval, reconstruction, failed proposals, checks, integration and retention are charged.
Inherited construction can cost less than exact reconstruction while ordinary equivalent reuse is cheaper still.

On the binding disruption, the constructed repair is valid with movement 9; the existing matching native repair achieves
movement 7. The system selects the stronger native method and retains the candidate's **LOSS / HOLD**. Earlier no-change
and tied cases remain historical evidence. These observations establish neither capability growth nor economic superiority.

Correctness does not imply economic admission. Human effort, model-assisted authorship, hardware/currency cost, Python
HTTP/journal/cryptographic overhead and whole QA/development cost remain partly unknown. Model inference calls in the
fixed executor are zero. Forecast maintenance is an assumption. Work units, CPU seconds, monetary value and revenue are
different quantities; no synthetic saving is profit.

Human time breaks even only if setup + approvals + review + intervention + recovery + remaining work is less than a
matched ordinary workflow at equal accepted quality. Those effort terms and residual human attention remain unknown.
Economic payback also requires measured value to exceed delivery + allocated improvement + checking/retries + integration +
maintenance costs in consistent monetary units; those totals remain unknown. No empirical human speedup or payback is established.

## Pause, stop and recover

**Pause** fences the next bounded checkpoint. **Stop** is permanent for that installed operating envelope. Closing a tab
does not cancel an already approved request; reconnect and select the retained mission. An approved but unstarted plan
requires fresh consent to resume. Running or uncertain work never retries automatically.

After a crash, the previous process may be gone while its journal still records a lease. The interface says it is
awaiting evidence, preserves checked partials and holds the full unknown reservation. Inspect effects and export the
record before reconciliation. An unexpired lease cannot be cleared. Reconciliation retains unknown ceilings without a
refund and does not resume work. The operator procedure in the packaged guide covers source changes, expiry and renewal.

Actual supervisor-death checks include a bounded native child and an unchanged server restart. SIGKILL cannot run Python
cleanup instantly; stdin EOF fences the next phase after any already bounded call. Descendants do not inherit proof,
grants or a serving release. Use the last accepted installation for rollback; do not move tags, rewrite old evidence or
reset a stopped journal to recover authority.
