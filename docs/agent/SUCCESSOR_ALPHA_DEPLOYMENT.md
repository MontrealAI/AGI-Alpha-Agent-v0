## What has been established

This record preserves the exact names and addresses supplied by the owner. It does not assign the
current repository commit as the deployment source. The deployment source commit, compiler inputs,
creation receipts and runtime bytecode hashes remain unknown in this record.

On October 18, read-only retrieval of the five exact explorer code pages was unavailable. Exact-address
search returned no results, and a direct HTTPS request returned HTTP 403. Consequently, this implementation
does not independently assert explorer source verification, deployed contract names, runtime bytecode,
constructor bindings, ownership, governance acceptance, role holders, pause state or funding state.
The recorded status is **independently unconfirmed**, which is a limitation of this check and not a finding
that the deployment failed.

## How the flagship uses this record

Local capability development and comparison require no wallet. The addresses are displayed as transparent
references for the optional Ascension route. The reference record does not grant contract permissions,
activate a paid work cycle or authorize signing. Preparing and exporting a local project sends no transaction.

Before enabling funded execution, bind the exact deployment to its retained source and creation evidence;
read back dependency bindings, actual owners and roles, governance acceptance, and the intended operational
state at an identified block. Validate the matching client ABI and configured token route. A source-verified
explorer page alone does not establish these runtime facts or permission to act.

USDC commissioning and `$AGIALPHA` commissioning retain their distinct budgets, interfaces, acceptance and
settlement requirements. This Ascension reference record does not update another work route automatically.

Historical deployment manifests and their qualification boundaries remain intact. Existing operator tools
continue to enforce their own qualified deployment requirements; this reference file is not an override.
