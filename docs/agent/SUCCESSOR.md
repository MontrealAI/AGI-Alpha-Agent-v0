# SUCCESSOR Ω — mission quickstart / guide de mission

[Research disclaimer](../DISCLAIMER_SNIPPET.md)

SUCCESSOR Ω extends Ascension into a persistent mission lifecycle. The first mission aggregates public synthetic
streaming events exactly, constructs bounded competing implementations, freezes one complete challenger, evaluates fresh
work and records an honest decision. A successor inherits permitted knowledge; proof and authority start empty.

## Native one-command quickstart / démarrage natif

With the minimal operator package installed and its environment activated, run:

```sh
alpha-agent --home ./successor-state successor-demo --output ./successor-evidence
```

Pour le rapport et l'aide en français :

```sh
alpha-agent --home ./etat-successor successor-demo --output ./preuves-successor --language fr
alpha-agent successor-help --language fr
```

The new evidence directory includes `REPORT.txt`, `request.json`, signed `result.json`, `portable.json`,
`checkpoint.json` and `public-key.txt`. Keep the public key and checkpoint independently; the private home contains
credentials and is not an export. Interrupted runs use the saved request and explicit `successor-run --resume`;
`successor-export` reproduces a completed result without new measurements. A local performance result leaves independent
qualification on `HOLD`. Read the [installed-command, recovery and verifier handbook](SUCCESSOR_OPERATIONS.md) before
resuming, restoring or interpreting signatures. No source checkout is required.

Le dossier de preuves contient les mêmes fichiers et un rapport français. Gardez séparément la clé publique et le point
de contrôle; ne publiez pas le dossier privé. La reprise utilise `successor-run --resume` avec la requête conservée;
l'export ne refait pas les mesures. La qualification indépendante reste `HOLD`. Le
[manuel d'exploitation et de vérification](SUCCESSOR_OPERATIONS.md) détaille les commandes et limites de confiance.

## English: first session

1. Open the workspace. No account, wallet, paid service, API key or model download is required.
2. Inspect **Current**, a competent one-pass dictionary accumulator, and **Beta**, an independently implemented sorted
   reduction. Select bounds and record underwriting. Retain, repair, rent, build, partner, reserve and stop are distinct
   choices. Rent/partner remain blocked on supplier evidence; their status is not invented.
3. Run discovery. It constructs distinct configurations from a fixed grammar: tuple/nested dictionaries, last-group
   caching and branch/builtin maximum updates. The WORLD prediction is recorded before measurement and influences the
   declared comparison. There are eight distinct configurations; a larger budget does not fabricate extra candidates.
4. Freeze the selected configuration, exact engine source digest, request, comparator identifiers and protocol. Editing
   a mission input clears dependent results and requires new underwriting.
5. Evaluate fresh workloads. Every valid output must match exactly; malformed inputs must be rejected. Correctness is a
   hard gate. Inspect all timings, attempts and limitations. A loss to Current or Beta is an ordinary valid outcome.
6. Record a local decision. The browser offers hold/retain choices and issues no production grant. An operator label is
   not an authenticated principal. Local timings do not establish independent mission superiority.
7. Preserve and run generation two. Matched treatment/control arms share starting code, workload seeds and budgets.
   Treatment receives only a configuration-order hint. Each arm constructs the same number of candidates; equal effort
   does not demonstrate compounding. Every trial is exported, including negative results.
8. Download the complete machine-readable evidence. The readable report is also visible in the workspace.

The browser executes only shipped fixed aggregation engines and validated non-general-purpose configurations. It never
executes arbitrary generated source. All browser test material is publicly inspectable: this is a local rehearsal,
not a protected or independently administered proof environment. Timing is descriptive; browser JIT, measurement order,
clock resolution and device load may dominate. Peak memory, money, human review effort and accepted realized value are
unmeasured. Correct results do not fill those gaps.

## Native file round trip

Install the supported operator package using the repository's minimal operator instructions. In the browser choose
**Download request.json**, then run:

```sh
alpha-agent successor-run request.json --output result.json
```

Import `result.json` into the same browser request. After a reload or on another device, restore the original
`request.json` first. The browser verifies:

- supported version, exact request fields and bounds;
- the original request's domain-separated SHA-256 digest;
- the complete request and native scope inside the returned evidence;
- the evidence digest and the cryptographic validity of any supplied signature.

A result's embedded signing key does not make that key trusted. Optionally provide a trusted public key obtained through
a separate channel to authenticate a local signer. A valid local signature does not establish organizational
independence, truthful measurements, a customer acceptance, an admission decision or operational authority.

The native command runs fixed pure engines. Arbitrary generated code requires the separately configured, explicitly
opted-in Docker isolation path. There is no automatic host-execution fallback. The public site has no provider
credentials, secrets or production control channel.

The transport accepts bounded JSON only: UTF-8, at most 2 MB, at most 32 nesting levels and 100,000 nodes, unique printable
ASCII object keys, Unicode scalar string values and exactly represented integers. Duplicate keys, floats, nonfinite
numbers, negative zero, unsafe integers and malformed surrogates are rejected. Request identifiers are canonical
lowercase UUIDs. Hash domains are separate for request, evidence, release and candidate records. Exact cross-language
vectors ship with the native protocol.

## Cancellation, recovery and offline use

Cancel interrupts between bounded computation units; a completed earlier stage remains inspectable. Retry the interrupted
phase or select **Start over**. No partially completed phase is admitted. Inputs are saved locally for convenience; reload
does not restore a trusted phase or production permission. Export evidence files before clearing browser data.

An online first visit installs the site's content-versioned service worker. Wait for **Offline cache ready**. Cached
visits can run the fixed browser engines without a network or optional model assets. A first-ever offline visit needs a
previously downloaded site package served on localhost. Opening ES modules directly with `file://` is unsupported.
Upgrades replace only the site's own gallery caches and preserve unrelated application caches.

The public workspace supports keyboard controls, English/French labels, reduced motion, screen-reader status updates and
narrow layouts. Advanced records remain available under the expandable inspectors. Machine keys are stable across both
languages; changing language changes the exported request and stales previous dependent evidence.

## Français : première utilisation

1. Ouvrez l'espace bilingue. Aucun compte, portefeuille, service payant, clé API ni téléchargement de modèle n'est requis.
2. Examinez **Current**, un accumulateur compétent en un passage, et **Beta**, une réduction triée indépendante. Choisissez
   les limites puis consignez l'engagement. Conserver, réparer, louer, construire, collaborer, réserver et arrêter sont des
   décisions distinctes. Louer/collaborer exige des preuves du fournisseur ou partenaire; aucun résultat n'est inventé.
3. Lancez l'exploration. Des configurations distinctes sont construites dans une grammaire fixe : tables simples ou
   imbriquées, cache du dernier groupe et deux méthodes de maximum. La prédiction WORLD est consignée avant la mesure.
   Huit configurations uniques existent; un budget supérieur ne crée pas artificiellement de nouveaux candidats.
4. Figez le candidat sélectionné, le condensat du moteur, la requête, les comparateurs et le protocole. Une modification
   des paramètres invalide les résultats dépendants et exige un nouvel engagement.
5. Évaluez des charges nouvelles. Les résultats valides doivent être exacts et les entrées malformées rejetées. La vitesse
   ne compense jamais une erreur. Perdre face à Current ou Beta est une issue valide.
6. Consignez une décision locale : attendre ou conserver une solution. L'étiquette de l'opérateur n'est pas une identité
   authentifiée; aucune permission de production n'est accordée. Les temps locaux n'établissent pas une supériorité
   indépendante.
7. Préservez les méthodes et lancez la deuxième génération. Les bras traitement/témoin utilisent le même code initial, les
   mêmes graines et budgets. Seul le traitement reçoit un ordre de configurations suggéré. Les nombres de constructions
   restent égaux : cela ne démontre pas un gain récursif. Tous les essais, y compris négatifs, sont exportés.
8. Exportez les preuves complètes et consultez le rapport lisible.

Le navigateur n'exécute que des moteurs livrés fixes et des configurations validées, jamais du code arbitraire généré.
Toutes ses données de test sont publiques : c'est une répétition locale, pas une preuve protégée ou indépendante.
Le JIT, l'ordre de mesure, la résolution de l'horloge et la charge influencent les temps. Pic mémoire, dépenses, effort de
révision humaine et valeur réalisée acceptée ne sont pas mesurés. Un résultat exact ne comble pas ces lacunes.

### Aller-retour natif

Téléchargez `request.json`, exécutez la commande ci-dessus avec le paquet opérateur installé, puis importez `result.json`.
Sur un autre appareil ou après rechargement, restaurez d'abord la requête originale. Le navigateur vérifie les versions,
limites, liens à la requête, condensats et validité cryptographique des signatures présentes. Une clé contenue dans un
résultat n'est jamais automatiquement fiable. Une clé fiable fournie séparément peut authentifier un signataire local;
cela n'établit ni indépendance, ni véracité des mesures, ni acceptation client, ni admission, ni autorité opérationnelle.

La commande native utilise des moteurs purs fixes. Le code arbitraire nécessite le chemin Docker explicitement configuré,
sans repli automatique sur l'hôte. Le site public ne contient ni identifiants de fournisseur ni contrôle de production.

Le transport accepte au plus 2 Mo de JSON UTF-8, 32 niveaux et 100 000 nœuds. Les clés ASCII imprimables sont uniques;
les valeurs textuelles sont des scalaires Unicode et les nombres des entiers exactement représentables. Clés dupliquées,
flottants, valeurs non finies, zéro négatif, entiers non sûrs et substituts Unicode invalides sont rejetés. Les UUID sont
canoniques en minuscules. Les domaines de hachage séparent requête, preuve, version et candidat; des vecteurs Python/
JavaScript sont inclus.

### Annulation, récupération et hors ligne

**Annuler** interrompt entre unités de calcul bornées. Les phases déjà terminées restent consultables; une phase partielle
n'est pas admise. Relancez-la ou choisissez **Recommencer**. Les paramètres sont conservés localement, mais un rechargement
ne rétablit ni état fiable ni permission. Exportez les preuves avant d'effacer les données du navigateur.

La première visite en ligne installe le cache versionné. Attendez **Cache hors ligne prêt**; les visites suivantes peuvent
fonctionner sans réseau ni modèle facultatif. Une première visite hors ligne exige un paquet déjà téléchargé servi sur
localhost; `file://` n'est pas pris en charge. Les mises à jour ne suppriment que les caches de galerie du site.

Clavier, lecteurs d'écran, mouvement réduit et écrans étroits sont pris en charge. Les inspecteurs donnent accès aux
manifestes. Les clés machine restent identiques dans les deux langues; changer de langue modifie la requête et rend les
preuves précédentes périmées.
