# 1.29.0 — Additive SUCCESSOR workbench and bounded Computer Use

This candidate adds five useful local mission families, a portable bilingual workbench, signed native
receipts and an optional isolated browser-action runtime. Existing functionality and deployed contracts
retain their interfaces and economic rules. No mainnet operation is authorized by this source release.

- `successor/work/`: actual repairs, benchmarks, checked examples, data reports and numerical calculations.
- `successor-work`: machine-readable planning, native execution, review, export and explicit recovery.
- Existing strict lifecycle records and the pinned AGI Jobs compiler bind the new work and draft handoff.
- `createWorkbench`: a documented extension interface and executable additional adapter example.
- `successor-computer`: screenshot/action loops, two provider interfaces, no-network Docker browser,
  exact-URL read broker, resource bounds, cancellation, signed observations and no automatic replay.
- A dedicated release acceptance job covers domain conformance, offline/accessibility journeys and actual
  container keyboard/screenshot execution. Every previous release gate remains required.

The five built-in adapters have deliberately bounded domains described in
[SUCCESSOR_WORK.md](SUCCESSOR_WORK.md). Browser Computer Use is distinct from general desktop control;
see [SUCCESSOR_COMPUTER_USE.md](SUCCESSOR_COMPUTER_USE.md). Local software tests, real model qualification,
independent evidence and live market commissioning are separate claims.

Publication remains subject to exact-head CI, independent review, the normal merge process and deployed
artifact verification. This note does not claim those gates have passed. Actual outcomes and blockers are
tracked in [the acceptance record](SUCCESSOR_IMPLEMENTATION_2026-10-13.md).

Begin with [START_HERE.md](START_HERE.md) for installation and the preserved operator workflows.
