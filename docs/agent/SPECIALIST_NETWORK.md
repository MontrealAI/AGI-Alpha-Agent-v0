# Specialist network / Réseau de spécialistes

This additive slice extends the general executor in PR #4960. It uses the same
Journal, durable high-water checkpoint, CostLedger, TransformationLibrary,
ProtectedLibrary, ENS boundary, native operator and public Flywheel. It introduces
no competing registry, publisher, wallet role, contract or settlement authority.

## Useful work and retained change

The first specialization is resilient service placement. It produces a finite
minimum-cost placement satisfying host capacities and two replicas in distinct
failure domains, or establishes infeasibility. An independent exhaustive enumerator
checks affordable instances. These are synthetic engineering deliverables, not
customer acceptance or evidence of a profitable offering.

`PlacementWorkflow` is a runnable data artifact interpreted by installed code.
v1 uses service order, static cost bounds and no aggregate-capacity pruning. A
bounded Gym campaign searches explicitly enumerated workflows and retains v2 only
when its training score improves. It does not update proprietary model weights.
The observed v2 uses largest-demand ordering, residual-capacity lower bounds and
aggregate-capacity pruning. The original artifact and every attempted trial remain.

v1 is an engineered procedure used during delivery. Its prior existence and the
scripted production model mean this fixture does not demonstrate that frontier
reasoning invented it through paid experience. The observed retained learning is
the Gym's actual selection of v2 from executable alternatives. Neither workflow
is claimed as a novel optimization algorithm.

The executable form is implemented end to end. The common capability description
also distinguishes trained components and specialist services, whose adapters are
**unsupported**. A manifest cannot activate an arbitrary script, shell command,
model loader or remote service. A callable service is not copied expertise.

## Executable environment contract

`MissionEnvironment[Task]` defines reset, observation, permitted transitions and
outcome evidence. `PlacementEnvironment` implements reproducible reset, bounded
work, stop checks, terminal failures and an independent original-objective check.
It also implements the general executor's production tool protocol.

`ToolMissionEnvironment` adapts an approved production `ExecutionEnvironment` for
code/tool or visual practice. Trusted operator callbacks reset the actual state,
observe it and independently check the mission. Actions preserve before/action/
after evidence. Unknown attempted actions never receive acceptance. The original
tool allowlist and resource constraints remain. The callbacks must implement their
own isolation, bounded operations and custody; this adapter creates none of those.
No new actual visual computer action has been qualified by this contribution.

`GymPlan` authorizes an exact original artifact, alternatives, training inputs,
source environment, work/time limits, finite funding envelope and expiry. The
campaign verifies installed-source continuity and checkpoints before every trial.
It reserves one unknown C activity before execution. Interrupted work stays
recorded; replay and automatic restart are refused. A partial campaign cannot emit
a qualified v2. The previous working version remains available.

Training cannot contain protected or transfer tasks. The candidate freezes before
fresh evaluation. Source and semantic exposure checks exclude original delivery,
training and prior evaluation inputs, including service/host permutations, renamed
domains and changed node caps. The conservative projection can exclude distinct
instances; it does not count cosmetic changes as fresh evidence.

The public recorder contains retired synthetic conformance partitions. They are
disclosed after their one campaign and are never a live private evaluation pool.
Production evaluation material, assets and keys stay in private deployment custody.
The artifact contains no checker, evaluation cases or scorer implementation.

## Accepted origin and protected peer use

`general-acceptance` requires a separately signed acceptance role, exact completed
executor record, matching actual tool observation, artifact digest, independent
finite check, complete A accounting and rights evidence. Model completion alone
cannot create an accepted origin. Placement retention binds that origin and the
runtime wallet. A different workflow requires the exact frozen Gym record and
complete separate C accounting, including its training exposure commitments.

The existing `candidate`, `plan`, `evidence`, `validate`, `admit`, catalog, manifest,
invoke, revoke and archive paths handle the placement executable through a typed
adapter. Existing source-selection fixtures keep their original runtime. Both
adapters use the same encrypted store, permission boundary and lifecycle.

Evaluation still requires separately configured executor, acceptance, evaluator,
validator and controller attestations. Matched frontier configuration, tools,
resources and current Beta commitments remain required. Admission accounts for
incremental B costs, completed additional Gym C costs and prospective upkeep;
the ledger never bills those activities again. Unsuccessful campaigns and rejected
assessments remain in their original buckets. A delivery's required learning stays
in A and is not rebilled as optional research.

Every peer discovery/invocation uses the existing fresh, wallet-signed ENS challenge
and current two-reader authority check at the resource boundary. Membership grants
eligible access, not execution authority. Expiry, replay, changed ownership,
revocation, source changes, wrong runtime, corrupt ciphertext and stale versions
refuse. Serving reserves uncertain costs before computation. Actual reuse success
and net benefit require independent acceptance and complete reconciled costs.

Access controls do not prevent an authorized recipient from retaining outputs or
exporting knowledge. No promise of impossible copying is made. Jobs validator roles,
`*.club.agi.eth`, governance, USDC economics and $AGIALPHA utility remain separate.

## Executed evidence and limits

The source-checkout recorder runs original delivery through `MissionExecutor`,
searches 12 training trials across three artifacts, freezes v2, executes 12 fresh
finite cases from changed topology and contention families, exercises protected
loading/invocation using fictional authority, and tests eight composition missions.
It also preserves an interrupted campaign and unknown liability.

The first observed campaign passed all 12 fresh finite cases; v2 used less logical
search work on six, with aggregate units 3,422 versus 10,470 for v1. These units do
not measure complete CPU, verification, latency or commercial cost. A strong
conventional procedure matches the learned workflow. Composition adds an explicit
64-unit coordination envelope and does not beat that procedure. Identical-content
private, shared and ordinary-library controls have identical algorithmic results;
no graph-specific advantage is claimed. These are sequential finite experiments,
not measured multi-agent serving capacity or extrapolated network scale.

The report separates the real technical experiment's **do not admit** decision
from a separate positive **fictional protocol admission** used to test controls.
Ephemeral signatures and local invocation are real; chain state, model receipts,
funding, category amounts and reuse forecasts in that conformance test are fictional.
They cannot mint production identity, acceptance, payment or model receipts.

There are zero actual provider calls, new computer actions and customer collections.
Complete actual research cost and equivalent human-service market pricing are
unmeasured. Profitable Beta delivery remains independently valuable; this slice
neither establishes nor refutes its commercial profitability. Net Alpha, sustained
compounding, live peer advantage and specialist ASI are not established.

## Reproduction and operator commands

From a source checkout with development dependencies:

```sh
PYTHONPATH=. python scripts/record_specialist_relay.py --output /private/new-relay.json
python -m pytest tests/runtime/test_flywheel_specialists.py -q --no-cov
```

The recorder refuses an existing output. The canonical public packet is
`scripts/templates/alpha-flywheel/specialist-evidence.json`; its runtime source
hashes bind the recorded implementation. The earlier general-execution packet
retains its historical scope and identities. Neither packet installs authority.

Only an independently provisioned protected deployment can accept signed commands:

```sh
alpha-agent --home /private/agent flywheel --deployment /private/deployment.json \
  --output /private/new-gym-result.json gym-run /private/signed-gym-plan.json
alpha-agent --home /private/agent flywheel --deployment /private/deployment.json \
  --output /private/new-acceptance.json general-acceptance /private/signed-acceptance.json
```

The existing candidate command accepts a placement manifest and workflow. The
existing protected invoke API accepts `PlacementInvocation`; it never evaluates
arbitrary capsule code. Do not treat a public report as an operational input.

Live qualification needs the previously identified approved model/account,
per-request caps and external hard budget/billing evidence; an approved sandbox or
immutable browser image; HTTPS service, storage, encryption and checkpoint custody;
two approved mainnet RPC readers with checked code pins; and two distinct wallets
controlling eligible names. It also requires genuinely fresh rights-cleared work,
competent frontier comparisons and independent acceptance. This work provisions
none of those resources. There is no parallel release dispatch.

Official interfaces were checked on 2026-10-27:
[Astra](https://developers.openai.com/api/docs/models/gpt-6-astra),
[Terra](https://developers.openai.com/api/docs/models/gpt-6.1-terra),
[computer use](https://developers.openai.com/api/docs/guides/tools-computer-use),
[pricing](https://developers.openai.com/api/docs/pricing).
Published model capabilities and tariffs do not establish account access. ChatGPT
Pro is not an API model or an API budget. No default model or credential is replaced.

Rollback uses the existing stopped-runtime and previously qualified release path.
Retain the current journal, high-water checkpoint, outstanding liabilities,
revocations and original evidence. Reverting a binary cannot revive spent permits,
old ownership or retired admission. Requalification follows material source changes.
