# Choosing the next useful experiment

This is a researcher-led opportunity comparison, prepared before the bounded local
experiment. It does not establish autonomous discovery, a generally unsolved field,
customer demand or Operational Alpha. The flagship starts with a blank useful need;
the candidate below is optional and remains an assessed research hypothesis.

| Candidate | Beneficiary and useful outcome | Existing approaches | Specific question left open here |
|---|---|---|---|
| Evaluation evidence across scorer revisions | Evaluation teams need meaningful historical comparisons | Pinned commits/configuration, fresh run IDs, full rescoring, differential tests | Can a witness separate an intended evaluator correction from an accidental change with less complete review effort? |
| Scientific pipeline migration | Scientific teams need preserved data meaning after dependency changes | Official pandas migration guides, pinned environments, warning modes, pytest and property tests | Can a recipient-specific invariant package cost less than direct migration testing at equal accepted quality? |
| Workflow inheritance after tool changes | Agent integrators need a still-useful workflow under current semantics, effects and permission | MCP conformance, full consumer contract tests, pinned identities, Pact and property tests | Can stable generic qualification be reused while every fresh purpose/output/effect and authority check remains correct? |

The first two candidates have strong conventional outside options. Evaluation work
also overlaps the active publication/evidence owners; a cache-key repair alone is
not the intended contribution. Pipeline migration has extensive established support.

The selected **next experiment** is workflow inheritance after tool changes. It
directly tests the enterprise's fresh-recipient boundary, can execute locally without
private data or external actions, and has a cheap decisive comparison against full
fresh consumer testing. These are engineering selection reasons, not estimates of
market size or proof that the technique is novel.

## Evidence and the remaining gap

The official [MCP tools specification](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)
describes tool schemas, untrusted annotations and tools that can vary with the
authorization on a request. Its [authorization specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)
requires current request/resource authorization when that HTTP authorization
mechanism is supported. The [official conformance implementation](https://github.com/modelcontextprotocol/conformance/blob/main/README.md)
already provides revision-aware protocol testing. This project does not claim to
invent schema checking, protocol conformance, API compatibility or authorization.

Our inference is narrower: structurally valid tool results and an old successful
workflow do not alone establish a new consumer mission's meaning or desired side
effects. A retained instrument might help assemble the right fresh checks; whether
it reduces complete work compared with ordinary contract tests is unmeasured until
the experiment executes. Finite checks cannot guarantee arbitrary future behavior.

For the alternatives, independent source context is available in the
[SWE-bench README](https://github.com/swe-bench/SWE-bench/blob/main/README.md),
[EleutherAI task guide](https://github.com/EleutherAI/lm-evaluation-harness/blob/main/docs/task_guide.md),
[pandas 3 release notes](https://pandas.pydata.org/docs/whatsnew/v3.0.0.html),
[Pact contract mechanism](https://docs.pact.io/getting_started/how_pact_works) and
[Hypothesis equivalent-function testing](https://hypothesis.readthedocs.io/en/latest/ghostwriter.html).
These sources describe actual existing tools and changes. They do not supply buyers
for this enterprise or demonstrate that our proposed combination beats those tools.

## Construction, decisive test and falsifier

Construct a frozen executable workflow/probe instrument on the existing reusable
mission-environment contract. Execute actual local tool actions and inspect changed
artifact bytes. Compare full fresh qualification, identity-bound stable-check reuse
plus fresh mission checks, and an ordinary library with identical contents. A
schema-only arm is a weak diagnostic, not the principal competitor.

Use fresh task data and adversarial changes to schema, dependency, tool version,
model identity, permission, revocation, units and meaning. Keep authorization checks
separate and require a new grant for each mission. Untrusted tool descriptions are
data, not instructions. Include same-schema changes because schema drift alone is
an insufficient test of semantic preservation. Known identity changes must refuse
reuse; hidden behavior changes still need independently checked fresh outputs.

The falsifier is an unsafe compatibility decision, inherited/expired permission,
relaxed original purpose, or no complete-work benefit over equally enabled ordinary
consumer testing at matched accepted quality. Count generic tests, fresh checks,
instrument processing, authority checks, execution and artifact verification
separately. Logical counts are not monetary costs or human minutes. A conventional
tie means no graph-specific advantage; unknown complete costs block economic Alpha.

## Commercial arrangement and next decision

A possible offering is a bounded workflow migration/requalification engineering
service: a common testing instrument plus customer-specific purpose/effect contracts.
The beneficiary would receive an inspectable compatibility report and explicit
refusals, with acceptance defined in advance. Current demand, willingness to pay,
human-service prices, rights and responsibilities require independent evidence.
There are no commitments, pooled customers or revenues in this experiment.

The next decision can be stop, revise or obtain approved actual-model/customer
evidence. A useful internal report is not an authorized commercial offering.
Existing numerical, scheduling, placement and economy examples remain regressions;
they do not limit the kinds of useful needs an operator can investigate.
