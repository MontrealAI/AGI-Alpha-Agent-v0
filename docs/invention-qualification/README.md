# Invention component qualification

This lane distinguishes constructing an allowlisted AST, checking it statically,
and executing that exact AST inside the existing Docker sandbox. None of those
stages establishes physical suitability, source authenticity, commercial demand,
profitability, or improvement in invention capability.

## Acceptance boundary

- Freeze and hash the request, source evidence, program, cohort, and implementation.
- Preserve failed, blocked, and inconclusive receipts; never overwrite them with a
  later success. A missing Docker engine is `BLOCKED`, not a pass or host fallback.
- Retain the existing non-root, network-disabled, read-only Docker execution
  boundary. Resolve the image to a digest and test the isolation boundary first.
- Compare execution outputs to an independent dimensional oracle. The exposed
  component cohort must contain both consistent and inconsistent records.
- Actually execute an unconditional-accept negative control and reject its output;
  a crashing or blocked control does not count as a successful discrimination test.
- Unit tests using receipt doubles test the verifier, not generated-program
  execution. Only the real execution job can produce `DYNAMIC_COMPONENT_PASS`.

The dimensional oracle is deliberately narrow: it checks units for specified
fields, not engineering design validity or whether a cited source supports the
field/value association. Source-binding tests are a separate required obligation.

## Subsequent research acceptance (not implemented by this gate)

Criticism, cross-domain transfer, and evolutionary search are replaceable
strategies, not permanent dependencies. Removing a strategy is acceptable when
the required functional outcome is preserved. Track capability dependencies,
costs, failure evidence, and counterexamples rather than rewarding use of a named
method.

Separate three claims: better task performance, better invention, and better
improvement procedures. Test each using fresh cross-generation controls,
matched total compute and source access, held-out outcomes, and cumulative versus
frozen/reset experience. Preserve unsuccessful generations and test whether any
gain survives removal of the claimed causal component. A supplied compiler or
constraint family is engineering input, not evidence of autonomous discovery.

## Current integration and use

The source-checkout CLI exposes only `invention critic-loop` and `critic-resume`.
It deliberately does not expose unfinished financial, meter, or legacy
whole-excerpt qualification commands. The prior broad package initializers and
operator are reduced to this explicit dependency closure. The original archives
remain unchanged; `evidence/invention-qualification-20261029/provenance.json`
identifies their bytes and retained historical receipts.

The root packaging configuration remains unchanged to preserve the existing
versioned strategy compatibility identity. **Installed-wheel use of the new
commands is not qualified:** the separate contrib verifier is not included in the
current root wheel. Missing verifier code fails closed. Use the checked-out source
for this draft; a reviewed packaging/compatibility revision is separate work.

The fixed public request redacts only original task-prompt/workspace metadata;
its AST, cohort, source excerpt and task requirements are unchanged. This changes
the request identity, so the integration has its own freeze. Old freeze files are
historical evidence, not a claim that modified integration source has old hashes.

The new PR workflow tests receipt doubles and executes the retained AST using
real Docker on the existing runner. It first verifies the existing isolation
boundary and freezes the pulled image digest. The execution step performs source
admission, static program proof, exact program/cohort binding, independent final
acceptance and a truly executed unconditional-accept negative control. It does
not invoke the generator or reset the inherited campaign cutoff. Artifacts are
uploaded on success or failure. A passing exposed component test would still not
establish superiority to the conventional dimensional validator.

Local integration checks include 148 source/verifier tests, two native command
registration tests, ten receipt-double tests, actual source-restricted verifier
admission, and a native CLI static loop plus exact resume. The loop confirms only
the source-associated dimensional guard defect; generated execution and acceptance
remain `BLOCKED` locally because Docker is absent. The failed order-dependent test
fixture and an initially invalid verifier CLI invocation are retained in history.

### Retained identity review correction

The qualification gate additionally requires the supplied AST's canonical hash
to equal the proposal in the frozen request. A different statically valid AST is
refused before any Docker lookup or execution. This intentionally narrows the gate
to the retained proposal; it is not an arbitrary-program qualification interface.
The original hosted run executed the intended fixed proposal and its exact receipts
are retained in `hosted-source-v1/`; those receipts are not relabeled as evidence
for a later gate revision. The revision's hosted checks must pass separately.
