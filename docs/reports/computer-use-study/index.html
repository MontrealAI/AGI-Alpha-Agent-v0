The assistant wrote code, used the browser, inspected screenshots and repaired observed mistakes. The first website reached 31/31 checks. The second introduced a different catalogue, capacities and discount policy.

02 / RECOVER

Recover the work. Review it again.

A worker was interrupted after checkpointing. Restores recovered the expected files, and drafts required a fresh calculation and review. Tampered, stale and wrong-task imports were refused in the tested cases.

Unsaved work can be lost. A hash proves neither identity nor truth. Rollback detection requires a separately retained current head. No power-failure or real transaction was tested.

03 / REUSE

A retained fix prevented the same failure.

Recovery export initially failed when Web Crypto was unavailable. A portable fix was retained. On the next project, removing only that fix reproduced the failure.

WHAT THE EVIDENCE SUPPORTS

Promising, with precise boundaries.

What was executed

Application code, browser interaction, calculations, downloads, fix-removal tests, recovery and file comparisons.

What remains unproven

Savings with real people, customer acceptance, independent review, superiority over leading agents and production reliability.

Read the method and environment limits

Both sites and their initial defects were constructed for the study. The same assistant knew both briefs and designed repairs and tests. The study was neither blinded nor independently preregistered. No independent reviewer model or separately metered provider call was used.

Tests used Chromium, in-memory HTML and blocked HTTP/HTTPS. Direct opening from disk was not qualified in that study. The environment's required --no-sandbox setting is not a production recommendation.

The repository itself was not executed. The scope review referenced commit 8c027575… and the then-observed v1.29.0 release. Publishing the report does not validate later versions.
