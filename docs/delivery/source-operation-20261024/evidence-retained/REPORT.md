## Envelope and actual campaign

Each normal case has a 60-second absolute horizon, concurrency one, maximum three computation attempts per child,
separate search/checking campaign ceilings of 1,000,000 each, bounded source inputs, pure local execution and Journal
writes only. No provider, network fetch, wallet, contract, deployment, paid infrastructure or financial effect is allowed.
The deadline case deliberately has one second. At most ten whole campaign units were scheduled. Normal empty periods
wait; STOP, authority expiry, invalid source/input bindings, exhausted attempts or deterministic failures stop or HOLD.

The controller approved the fixed envelope once, launched the first process, injected SIGKILL after the first
confirmation child committed but before parent attachment, then launched one unchanged CLI restart. Subsequent timed
arrivals and phases completed without manually selecting every task or candidate. A separate active STOP case canceled
the same handoff boundary. Setup, design, source repairs, review, failure-controller construction, recovery launch and
selection of this mission family required operator engineering. Human minutes are unmeasured. This is not autonomous
end-to-end development.

## Improvement result and costs

The main campaign performed **six fresh imported-program trials, four selections and two incumbent retentions**.
The two policies each selected the inherited program on the first two changed tasks; simpler source order won the
third. Conventional reuse and successor reuse have identical per-task quality, counted work and confirmation utility.
Direct construction also matched them. Confirmation quality was 833333, 687500 and 937500 millionths; utility means
were 819416 for all three policies. Frozen paired gain is zero. These are structural scores, not reader benefits.

Each policy's training construction cost was 42 search/78 checking units. Its three later missions cost 84 search/138
checking units in total. All three policies, ancestors and controls are included in 378/648 main totals. Measured
surviving-session process CPU was 4.578 seconds and measured session wall was 8.665 seconds; process-launch-inclusive
elapsed time was 14.575 seconds. The killed session's lost CPU remains unknown. Engineering, maintenance, review and
human minutes remain unknown. Logical units, CPU, wall time and human effort are separate; none is converted to money.
USDC and AGIALPHA base units are separately zero. Full-cost improvement cannot be inferred.

The separate standard-library [audit](audit_outputs.py), with no candidate-runtime import, reconstructed **415 attached
outputs across 83 children plus five outputs from the completed pending STOP child**. Exact text/references, identity,
clause bounds, recursive support, weights, source commitments and exhaustive conventional optima all match. This is
a same-operator audit, not organizational independence. Repeated engineering campaigns are not independent scientific samples.
For clarity, the original cold report's 400 outputs counted attached children only, excluding its pending STOP child.

## Reproduce

Use Python 3.11–3.13 and a source/install containing this feature. For the failure harness, use POSIX and a new output
directory. It kills only its own child. Plans are immutable; do not regenerate them to relabel an observed outcome.

```sh
PYTHONPATH=. python examples/transformational-intelligence/source-operation/verify_campaign.py run --plan docs/delivery/source-operation-20261024/plan-retained-final --output NEW_RESULTS
python docs/delivery/source-operation-20261024/evidence-retained/audit_outputs.py docs/delivery/source-operation-20261024/evidence-retained
```

The first command is source execution, not public installed-release verification. Ordinary installed first-run,
status, STOP, export, backup and recovery commands are in the runbook. All evidence bytes are bound by `manifest.json`.
